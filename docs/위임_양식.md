# 위임 양식 (팀장이 위임문 쓸 때 쓰는 틀, D-125·T7)

## 넘길 것
- 작업 번호, 목표, 완료 조건, 관련 ID
- 마지막 반영 D 이후 변경 D의 한 줄 요약 (있으면 에이전트는 INDEX·DECISIONS를 열지 않음, D-116)
- 읽을 설계 문서의 장(줄 범위 80~120줄 단위)과 코드의 함수명. 대화 전체는 넘기지 않는다
- 동시 작업이 있으면 건드리지 말 파일
- 파일 분할·이동 같은 기계적 작업은 셸이 있는 역할(developer·devops)에 맡긴다(M4-2 documenter 144k 교훈)

## 시험이 있는 위임에 넣을 문장
- 시작 전 포트 확인·자기 포트·한 번에 하나·끝나면 서버 종료 확인
- 바꾼 부분의 개별 시험만. npm test 전체는 팀장이 마무리 때 1회 백그라운드. 출력은 `| tail -n 16`
- 시간 초과가 나면 같은 명령을 다시 돌리지 말고 범위를 줄인다 (P-37)
- 같은 시험·측정이 3번 실패하면 멈추고 보고
- 이미지 촬영 전 고양이 자세·카메라 구도 고정, 비교는 같은 실행·같은 장면에서 수치로. 이미지는 최종 1~2장

## 공통 문장
- 공통 토큰 수칙은 docs/design/토큰_최적화_설계.md 5장 (통독 8KB)
- 도구 30회째에 멈추고 한 일·남은 일 5줄로 중간 보고(디버깅 포함, W1). 팀장은 LOG에 [이슈]로 남기고 방향을 정해 재지시
- 글 입력 경로는 서버 gn_text_check를 거친다 (D-122)

## 보고 형식
- **15줄 이내**(D-127): 바꾼 파일, 핵심 3줄, 팀장 확인 필요, 기록 항목(`날짜 | 역할 | [유형] 내용 (ID)` 120자 이내). 측정 수치·세부는 필요할 때만 파일로
- 도구 20회 이상이면 토큰 내역 3줄(큰 읽기·재읽기 횟수·읽은 총 KB)

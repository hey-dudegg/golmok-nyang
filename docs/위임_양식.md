# 위임 양식 (팀장이 위임문 쓸 때 쓰는 틀, D-125·T7)

## 넘길 것
- 작업 번호, 목표, 완료 조건, 관련 ID
- 마지막 반영 D 이후 변경 D의 한 줄 요약 (있으면 에이전트는 INDEX·DECISIONS를 열지 않음, D-116)
- 읽을 설계 문서의 장(줄 범위 80~120줄 단위)과 코드의 함수명. 대화 전체는 넘기지 않는다
- 동시 작업이 있으면 건드리지 말 파일
- 한 위임은 한 산출물까지. 후속은 확정 사실·함수명·줄 범위를 적은 새 위임으로 (Y1)
- 큰 구현은 팀장이 2~3조각으로 나눠 조각마다 새 위임, 한 위임 40회 안 (Z2)
- 위임문에 "N회 안에"를 숫자로(15·25·최대 40). 40회에 안 들어갈 조각은 위임 전에 둘로 (AA1)
- 형식 참고 파일은 "앞 40줄만"처럼 범위를 지정 (AB3)
- 큰 문서(20KB 이상) 분할·이동은 셸이 있는 역할이 split·sed -n·mv로 하고, 셸 없는 역할에는 통째 재작성을 시키지 않는다 (X1)

## 시험이 있는 위임에 넣을 문장
- 시작 전 포트 확인·자기 포트·한 번에 하나·끝나면 서버 종료 확인
- 개별 시험 BASE_URL은 `http://localhost:<포트>/prototype/`(끝 /prototype/ 필수)
- 바꾼 부분의 개별 시험만. npm test 전체는 팀장이 마무리 때 1회 백그라운드. 출력은 `| tail -n 16`
- 시간 초과가 나면 같은 명령을 다시 돌리지 말고 범위를 줄인다 (P-37)
- 같은 시험·측정이 3번 실패하면 멈추고 보고
- 구현 보고 전 단위 시험 1회, FAIL이면 원인 한 줄을 보고에 (AB2)
- 촬영 전 `node tests/lib/static_server.js`로 서버, 첫 장이 흰 화면이면 고칠 때까지 추가 촬영 금지, 최대 3장 (X3)
- 브라우저 측정은 순수 계산을 먼저 검토, npm test와 동시 금지, 카메라는 코드로 고정, 결과는 한 줄씩 즉시 기록, 2회 실패 시 멈춤 (Z1)
- 시작한 서버·headless chrome은 PID로 직접 끄고, 보고에 포트 확인 한 줄 (Z3)
- 촬영 전 좌표·대상·구도를 한 줄로 적고, 같은 시점 재촬영은 2회까지. 변경 확인은 diff --stat과 함수 줄 범위만 (Y3)
- 측정 스크립트는 여러 조건을 인자로 받아 결과를 파일 1개에 모아 한 번에 돌린다 (AC2)
- 이미지 촬영 전 고양이 자세·카메라 구도 고정, 비교는 같은 실행·같은 장면에서 수치로. 이미지는 최종 1~2장

## 공통 문장
- 공통 토큰 수칙은 docs/design/토큰_최적화_설계.md 5장 (통독 8KB)
- 도구 30회째에 현재까지 한 일·남은 일 5줄로 멈춘다(디버깅 포함, W1·X5). 팀장은 LOG에 [이슈]로 남기고 재지시. 30회 보고 없이 끝난 결과는 받지 않고 재지시 (Y2). 보고에 호출 수를 n/30으로 적는다 (Z2). 호출마다 세어 n/N으로, 실측과 3회 이상 어긋난 역할은 중간 보고 지점 추가 (AA2). 40회 넘은 건은 TOKEN_USAGE에 "보고 누락". 호출 수는 도구 결과 개수로 세고, 실측과 2회 이상 어긋난 역할은 15회째 남은 계획 3줄 자기 점검, 30회 안 넘칠 듯하면 멈추고 최종 보고 (AB1·AC1)
- scratchpad 파일명에 역할명을 접두어로 붙이고, 남의 접두어 파일은 덮어쓰지 않는다 (X4)
- 파일 편집 전 줄 끝(CRLF/LF) 확인, 꼬이면 git diff --stat → checkout(남의 미커밋 변경 없을 때만) → 한 번에 재적용 (X2)
- 글 입력 경로는 서버 gn_text_check를 거친다 (D-122)

## 행동 설계 요지 (상세는 위 문서)
- 구조: 입력(장면 자극·이웃 교감·시간대·성격 6축) → 상태(욕구 4: 에너지·배고픔·지루함·안심 / 감정 8: 편안·호기심·신남·애정·경계·두려움·짜증·졸림, 0~1 값, 성격 평소값으로 감쇠) → 행동 선택 → 실행 4겹(행동 자세 → 이동·점프 → 표정 레이어 → 시선·숨쉬기)
- 시계 두 개: 주요 행동 60~120초, 작은 동작 5~20초, 교감·자극은 즉시 끊고 반응
- 점수 = w·P·N·E·T·R·A, 상위 5개 중 점수 비례 추첨(온도 조절), 반복 방지(최근 5개 ×0.3, 같은 분류 연속 ×0.6, 오늘 처음 ×1.3)
- 10개 분류 51가지 행동. 장면 지점(높은 곳·상자·햇볕 자리·숨을 곳·비비기 자리), 점프는 고양이 키 4배까지, 높은 담은 두 번에
- 뼈대 확장: 등 4마디 + 굽힘 값, 귀 2축 양쪽 따로, 눈꺼풀 모양, 턱 뼈, 꼬리 마디별 부풀림·말기, 발 2마디 IK, 수염 회전
- 행동 DSL(behavior('box_peek', {...}))로 데이터 정의, ?debug 조정 화면
- 새 교감 '물건 놓아 주기'(종이상자·낚싯대 장난감), 놓은 상자는 동네에 하루 유지

## 서버리스 배포안
- Cloudflare Pages(정적, 대역폭·요청 무제한, 월 500회 빌드, 파일당 25MiB) + Supabase 무료(카카오·Google 로그인, DB 500MB, 파일 1GB, 전송 5GB, 월 5만 명, 실시간, RLS, Edge Functions 50만 회)
- Supabase 7일 무요청 시 정지 → GitHub Actions로 하루 한 번 요청
- Firebase 제외(카카오 기본 미지원, 2026-02-03부터 Spark에서 Cloud Storage 불가)
- 바뀌는 코드: 저장소 어댑터 한 파일(약 200줄)이 아티팩트 Caps(db·user·downloads·sample) 대체. 화면·행동 엔진·동네 선택·캡쳐는 그대로
- 반응 수집: 이벤트 기록(30초 묶음), 앱 안 의견 보내기, Cloudflare Web Analytics. 개인정보 안내 페이지 필요, 이벤트에 이름·연락처 넣지 않음
- 계정 4개(GitHub, Cloudflare, Supabase, 카카오 디벨로퍼스)는 사용자 명의. 공개용 anon 키만 쓰고 관리자 키는 어디에도 넣지 않음

## 확정한 방향 (유지)
- 지역: 처음엔 시/군/구 256곳마다 마스코트 1마리, 사용자가 늘면 행정동 3,558곳. 프로토타입은 1~2마리
- 생애주기: 처음 1회 생성, 생애 단계가 바뀌면 배치로 재생성 (동네 코드 + 날짜로 브라우저가 계산)
- 교감: AI 호출 없음. 성격 × 교감 종류별 확률 반응표
- 이름: 이웃 제안(1인 3개), 좋아요 상위 10 랭킹, 1위가 고양이 이름

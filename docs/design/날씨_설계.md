## 0. 요약·전제

- 날씨는 **우리 Pages Function(`/api/weather`)이 Open-Meteo에서 받아 30분 동안 모아 두고**, 브라우저는 같은 주소에서 받는다(B안 확정, D-95).
- 비상업 서비스로 확정되어 Open-Meteo 무료 API를 그대로 쓴다(D-96).
- 날씨 종류는 6가지(`clear·cloudy·fog·rain·snow·storm`)이고, 낮·밤은 해 계산(기존)으로 나눈다.
- 한 번 받은 값(종류·온도·강수량) 하나를 **패널·장면·행동이 같이 쓴다.** 그래서 "비 그림인데 장면은 맑음" 같은 어긋남이 없다.
- 어떤 지역 값이 비면 **인근 지역 날씨를 빌려 쓴다**(9장, D-97). 빌릴 곳도 없으면 장면·행동은 `clear`, 패널은 날씨 칸을 숨긴다.
- 지금 코드에는 가짜 날씨 `core/landmarks.js weatherFor()`(지역+날짜 난수, clear/haze/mist)가 있다. 실제 값을 받으면 이것을 대신한다(4-5).
- 지역 좌표: `regions.json`은 `{시도: {시군구: [동{c,n,x,y,a,p}]}}` 구조이고 `x=경도×1e4`, `y=위도×1e4`다.
  `core/regions.js`가 이미 단위별 중심(속한 동 평균 `lat·lng`)을 만든다. 날씨 지점은 이 중심을 그대로 쓴다(해 계산과 같음, 수정설계 6장).

## 1. 자료 받기

### 1-1. Open-Meteo 호출 (Function 안에서만)
```
GET https://api.open-meteo.com/v1/forecast
  ?latitude=37.57,35.18,...(16개, 쉼표)&longitude=126.98,129.07,...
  &models=kma_seamless                         [미확인: 모델 이름]
  &current=temperature_2m,weather_code,precipitation,snowfall,cloud_cover,is_day
  &hourly=weather_code,precipitation,snowfall,cloud_cover,temperature_2m
  &past_hours=1&forecast_hours=3&timezone=Asia%2FSeoul
```
- 좌표는 소수 둘째 자리로 자른다(약 1km, 캐시 키가 흔들리지 않게).
- 여러 지점을 한 번에 보내면 응답이 지점 순서의 배열로 온다 [미확인: 배열 형태·지점 수 상한].
- KMA 모델에 `weather_code`가 비어(null) 오면 1-2의 "직접 판정"으로 정한다 [미확인: KMA 모델이 주는 변수 목록].

### 1-2. 종류 매핑 (`core/weather_rules.js`, 순수 함수)
| 종류 | WMO weather_code | 직접 판정(코드가 없을 때) |
|---|---|---|
| clear | 0, 1 | cloud_cover < 40 |
| cloudy | 2, 3 | cloud_cover ≥ 40 |
| fog | 45, 48 | (판정 안 함, 코드가 있을 때만) |
| rain | 51~57, 61~67, 80~82 | precipitation ≥ 0.1 mm/h, snowfall = 0 |
| snow | 71~77, 85, 86 | snowfall > 0 |
| storm | 95, 96, 99 | (코드가 있을 때만) |
- 세기 `amt`(0~1): `rain·storm`은 `precipitation/8` 상한 1, `snow`는 `snowfall/3` 상한 1, 나머지는 0. 입자 수·행동 세기에 쓴다.
- 알 수 없는 코드 → `cloudy`(가장 무난). 매핑 표는 시험 표(tests/wx_cases.json)로 고정한다.

### 1-3. 우리 Function 응답 형식 (작고 고정된 모양)
```js
// GET /api/weather?level=sido
{ v: 1, at: 1762560000000,          // 이 묶음을 Open-Meteo에서 받은 시각(ms). 30분 칸의 시작으로 맞춤
  src: 'kma',                        // 실제 쓰인 모델 표시(출처 표기용)
  pts: { '11': { t: 12.3, kind: 'rain', amt: 0.2, hours: [[1762556400000, 'cloudy', 0], ...] }, ... } }
```
- 키는 시/도 코드 2자리(D-05 고양이 생성 단위와 같음). `hours`는 정시 시각·종류·세기(지난 1시간~3시간 뒤).
- 16곳을 늘 한꺼번에 준다(약 3KB). 서버는 사용자가 어느 지역을 보는지 모른다(6장).
- 한 지점만 값이 없으면(종류를 정할 수 없음) 그 키는 `null`로 준다. 빌려 쓰기는 브라우저가 한다(9장). Function은 채워 넣지 않는다.

### 1-4. 캐시 (3단)
1. **Function 가장자리 캐시**: Cache API, 키 = 요청 주소 + 30분 칸 번호. 30분 칸(:00, :30)이 바뀔 때만 Open-Meteo를 부른다.
   칸에 맞추는 이유: 같은 칸이면 모든 사용자가 **같은 묶음**을 받아 행동 계산이 같아진다(4-3).
2. **브라우저 localStorage** `wx:sido` = 응답 그대로 + 받은 시각. 30분 안이면 다시 부르지 않는다.
3. **오래된 값 허용**: 새로 받기가 실패하면 3시간까지는 저장된 값을 쓴다. 넘으면 기본(1-7).
- 다시 받기: 화면이 보이는 동안 다음 30분 칸 시작 + 0~60초 흔들림(한꺼번에 몰리지 않게). 탭이 숨으면 멈추고, 돌아오면 확인.

### 1-5. 호출량과 무료 한도
| 구간 | 추정 | 한도 [미확인] |
|---|---|---|
| Function → Open-Meteo | 하루 48회 × 16지점 = 최대 768 "호출" | 비상업 하루 10,000 / 시간 5,000 / 분 600 |
| 브라우저 → Function | 사용자 1명이 30분마다 1회. 하루 1,000명 × 평균 3회 ≈ 3,000 | Workers·Pages Functions 무료 하루 100,000 |
- Open-Meteo는 지점 수·변수 수가 많으면 "여러 호출"로 센다고 알려져 있다. 16지점을 16호출로 쳐도 한도의 8%다 [미확인: 계산법].
- 사용자 수와 상관없이 Open-Meteo 호출량이 고정된다는 점이 B안의 핵심이다.

### 1-6. 경로 비교와 권장안
| | A. 브라우저 직접 | **B. Pages Function 중계(권장)** | C. GitHub Actions → Supabase |
|---|---|---|---|
| 구조 | 각 브라우저가 Open-Meteo 호출 | `functions/api/weather.js`가 받아 30분 캐시 | 30분 cron이 받아 표에 쓰고, 브라우저가 Supabase에서 읽음 |
| CSP | `api.open-meteo.com` 추가 | 변경 없음(`'self'`) | 변경 없음(Supabase 이미 허용) |
| 사용자 IP | 제3자(Open-Meteo)에 전달됨 | 우리 Function까지만 | Supabase까지만 |
| 같은 값 보장 | 받은 시각마다 다름 | 30분 칸마다 모두 같음 | 같음 |
| 호출량 | 사용자 수에 비례 | 고정 | 고정 |
| 주기 정확도 | 좋음 | 좋음 | cron이 자주 10~30분 늦음, 60일 활동 없으면 꺼짐 [미확인] |
| 쓰기 권한 | 없음 | 없음(키 없음) | 표 쓰기용 비밀 필요 → D-11(관리자 키 금지)과 부딪힘 |
| 선례 | — | D-62 의견 중계와 같은 방식 | D-09 깨우기와 같은 방식 |
- **채택: B (D-95).** 키가 없어 비밀 관리가 필요 없고, CSP·개인정보·호출량이 모두 가장 단순하다. C는 쓰기 권한 문제로 권하지 않는다.
- 정적 JSON을 cron으로 커밋해 배포하는 방법은 Pages 빌드 한도(월 500회 [미확인])를 넘으므로 뺀다.

### 1-7. 실패 시 동작
| 상황 | 장면·행동 | 패널 |
|---|---|---|
| 정상/3시간 안 저장값 | 그 값 | 그림·온도(저장값이면 `title`에 "n분 전") |
| 묶음은 있으나 이 지역만 `null` | 인근 지역 값(9장) | 빌린 값 표시(9-5) |
| 인근에서도 못 찾음 | `clear`, amt 0 | 날씨 칸 숨김 |
| 묶음이 3시간보다 오래됨·처음부터 실패 | 모든 지역 `clear`, amt 0 | 날씨 칸 숨김 |
| 로컬(`python3 -m http.server`, Function 없음) | 설정 `weather: 'mock'`이면 고정 가짜 값 | 가짜 값 표시 |
- Function 쪽: Open-Meteo 실패 시 직전 캐시가 있으면 그것을 `stale: true`로 주고, 없으면 `503 { v:1, err:'upstream' }`.
- 시험·디버그: `?wx=rain` 등으로 종류를 강제(localhost·127.0.0.1에서만, `core/test_host.js` 규칙).

## 2. 패널 표시

### 2-1. 그림 방식: 자체 SVG
- 이모지는 기기마다 모양이 다르고(파란 주소판 위에서 색이 튐), 컬러 이모지 글꼴 자체 호스팅(D-47·53 방식)은 수 MB라 맞지 않다.
- **선 그림 SVG 8개**(해·달·구름·해+구름·달+구름·안개·비·눈·번개 중 조합)를 `ui/wx_icons.js`에 문자열로 둔다(합계 3KB 안팎).
  기존 `svg.i` 규칙(stroke=currentColor, 1.7)을 따라 주소판 글자색(`--plate-ink`)으로 그린다. 외부 파일·글꼴 추가 없음.
- 맑음·구름 조금은 해 고도로 낮/밤 그림을 고른다(`is_day`보다 기존 해 계산을 우선, 장면과 맞추기 위해).

### 2-2. 배치
- 주소판 `.plate`는 2열 그리드이고 2열에 `지역 바꾸기` 버튼이 3줄을 차지한다.
  → 2열 1줄에 `.wx`(그림 18px + 온도), 버튼은 2~3줄로 옮긴다. 1열(시도·동 이름)은 그대로 둔다.
```
┌──────────────────────────────┐
│ 서울특별시 종로구     ☁ 12°  │
│ 삼청동             [지역 바꾸기]│
│ 1111054000                   │
└──────────────────────────────┘
```
- 온도: 정수 반올림, `°`만(단위 글자 없음), 영하는 `−3°`(빼기 기호). `--f-mono`, `tabular-nums`, 13px.
- 접근성: `role="img"` `aria-label="흐림, 영상 12도"`. `title`에 "기상청 모델 · Open-Meteo · 14:30 기준".
- 모바일(≤720px): 그림 16px·온도 12px. 주소판 최대 너비(360px)는 바꾸지 않는다. 동 이름이 길어 넘치면 `.wx`가 아니라 이름이 줄바꿈된다.
- 출처 표기: 패널에는 넣지 않고 기존 정보·도움말 자리에 "날씨 자료: Open-Meteo.com (기상청 모델)" 링크를 둔다 [미확인: 표기 문구 요구].

## 3. 장면 연출·폰 성능 예산·천둥 번쩍임

### 3-1. 연출
| 종류 | 하늘·조명 | 입자 | 원경(명소 배경) |
|---|---|---|---|
| clear | 지금 그대로 | 없음 | haze ×1 |
| cloudy | 하늘색을 회색 쪽으로 35% 섞음, 해 빛 ×0.6, 그림자 연하게 | 없음 | haze ×1.35 |
| fog | 회색 50%, 해 빛 ×0.5, `scene.fog` 가까이 | 없음 | haze ×1.75 |
| rain | cloudy + 해 빛 ×0.5, 바닥 거칠기 낮춤(젖은 느낌, 선택) | 빗줄기 | haze ×1.5 |
| snow | 회색 25%·약간 밝게 | 눈송이 | haze ×1.4 |
| storm | rain + 드물고 약한 번쩍임(3-3) | 빗줄기 많이 | haze ×1.6 |
- 바뀔 때는 3초에 걸쳐 섞는다(갑자기 바뀌지 않게). 밤에는 하늘 섞기 양을 절반으로(이미 어두움).
- `prefers-reduced-motion`: 입자 30%·느리게, 번쩍임 끔(3-3).
- 새 파일 `render/weather_fx.js`: `createWeatherFx(scene) → { set(wx), tick(t), dispose() }`. Scene3D는 `setTime`처럼 `setWeather(wx)`만 부른다.

### 3-2. 성능 예산 (털 렌더가 이미 무겁다, D-70·71)
- 입자는 **그리기 1번**: 빗줄기는 가는 사각형 인스턴스(또는 LineSegments), 눈은 Points. 위치는 정점 셰이더에서 `uTime`으로 떨어뜨리고 감싸 돌린다(매 프레임 CPU 갱신 없음).
- 범위는 카메라 앞 상자(가로 7m·깊이 5m·높이 4m)만. 투명 정렬 끄고 깊이 쓰기 끔.
- 개수 상한: 비 데스크톱 1,200 / 터치(`pointer: coarse`) 500, 눈 600 / 250. 실제 개수 = 상한 × max(0.3, amt).
- 예산: **같은 장면·같은 구도에서 rain(amt 1) 켰을 때 프레임 시간 증가 ≤ 1ms(데스크톱), 터치 기기 FPS 하락 ≤ 5%.**
  못 맞추면 터치 상한을 반으로 줄인다(털 밀도는 건드리지 않음).
- 고양이 털이 젖는 표현·발자국·쌓인 눈은 이번 범위가 아니다(털 셰이더 변경은 P-36 실기 확인이 필요).

### 3-3. 천둥 번쩍임: 약하게·드물게 (D-98)
- 기준: WCAG 2.3.1(1초에 3번 넘게 번쩍이지 않음)과 "일반 번쩍임" 정의(화면 상대 휘도 10% 이상 변화)를 참고해 **그 기준에 닿지 않게** 잡는다.

| 항목 | 값 |
|---|---|
| 밝기 상한 | 해·환경광 세기 +12%까지. 목표: 화면 평균 상대 휘도 변화 < 10% |
| 모양 | 한 번에 한 번만(겹번쩍 없음). 올라감 0.1초, 내려감 0.5초(깜빡이 아닌 은은한 밝아짐) |
| 간격 | 최소 45초, 보통 60~120초. 30분 칸당 최대 20회. amt < 0.3이면 간격 2배 |
| 정하기 | `(지역코드, 칸 번호)` 난수로 시각을 정한다(결정적, 같은 칸이면 모두 같은 때 번쩍) |
| 끔 | `prefers-reduced-motion`, 탭 숨김, 어드민 `?wx=storm&flash=0` |
- 소리(천둥)는 넣지 않는다. 고양이 행동은 번쩍임과 무관하게 storm 배수(4-1)만 받는다.
- 측정(M3-e): 같은 장면·같은 구도에서 번쩍임 직전·최고점 캔버스 평균 휘도를 수치로 비교해 10% 미만이면 통과.

## 4. 고양이 행동과 세계 시계

### 4-1. 입력 위치
- 행동 점수는 `clock.ctx()`가 만든 `world`(지금은 `night·day`)를 읽는다(D-07). 여기에 `world.wx = { kind, amt }`를 더한다.
- 각 행동(ACTIONS)의 score 함수는 고치지 않는다. 대신 `clock.weights()`에서 감정 보정(EMO_BIAS)과 같은 자리에 **날씨 배수표 `WX_BIAS`** 를 곱한다.
```js
// core/weather_rules.js (예시, 값은 시작점. ?debug 화면에서 조정)
export const WX_BIAS = {
  rain:  { zoom: 0.3, hunt: 0.4, wander: 0.5, belly: 0.3, nap: 1.3, loaf: 1.4, groom: 1.2, watch: 1.2 },
  storm: { zoom: 0.2, hunt: 0.3, wander: 0.3, belly: 0.2, nap: 1.2, loaf: 1.5, watch: 1.3 },
  snow:  { wander: 0.8, belly: 0.5, loaf: 1.2 },   // 아기 고양이는 zoom ×1.2 (눈 장난)
  fog:   { watch: 1.2 }, cloudy: {}, clear: {},
};
// 배수 = 1 + (표 값 - 1) × amt' (amt' = max(0.5, amt)) → 이슬비는 약하게, 장대비는 세게
```
- 감정 보정(작게): storm → scared +0.15·wary +0.1, rain → calm +0.1·playful −0.1. `clock.state()`에 `wx`를 선택 인자로 받는다.
- **비 피하기(목적지)**: `rain·storm`이고 amt ≥ 0.2이면, 칸에서 정하는 "어디서"를 무대 전체(BOUNDS) 대신 **비 피할 자리 목록**에서 고른다.
  목록은 장면 테마별 자료로 `core/weather_rules.js`의 `SHELTER = { alley: [[x,z],...], market: [...], park: [...] }`에 둔다
  (core는 render를 못 읽으므로 좌표를 자료로 두고, `render/scene_themes.js`가 같은 자리에 처마·차양·상자를 놓는다).
  자리 고르기도 `(고양이 id, 칸 번호)` 난수라 결정적이다. 자리가 고양이 수보다 적으면 같은 자리 둘까지 허용.
- 눈: 숨지는 않고, 털 고르기·식빵이 늘어난다. 아기 고양이는 눈 장난(zoom) 쪽.

### 4-2. 세계 시계(D-19)와의 관계
- D-19는 "상태 = 시각의 결정적 함수"다. 날씨는 실시간 자료라 이 함수의 입력이 하나 늘어난다: **상태 = f(시각, 날씨 묶음)**.
- 결정성을 지키는 방법: 행동 계산에는 `current`가 아니라 **묶음의 정시 값 `hours`** 를 쓴다. 칸 시각 ms의 날씨 = `hours`에서 그 시각이 속한 정시의 값.
  - 같은 30분 칸 묶음(1-4)을 받은 사람끼리는 **완전히 같은 행동**이 나온다.
  - 묶음이 바뀌는 순간(30분마다) 예보가 달라졌으면 사람마다 몇 분 어긋날 수 있다. 수정설계 2장의 "몇 초~몇 분 오차, 같은 고양이가 같은 행동" 범위로 본다.
- 접속 때 최근 10~30분 복원: 지난 칸들도 `hours`의 과거 1시간 값을 쓴다(`past_hours=1`). 없으면 지금 값으로 채운다.
- 빌린 값(9장)도 같은 묶음에서 결정적으로 정해지므로 행동 계산에 그대로 쓴다.
- 날씨가 없거나 `clear`면 `WX_BIAS`·SHELTER를 건너뛴다 → **지금의 시계 결과와 1비트도 달라지지 않는다**(기존 시험 기준값 유지).
- 패널·장면은 `current`(15분 단위로 더 최신)가 아니라 같은 정시 값의 종류를 쓰고, 온도만 `current.t`를 쓴다. 종류를 하나로 맞추기 위해서다.

### 4-3. 놀러 간 고양이·교감
- 다른 지역에 놀러 간 고양이(자리 비움)는 **간 곳의 날씨**를 쓴다(그 화면의 장면과 맞춤). 손님 고양이도 같다.
  간 곳 값이 빌린 값이면 9장 결과를 그대로 읽는다(다시 빌리기를 돌리지 않음).
- 교감 반응(D-03 확률표)은 날씨로 바꾸지 않는다. 비 피하는 중에 쓰다듬으면 그 자리에서 반응하고, 끝나면 일정으로 돌아간다.

### 4-4. 시작 시 순서
- 날씨를 기다리느라 첫 화면을 늦추지 않는다. 저장된 묶음이 있으면 바로 쓰고, 없으면 `clear`로 시작한 뒤 받으면 반영(장면 3초 섞기, 행동은 다음 칸부터).

### 4-5. 명소 배경 가짜 날씨 정리
- `core/landmarks.js weatherFor()`(clear/haze/mist)는 실제 값(빌린 값 포함)이 있으면 쓰지 않는다(D-95). `backdropVariant(code, ms, sunDeg, wx)`처럼 선택 인자를 받아
  `wx`가 있으면 3-1 표의 haze 배수를, 없으면 지금처럼 가짜 값을 쓴다(명소 시험 `test:backdrop` 기준값 유지).

## 5. 확장: 시군구·읍면동

- **날씨 지점 = 격자 칸**으로 일반화한다. 칸 id = `round(위도×20)_round(경도×20)`(0.05°, 약 5km). 시/도 16곳도 중심 좌표의 칸 id로 바꿀 수 있다.
  지역 단위는 자기 중심 좌표 → 칸 id를 계산할 뿐, 날씨 쪽은 지역 단계를 모른다.
- 요청: `GET /api/weather?cells=7515_25395,7516_25390`(한 번에 최대 8칸). Function은 칸마다 30분(시군구) 또는 60분(동) 캐시.
  칸 id는 한국 범위(위도 33~39, 경도 124~132)만 받고 나머지는 400 — 임의 좌표 중계로 쓰이지 않게.
- 호출량 [미확인 한도 기준]: 시군구 256곳 → 칸 약 230개, 모두 쓰일 때 최악 230×48 = 11,040/일로 한도를 넘는다.
  → 시군구 단계부터는 칸 TTL 60분(최악 5,520), 동 단계는 칸 0.1°(약 10km, 칸 수 약 1,000 [추정])·60분·**요청이 있는 칸만** 받는다.
  그래도 넘칠 위험이 있으면 그때 P로 올린다(예: 인기 칸만 30분, 나머지 120분).
- 브라우저 캐시 키도 `wx:cell:<id>`로 바꾸고, 시/도용 `level=sido`는 남겨 두다가 단계 전환 때 지운다.
- `REGION_LEVEL` 설정(수정설계 6장)에 따라 칸 크기만 고르는 표 하나를 둔다. 지금 구현하지 않고 형식만 이 장에 남긴다.
- 빌려 쓰기(9장)는 같은 함수를 쓰고, 이웃 그래프만 "칸 id의 상하좌우·대각 8칸"으로 바꾼다(9-6).

## 6. 보안·개인정보

- **CSP**: B안이면 바꾸지 않는다(`connect-src 'self'`로 `/api/weather` 충분). A안을 고르면 `connect-src`에 `https://api.open-meteo.com`만 추가.
- Function: GET만, 바깥 주소는 코드에 고정(사용자 입력으로 주소를 만들지 않음), 입력은 `level=sido` 또는 검증된 칸 id만.
  키·비밀 없음(Open-Meteo 무료는 키 없음). 사용자 IP·요청을 기록하지 않는다. 응답에 `Cache-Control: public, max-age=300`.
- 위치: 기기 위치는 받지 않는다(`Permissions-Policy: geolocation=()` 그대로). 날씨 지점은 사용자가 고른 지역의 공개 중심 좌표다.
  `level=sido`는 16곳을 통째로 주므로 서버도 사용자가 보는 지역을 알 수 없다.
- 저장소에는 좌표 상수도 넣지 않는다(regions.json에서 계산). 시험 가짜 응답은 지어낸 값이다.
- 이용 약관: Open-Meteo 무료 API는 **비상업 용도**와 **출처 표기(CC BY 4.0)** 조건이다 [미확인: 문구]. 비상업은 사용자가 확정했다(D-96).
  광고·후원·유료 기능을 넣게 되면 날씨 경로를 다시 정해야 하므로, 그런 작업 전에 이 줄을 확인한다.

## 9. 인근 지역 날씨 빌려 쓰기 (D-97)

### 9-1. 원칙
- 고양이가 옆 동네로 놀러 가듯, 값이 빈 지역은 가까운 이웃의 값을 잠시 빌린다.
- (1) 같은 입력이면 누구나 같은 결과(결정적, D-19) (2) **직접 받은 값만 빌려준다** (3) 정해진 단계 안에서 반드시 끝난다
  (4) 순수 함수(core 층, fetch·시계·localStorage를 쓰지 않음, 지금 시각도 인자로 받음).

### 9-2. 입력·출력 (인터페이스 예시)
```js
// core/wx_borrow.js
// own:   Map<id, Wx|null>  이번 묶음에서 직접 받은 값만. Wx = { kind, amt, t, hours, at }
// graph: { ids(): string[], neighbors(id): string[], center(id): { lat, lng } }
// opt:   { maxHops, maxVisit, maxAgeMs, nowMs }
resolveWx(id, own, graph, opt) → { wx, from, hops } | null   // 자기 값이면 from === id, hops 0
resolveAll(own, graph, opt)    → Map<id, { wx, from, hops } | null>
```
- 결과는 새 Map으로 돌려준다. `own`·`graph`는 바꾸지 않는다. 그래프 만들기는 `state/weather.js`가 하고 함수에는 넘기기만 한다(시험은 가짜 그래프).

### 9-3. 이웃 고르기
1. 자기 값이 **쓸 수 있으면** 그대로(hops 0). 쓸 수 있음 = `kind`가 6종 중 하나 + `nowMs − at ≤ maxAgeMs`.
2. 아니면 너비 우선으로 1단계 → 2단계 … `maxHops`까지 넓힌다. 같은 단계 후보는 **중심 거리 가까운 순, 같으면 id 문자열 순.**
3. 처음 만나는 '쓸 수 있는 직접 받은 값'을 빌린다. 가까운 단계가 늘 먼 단계보다 앞선다.
4. 인접 이웃이 하나도 없는 지역(시/도에서는 제주)은 **중심 거리 가장 가까운 1곳**을 1단계 이웃으로 본다(그래프 만들 때 한 번 정하는 가상 연결).
5. 끝까지 못 찾으면 `null` → 장면·행동 `clear`, 패널 숨김.
- 신선도: 빌려주는 값도 자기 값과 같은 `maxAgeMs`(3시간, 1-4)를 통과해야 한다. 시/도는 16곳이 한 묶음이라 같은 시각 값끼리 빌린다.
  칸 단계(9-6)는 칸마다 받은 시각이 달라 이 조건이 실제로 걸린다.
- 값: 시/도 `maxHops 2`(그 너머는 날씨가 너무 다름), `maxVisit 16`. 칸 `maxHops 2`(0.05° 칸이면 약 10km), `maxVisit 25`(5×5).

### 9-4. 무한 반복·순환 방지
| 방지책 | 내용 |
|---|---|
| 직접 받은 값만 빌려줌 | 후보 값은 `own`에서만 읽는다. 빌린 결과는 출력 Map에만 쓰고 `own`에 넣지 않는다 → 빌린 값을 또 빌려주는 사슬이 생기지 않는다 |
| 방문 표시 | 탐색마다 `visited` 집합(자기 자신 포함). 한 번 본 id는 다시 큐에 넣지 않는다 → A↔B↔C↔A 순환도 끝난다 |
| 최대 단계 | `maxHops`를 넘는 이웃은 큐에 넣지 않는다 |
| 최대 방문 수 | 한 지역당 확인하는 이웃은 `maxVisit`까지. 넘으면 `null` |
| 재귀 없음·서로 독립 | 반복문 + 큐. 한 지역의 계산은 다른 지역의 결과를 읽지 않는다(계산 순서와 무관) |
| 그래프 정리 | 그래프 만들 때 자기 연결·중복·없는 id로의 연결은 버린다 |
- 계산량: 시/도 16곳 × 최대 16 방문 ≈ 256번 비교, 묶음을 받을 때 1번. 프레임마다 돌리지 않는다.

### 9-5. 패널에 빌린 값 표시 (제안, Q8)
- 권장: **그림은 보이되 흐리게(불투명도 0.6), 온도는 숨김.** 하늘 상태는 이웃끼리 비슷한 편이지만 온도는 산·바다로 차이가 커 틀린 숫자가 될 수 있다.
- `aria-label`·`title`: "흐림 · 인근 지역 날씨를 빌려 왔어요 · 14:30 기준". 어느 지역인지는 쓰지 않는다(놀러가기 표지판과 같은 방식, 수정설계 7장).
- 대안: 온도도 `≈12°`로 보여 주기(정보는 많지만 틀릴 수 있음). 장면·행동은 어느 쪽이든 빌린 값을 그대로 쓴다.

### 9-6. 시/도 그래프와 시군구·동 확장
- 시/도: `core/trips.js`의 `NEIGHBORS`(경계가 맞닿은 시/도, 수정설계 7장 놀러가기 표)를 그대로 쓴다. 놀러 가는 곳 = 날씨 빌리는 곳이라 "옆 동네" 뜻이 같다.
  제주(50)의 가상 연결(9-3 규칙 4)은 날씨 그래프에만 두고 놀러가기에는 쓰지 않는다. `center`는 `core/regions.js` 중심.
- 칸(5장): 함수는 그대로, 그래프만 바꾼다. `neighbors('7515_25395')` = 위도·경도 칸 번호 ±1의 8칸, `center` = 칸 번호 ÷ 20. 거리 순 규칙이라 상하좌우가 대각보다 앞선다.
- 칸 단계에서 자기 칸이 비면 1단계 8칸을 **한 번만** 더 요청한다(요청 상한 8칸과 같음). 2단계는 이미 받아 둔 칸만 쓴다 → 요청이 번지지 않는다.
- 시군구 경계 인접표는 아직 없다(`Trips.neighbors()`가 시/도 밖에서는 빈 배열). 그래서 확장 때는 행정 경계 대신 칸 그래프를 쓴다.

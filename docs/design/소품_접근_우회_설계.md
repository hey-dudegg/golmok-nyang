## 1. 문제와 범위
- 지금: `approach(a, S)`(core/prop_common.js:122)가 `STEP.walk(S.ax, S.az)` 직선 1개 + `PS.check(S)`.
  직선이 소품 사각형을 지나면 `world.resolve`(main.js:212, rectPush 여유 0.08)가 면에 밀고,
  밀림 1.5초 누적(sim/agent.js:230)이면 걷기 종료 -> PS.check(0.3m)에서 포기.
- 재현(조사 확정): crate@0.6,0.4(접근점 0.6,0.795)에 cat 0,0 -> (0.11,0.54) 정지,
  cat 0.6,-0.2 -> (0.31,0.08) 정지. tower@-0.6,0+cat 0,0, tower@0.6,0+cat 0.6,-0.7 실패.
- 바꾸는 것: 접근 걷기를 "모서리 우회점(최대 4개) -> 접근점" 여러 걸음으로 나눈다.
- 안 바꾸는 것: resolve·밀림 1.5초·PS.check·도약·렌더(a.x/a.z 그대로, agent.js:309).
  격자 길찾기(A*)는 넣지 않는다(소품 1~4개라 모서리 우회로 충분).
- 장애물 이웃 고양이(soft push)는 무시한다. 담(wall)은 우회 대상 아님(뒤쪽 경계).

## 2. 우회점 계산
순수 함수, 입력은 장애물 목록·출발·도착. 소품 좌표계(rot 반영) 안에서 계산한다.

```js
// core/detour.js
export const DETOUR = { m: 0.11, maxPts: 4, maxIter: 6 };
// obstacles: world 장애물 배열({x,z,hx,hz,rot,id} 사각형 | {x,z,r} 원 | {wall}), skip: 무시할 id(a.layer)
// ok(x,z): 우회점 허용 검사(보통 (x,z) => !world.blocked(x,z,0.2)). 반환: [{x,z},...] (0개 = 직선 그대로), null = 못 찾음
export function detour(obstacles, from, to, { skip = null, ok = () => true } = {}) {}
```
2.1 장애물 모양
- 사각형(hx 있음): 그대로. id === skip(차 밑에 든 고양이 layer)는 건너뜀.
- 원(r): 축 정렬 정사각형 hx=hz=r, rot 0 으로 본다(장면 나무·화분 등).
- wall: 건너뜀(소품 접근점은 모두 앞쪽 +z, props.js:19~45).
2.2 여유 m
- 기본 m=0.11: resolve 여유 0.08 + 0.03. 탑 접근점이 면에서 0.12(가장 가까움)라 그보다 작아야 함.
- 한 다리(leg)의 시작·끝점이 확장 사각형 안이면 그 사각형만 m_eff = (그 점의 면 거리 - 0.01),
  0.085 미만이면 그 다리에서 그 장애물은 건너뜀(이미 붙어 있음, resolve에 맡김).
2.3 다리 검사 `hit(leg, o, m)`
- 소품 좌표로 옮긴 선분과 (hx+m-0.01, hz+m-0.01) 사각형의 교차(slab 방식). 0.01 줄인 것은
  모서리를 스치는 다리를 통과로 보기 위함. 교차 시 진입 t 를 돌려준다.
2.4 어느 모서리를 고를지 (장애물 하나)
- 확장 사각형(hx+m, hz+m)의 4 모서리를 월드 좌표로.
- 1점 후보: 모서리 c 에서 from->c, c->to 둘 다 그 장애물과 안 겹치고 ok(c) 참인 것 중 경로 길이 최소.
- 1점이 없으면 2점 후보: 이웃한 모서리 쌍(같은 변) c1->c2 순서 8가지 중
  from->c1, c1->c2, c2->to 모두 안 겹치고 ok 참인 것 중 길이 최소(= 소품 뒤에서 앞으로 돌아가기).
- 둘 다 없으면 null.
2.5 여러 소품·차·담이 겹칠 때
- 반복(최대 maxIter=6): 경로의 다리마다 모든 장애물을 검사해 진입 t 가 가장 작은 장애물 하나를 고르고,
  그 다리를 2.4 결과로 바꿔 끼운다. 더 이상 겹침이 없으면 끝.
- 우회점이 다른 장애물 안·경계 밖·담 앞(z < 담z+0.32)이면 ok 에서 걸러진다(world.blocked 가 처리).
- 우회점 합계 > maxPts(4) 이거나 반복 초과, 또는 2.4 가 null 이면 detour 는 null.
- null 이면 호출부는 지금처럼 직선 1개로 간다(퇴행 없음, 실패는 기존 포기 경로).

## 3. 넣을 곳 (층 규칙)
층: core <- adapters <- state <- render·sim <- ui <- app·main. core 는 three·DOM 없음.
| 파일 | 내용 | 줄 수 |
|---|---|---|
| core/detour.js (새) | DETOUR, detour(), 내부 toLocal·hit·corners | 약 60 |
| core/prop_common.js approach() | 아래 의사 흐름, 제한 시간은 다리 길이 합으로 | +5 |
| main.js world 객체(62~70) | `get obstacles() { return app.s.obstacles; }` 한 줄 | +1 |
| tests/unit/detour.test.mjs (새) | 순수 함수 시험(5.1) | 약 40 |
- world.obstacles 는 getter 여야 한다(props_app.js:37·41 이 배열을 filter 로 바꿔 끼움).
- 시험용 가짜 world(core_more·wx_clock 단위 시험)는 obstacles 가 없으므로 `a.world.obstacles || []`.
- approach() 흐름(인터페이스 예시):
```js
const wps = detour(a.world.obstacles || [], a, { x: S.ax, z: S.az }, { skip: a.layer, ok: (x, z) => !a.world.blocked(x, z, 0.2) }) || [];
// 다리마다 STEP.walk(p.x, p.z, speed, { timeout: legTo }) , 마지막에 STEP.walk(S.ax, S.az, ...), PS.check(S)
```
- 접근점 자체 막힘 검사(123줄)·쿨다운은 그대로 먼저 한다.

## 5. 시험 조건
5.1 단위(node, 순수): 위 4 재현을 장애물 배열로 그대로 넣어
- crate@0.6,0.4, from 0,0 -> 우회점 1개(앞-왼쪽 모서리 약 0.215,0.735). from 0.6,-0.2 -> 2개(뒤-한쪽 -> 앞-같은쪽).
- from 0.6,0.9(이미 앞) -> 0개. tower@-0.6,0 from 0,0 -> 1개(약 -0.015,0.39). tower@0.6,0 from 0.6,-0.7 -> 2개.
- 다리마다 m-0.01 사각형과 교차 없음, 모든 점 ok 참. 상자+차 겹침 1건(우회점이 차 안이면 다른 쪽 선택).
5.2 촬영 측정(브라우저, 좌표마다 1회, 통과표만 보고):

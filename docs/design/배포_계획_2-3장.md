## 2. P-07 먼저: anon 키를 "빌드 없는" 정적 파일에 넣는 방법

**안전성:** Supabase의 anon(공개) 키는 **브라우저에 있어야 동작하는 열쇠**입니다. 어떤 방식으로 주입하든 방문자는 개발자 도구에서 볼 수 있습니다. 그래서 키가 비밀이어서가 아니라 **RLS(1-4)가 모든 표에 켜져 있고 정책이 맞아야 안전**합니다. 지켜야 할 것은 **관리자 키(service_role·secret 계열)를 어디에도 넣지 않는 것**(D-11)입니다. Supabase가 최근 "publishable/secret" 키 체계를 내놓았다는 기억이 있으나 [미확인] 대시보드에 보이는 "공개용(anon 또는 publishable)" 키 하나만 쓰면 됩니다.

| 항목 | A. `config.js`에 공개 값을 커밋 | B. 배포 때 환경 변수로 치환 |
|---|---|---|
| 방식 | `src/config.js`에 주소·공개 키를 직접 적고 커밋 | Pages 빌드 명령(예: 파일 문자열 치환 스크립트)이 환경 변수를 `config.js`에 써 넣음 |
| 빌드 없음(D-13) | 유지 | **빌드 명령이 생김**(작지만 D-13 취지에 어긋남, Node/쉘 환경 의존) |
| 저장소 노출 | 키가 공개 저장소에 보임 → 스캐너가 경고를 낼 수 있음(공개 키라 실제 위험은 아님) | 저장소에는 없음, 단 방문자에게는 똑같이 보임 |
| 방문자 노출 | 동일 | 동일 |
| 스테이징/운영 분리 | `config.js` 안에서 **접속 주소(hostname)로 고름**(운영 도메인이면 운영 값, 그 외 `*.pages.dev`면 스테이징 값). 빌드 불필요 | 환경마다 값을 따로 대시보드에 입력(Pages는 운영/미리보기 환경 변수 분리 지원 [미확인: 이번 문서 확인 못 함]) |
| 로컬 시험 | 같은 파일, 주소가 localhost면 모의 | 로컬 전용 값 파일 별도 필요 |
| 사용자 작업 | 값 2개를 `config.js`에 붙여 달라고 개발자에게 전달 | 대시보드에 환경 변수 입력 + 빌드 설정 |
| 키 교체 | 파일 수정 + 재배포(1분) | 대시보드 수정 + 재배포 |

**권장: A.** 이유: 키는 어차피 공개되고, 진짜 방어선은 RLS이며, 빌드 없음(D-13)을 지킵니다. 비밀이 아님을 파일 머리 주석에 명시하고, `/secure-check`에 "service_role·secret 문자열이 없는지" 검사를 추가합니다. 위험이 하나 있어요: 스캐너 경고가 오면 사용자가 놀랄 수 있으니 미리 안내합니다(이 문서가 안내). Web3Forms 접근 키도 같은 방식(공개용)입니다.
스캐너 경고를 정말 피하고 싶을 때만 B를 선택합니다. B로 가면 작업량이 +1회(빌드 스크립트와 테스트).

**결정 요청 번호 P-07 → 3장.**

## 3. 사용자 결정서 (번호로 답해 주세요)

한 번에 답하는 법: 예) "P-01 B, P-02 A, P-03 B, P-04 A, P-05 A, P-07 A, P-15 C" — 권장안을 모두 받아들이면 "권장대로"라고만 답해도 됩니다. (P-07은 architect 소관이지만 사용자 확인용으로 함께 적습니다.)

### P-01 로그인 제공자
질문: 이웃 등록(회원) 로그인을 어디까지 제공할까요? (비회원도 구경·익명 투표는 가능, 회원 전용은 홍보·츄르·게시판 쓰기, D-16)

| 선택 | 영향 | 사용자 작업 | 개발 작업 |
|---|---|---|---|
| A 카카오 + Google | 가입 쉬움, 외국 사용자도 가능 | 카카오 앱 + Google Cloud 설정(Google은 동의 화면 등 단계가 많음) 약 1시간 추가 | 버튼 1개 추가 수준(Supabase가 처리) |
| B 카카오만 | 한국 사용자 대상이면 충분. 설정이 가장 단순 | 카카오 디벨로퍼스 앱 1개 | 기본 |
| C 로그인 없이 익명만 | 회원 전용 기능을 의미 있게 못 막음(D-16과 충돌) | 없음 | 없음 |

**권장: B.** 이유: 대상이 한국 사용자이고, 공유 주요 채널이 카카오톡이라 [추측] 카톡 앱 안의 내장 브라우저에서 Google 로그인이 막힐 수 있습니다(구글이 내장 웹뷰 로그인을 제한하는 정책 [미확인-일반 지식]). 카카오는 닉네임만 받는 최소 동의로 시작하고 이메일은 받지 않습니다. Google은 시험 기간에 불편 보고가 있으면 켭니다(코드는 같음).
비용: 두 안 모두 0원. 위험: B는 카카오 앱 설정이 막히면 대안이 없음 → 그때 Google을 켭니다(대체 경로).

### P-02 첫 공개 범위
질문: 처음엔 누구에게 열까요?

| 선택 | 영향 |
|---|---|
| A 링크 공유만(검색에 안 뜨게) | 소수 시험에 안전. 검색 노출 막기: `noindex` 메타와 `X-Robots-Tag` 헤더(`_headers`). 링크는 비밀번호가 아니라 **누구나 링크를 받으면 접속**함. 한도·악용 위험이 작음 |
| B 전체 공개 | 접속 급증 시 한도(1-5) 위험, 악용·신고 대응 필요, 개인정보 안내 페이지(M5)가 **먼저** 있어야 함 |

**권장: A** (P-05 시험 기간 동안), 한도·악용 점검 후 B로 전환. 전환은 헤더 한 줄(`noindex` 제거)과 재배포. 선택적으로 Cloudflare Access(무료 50명 이내 [미확인])로 로그인 제한도 가능하나 시험 단계엔 과함.

### P-03 놓은 상자를 이웃도 볼지 (R-06 물건 놓기)
질문: 사용자가 놓은 상자를 그 동네 방문자 모두가 보게 할까요?

| 선택 | 영향 |
|---|---|
| A 모두에게 보임(실시간) | 함께 보는 재미 큼. 표 `placed_items` + 실시간 구독, 장난·도배 방지(1인당 개수·기간 제한, 신고), 실시간 메시지 추가 소비. 작업량 큼(R-06은 아직 미구현) |
| B 놓은 사람만 | 서버 부담 거의 없음(본인 기록만), 악용 없음. 함께 보는 재미는 작음 |

**권장: B 먼저**, 시험 후 A로 확장. 표 설계는 A도 가능하게 `region`·`owner`·`expires_at` 칸을 처음부터 넣어 둡니다(지금 결정이 되돌릴 수 없는 것이 아님). 이유: 시험 기간(P-05)의 가장 큰 위험이 실시간 한도와 악용이라 한꺼번에 늘리지 않는 것이 안전합니다. 비용: 둘 다 0원 범위(A는 한도 소비 증가 [추측: 크기 작으면 영향 작음]).

### P-04 주요 행동 간격 초깃값
질문: 주요 행동 시계(D-07)를 60~120초로 시작할까요?
참고: 이 값은 **서버 비용과 무관**합니다(브라우저 계산, D-19). 단 모든 접속자가 같은 값을 써야 같은 장면이 보이므로(결정적 상태) **값을 바꾸면 한꺼번에 재배포**해야 하고, 옛 화면이 열려 있으면 잠시 어긋납니다.

| 선택 | 영향 |
|---|---|
| A 60~120초 | 지금 구현·시험 값. 추가 작업 없음 |
| B 90~180초 | 더 느긋한 고양이. 시험·기준값 다시 잡기 필요(작업 소) |
| C 값은 서버 설정 한 줄(`app_config`)에서 읽기 | 재배포 없이 조정 가능. 단 읽는 시점 차이로 어긋날 수 있어 "버전 번호"를 함께 넣어야 함(작업 중) |

**권장: A로 시작**, 시험 중 의견을 보고 조정이 많이 필요하면 C. 이유: 값은 추측이고 실제 반응을 봐야 하며, 지금은 작업이 가장 적은 안이 맞습니다.

### P-05 테스트 기간과 목표 인원
질문: 비공개 시험을 얼마나, 몇 명까지?

| 선택 | 영향 |
|---|---|
| A 2주, 20~30명 | 1-5의 "소규모"(한도 3%). 가장 안전, 악용·결함 발견엔 충분 |
| B 4주, 50~100명 | "중간"에 근접(한도 70% 가능). 사람 수 알림 대비책 2단계(서버 감시)를 먼저 넣어야 함 |
| C 8주, 100~200명 | 한도 초과 가능. 대비책 3단계(RPC 방식)가 필요할 수 있음 |

**권장: A 2주 → 결과 보고 B 4주.** 한도 알림 기준: 월 메시지 100만 건(50%)에 도달하면 사용자에게 알림. 시험 종료 기준(예시): 심각한 결함 0건, 의견 메일 처리 완료, 월 사용량 70% 이하.

### P-07 anon 키 주입 방식 (2장 요약)
선택지: A 공개 값을 `config.js`에 커밋 / B 배포 때 치환.
**권장: A.** 호스트 이름으로 스테이징·운영 값을 고르는 방식(빌드 없음). 되돌릴 수 없는 부분 없음. 단 `service_role` 등 관리자 키는 절대 불가(D-11).

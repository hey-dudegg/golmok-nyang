## 9. 인근 지역 날씨 빌려 쓰기 (D-97)

### 9-1. 원칙
- 고양이가 옆 동네로 놀러 가듯, 값이 빈 지역은 가까운 이웃의 값을 잠시 빌린다.
- (1) 같은 입력이면 누구나 같은 결과(결정적, D-19) (2) **직접 받은 값만 빌려준다** (3) 정해진 단계 안에서 반드시 끝난다
  (4) 순수 함수(core 층, fetch·시계·localStorage를 쓰지 않음, 지금 시각도 인자로 받음).

### 9-2. 입력·출력 (인터페이스 예시)
```js
// core/wx_borrow.js
// own:   Map<id, Wx|null>  이번 묶음에서 직접 받은 값만. Wx = { kind, amt, t, hours, at }
// graph: { ids(): string[], neighbors(id): string[], center(id): { lat, lng } }
// opt:   { maxHops, maxVisit, maxAgeMs, nowMs }
resolveWx(id, own, graph, opt) → { wx, from, hops } | null   // 자기 값이면 from === id, hops 0
resolveAll(own, graph, opt)    → Map<id, { wx, from, hops } | null>
```
- 결과는 새 Map으로 돌려준다. `own`·`graph`는 바꾸지 않는다. 그래프 만들기는 `state/weather.js`가 하고 함수에는 넘기기만 한다(시험은 가짜 그래프).

### 9-3. 이웃 고르기
1. 자기 값이 **쓸 수 있으면** 그대로(hops 0). 쓸 수 있음 = `kind`가 6종 중 하나 + `nowMs − at ≤ maxAgeMs`.
2. 아니면 너비 우선으로 1단계 → 2단계 … `maxHops`까지 넓힌다. 같은 단계 후보는 **중심 거리 가까운 순, 같으면 id 문자열 순.**
3. 처음 만나는 '쓸 수 있는 직접 받은 값'을 빌린다. 가까운 단계가 늘 먼 단계보다 앞선다.
4. 인접 이웃이 하나도 없는 지역(시/도에서는 제주)은 **중심 거리 가장 가까운 1곳**을 1단계 이웃으로 본다(그래프 만들 때 한 번 정하는 가상 연결).
5. 끝까지 못 찾으면 `null` → 장면·행동 `clear`, 패널 숨김.
- 신선도: 빌려주는 값도 자기 값과 같은 `maxAgeMs`(3시간, 1-4)를 통과해야 한다. 시/도는 16곳이 한 묶음이라 같은 시각 값끼리 빌린다.
  칸 단계(9-6)는 칸마다 받은 시각이 달라 이 조건이 실제로 걸린다.
- 값: 시/도 `maxHops 2`(그 너머는 날씨가 너무 다름), `maxVisit 16`. 칸 `maxHops 2`(0.05° 칸이면 약 10km), `maxVisit 25`(5×5).

### 9-4. 무한 반복·순환 방지
| 방지책 | 내용 |
|---|---|
| 직접 받은 값만 빌려줌 | 후보 값은 `own`에서만 읽는다. 빌린 결과는 출력 Map에만 쓰고 `own`에 넣지 않는다 → 빌린 값을 또 빌려주는 사슬이 생기지 않는다 |
| 방문 표시 | 탐색마다 `visited` 집합(자기 자신 포함). 한 번 본 id는 다시 큐에 넣지 않는다 → A↔B↔C↔A 순환도 끝난다 |
| 최대 단계 | `maxHops`를 넘는 이웃은 큐에 넣지 않는다 |
| 최대 방문 수 | 한 지역당 확인하는 이웃은 `maxVisit`까지. 넘으면 `null` |
| 재귀 없음·서로 독립 | 반복문 + 큐. 한 지역의 계산은 다른 지역의 결과를 읽지 않는다(계산 순서와 무관) |
| 그래프 정리 | 그래프 만들 때 자기 연결·중복·없는 id로의 연결은 버린다 |
- 계산량: 시/도 16곳 × 최대 16 방문 ≈ 256번 비교, 묶음을 받을 때 1번. 프레임마다 돌리지 않는다.

### 9-5. 패널에 빌린 값 표시 (제안, Q8)
- 권장: **그림은 보이되 흐리게(불투명도 0.6), 온도는 숨김.** 하늘 상태는 이웃끼리 비슷한 편이지만 온도는 산·바다로 차이가 커 틀린 숫자가 될 수 있다.
- `aria-label`·`title`: "흐림 · 인근 지역 날씨를 빌려 왔어요 · 14:30 기준". 어느 지역인지는 쓰지 않는다(놀러가기 표지판과 같은 방식, 수정설계 7장).
- 대안: 온도도 `≈12°`로 보여 주기(정보는 많지만 틀릴 수 있음). 장면·행동은 어느 쪽이든 빌린 값을 그대로 쓴다.

### 9-6. 시/도 그래프와 시군구·동 확장
- 시/도: `core/trips.js`의 `NEIGHBORS`(경계가 맞닿은 시/도, 수정설계 7장 놀러가기 표)를 그대로 쓴다. 놀러 가는 곳 = 날씨 빌리는 곳이라 "옆 동네" 뜻이 같다.
  제주(50)의 가상 연결(9-3 규칙 4)은 날씨 그래프에만 두고 놀러가기에는 쓰지 않는다. `center`는 `core/regions.js` 중심.
- 칸(5장): 함수는 그대로, 그래프만 바꾼다. `neighbors('7515_25395')` = 위도·경도 칸 번호 ±1의 8칸, `center` = 칸 번호 ÷ 20. 거리 순 규칙이라 상하좌우가 대각보다 앞선다.
- 칸 단계에서 자기 칸이 비면 1단계 8칸을 **한 번만** 더 요청한다(요청 상한 8칸과 같음). 2단계는 이미 받아 둔 칸만 쓴다 → 요청이 번지지 않는다.
- 시군구 경계 인접표는 아직 없다(`Trips.neighbors()`가 시/도 밖에서는 빈 배열). 그래서 확장 때는 행정 경계 대신 칸 그래프를 쓴다.

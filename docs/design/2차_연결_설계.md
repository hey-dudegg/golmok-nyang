## 0. 전제와 범위
- 원래 회원 전용(D-49·67): 게시판 글·댓글, 이름 제안·좋아요/싫어요·신고. **누구나**: 게시판 좋아요, 츄르, 홍보하기, 놀러가기, 싸움.
- "누구나"도 서버 기록(좋아요 등)에는 uid가 필요하므로 **Supabase 익명 로그인**으로 방문자에게 uid를 준다(배포_계획 1-4). 회원 = 소셜 로그인 + `members` 행이 있는 사람.
- **지금 범위(D-82~84)**: 소셜 로그인 보류(버튼 없음) → 모든 방문자는 익명 uid. 게시판은 읽기·좋아요만, 글·댓글은 '준비 중'(서버도 거부, D-83). 이름 짓기는 임시로 익명 허용(D-84). 표·RLS·함수는 회원 기능까지 다 만들어 두고, 켜고 끄기는 2-1의 `app_config.features` 한 줄로 한다.
- 환경(D-81): 운영 `https://golmok-nyang.pages.dev`, 테스트 `https://test.golmok-nyang.pages.dev`. Supabase 프로젝트도 운영·테스트 2개.
- 어드민 판별은 `admins` 표 + `is_admin()` 함수(관리자 키 없음, D-11). 화면 `isOwner()`는 버튼 표시용일 뿐 방어는 RLS.
- 게시판·이름 갱신은 Realtime을 쓰지 않는다: "열 때 읽기 + 내가 쓴 뒤 다시 읽기 + 보이는 동안 60초마다 읽기"로 `onSnapshot` 모양을 흉내(메시지 한도 보호). Realtime은 8장(사람 수·홍보)에만 쓴다(D-79).
- 이번 범위 밖: 로그 표(로그_설계), 의견(D-62 Pages Function), 이웃 데이터 이전(D-51).
- D-51 호환: 글·이름 표의 `uid`는 null 허용(null = 옛 데이터 이전분, 클라이언트는 넣을 수 없음), `legacy_author text` 열을 둔다. id는 uuid.
- 새 의존성: supabase-js ESM 번들 1개를 `prototype/vendor/`에 버전 고정으로 둔다(D-13·47, MIT). M2-5a에서 추가됨.
- 불확실한 것은 [미확인]으로 표시. 테스트 프로젝트·테스트 주소에서 먼저 확인한다.

## 1. P-07 결론: 공개 키 주입
**권장 A: `prototype/src/config.js`에 Project URL과 공개 키(publishable 또는 anon)를 커밋하고, 접속 주소로 운영/테스트를 고른다.**
- 빌드 없음(D-13) 유지. 로컬 `python3 -m http.server`·`npm test`가 그대로 돈다.
- 공개 키는 어차피 모든 방문자 브라우저에 내려간다. 저장소에 있든 없든 노출 정도가 같고, 방어선은 RLS다(D-22 공개 저장소여도 추가 위험 없음).
- 관리자 키(service_role·`sb_secret_`)는 어디에도 쓰지 않는다(D-11). `/secure-check`에 두 문자열과 "config.js 밖의 `eyJ`·`sb_publishable_`" 검사를 더한다(devops).
- 부작용: GitHub 비밀 스캐너가 공개 키에 경고를 낼 수 있다(공개 키라 무시 가능, 사용자에게 미리 안내).

사용자 결정이 필요하면 두 안으로 묻는다.
| | A. config.js 커밋(권장) | C. Pages Function `/api/config`가 환경 변수를 JSON으로 돌려줌 |
|---|---|---|
| 빌드 | 없음 | 없음(D-62로 Functions는 이미 씀) |
| 저장소에 키 | 있음(공개 키) | 없음 |
| 방문자에게 키 | 보임 | 보임(같음) |
| 비용·속도 | 0, 추가 요청 없음 | 시작할 때 요청 1회 추가, Functions 무료 일 한도 소비 |
| 로컬 시험 | 그대로 | python 서버엔 Functions가 없어 모의로만, 실연결 로컬 시험은 wrangler 필요 |
옛 B안(빌드 때 치환)은 D-13에 어긋나 제외한다. 설정 모양(A 기준, 값은 빈칸이면 모의):
```js
export const SUPABASE_CONFIG = {           // 공개 값만. 비어 있으면 서버 연결 없이 지금과 같게 동작
  prod: { hosts: ['golmok-nyang.pages.dev'],      url: '', key: '' },   // 운영 프로젝트 값
  test: { hosts: ['test.golmok-nyang.pages.dev'], url: '', key: '' },   // 테스트 프로젝트 값 (옛 이름 staging)
};
export const FEATURES_DEFAULT = { login: false, board_write: false, names_anon: true };  // mock·static 모드용(2-1과 같은 값)
```
- 지금 `config.js` 15~16행은 자리표시 호스트와 `staging` 항목이다 → M2-5b에서 `prod`·`test` 두 항목을 위 호스트로 바꾸고 `FEATURES_DEFAULT`를 더한다(developer). url·key는 사용자가 준 공개 값만.

## 4. 로그인 흐름
**지금 범위는 1번(익명 세션)뿐이다. 2~7번과 아래 항목은 소셜 로그인 보류(D-82)로 구현하지 않고, 재개 때 쓰려고 남겨 둔다.** 재개 조건: 사용자 할 일 B·C(6장) + `features.login=true`(2-1).
1. 첫 방문: 세션이 없으면 `signInAnonymously()`로 익명 uid(브라우저에 세션 저장, 다시 와도 같은 uid). 실패하면 5-2의 "연결 없음"으로. **[현재 범위]** 로그아웃·탈퇴 버튼도 지금은 없다(익명 uid는 브라우저 데이터를 지우면 사라짐).
2. [보류] 로그인 버튼(회원 전용 동작을 누를 때 또는 메뉴): 카카오 / Google 두 버튼. `signInWithOAuth({ provider, options: { redirectTo: location.origin + location.pathname } })`, `flowType: 'pkce'`.
3. 카카오·Google → Supabase 콜백 `https://<프로젝트>.supabase.co/auth/v1/callback` → 우리 사이트로 돌아옴(코드 교환은 supabase-js가 자동).
4. 돌아왔을 때 `members` 행이 없으면 가입 시트(`ui/signup`): 닉네임, 동네(선택), **"만 14세 이상입니다"(필수, D-52)**, **이용 안내·개인정보 안내 동의(필수, 링크, D-57)**. 동의 전에는 회원 전용 동작 불가(서버도 `is_member()`로 거부).
   - 시트를 닫으면 `signOut()` 후 다시 익명. 가입 안 끝난 계정은 7일 뒤 정리(2-7).
5. 가입 완료: `members` insert(트리거가 nick 필터·약관 버전 확인) → 로컬 교감 기록을 `bonds`로 한 번 올림.
6. 로그아웃: `signOut()` → 새 익명 세션. 익명 시절 좋아요는 옛 익명 uid에 남는다(수용).
7. 탈퇴: 확인 창 두 번 → 내 캡쳐 폴더 지우기 → `member_leave()` → `signOut()` → 안내 "모든 글·이름·기록을 지웠어요".
- 익명 계정을 소셜 계정으로 "연결"하는 기능(linkIdentity)은 쓰지 않는다(설정·시험이 늘어남). 로그인하면 새 uid다.
- 리디렉트 허용 주소(Supabase URL Configuration, D-81로 설정 완료). **프로젝트마다 자기 주소만 넣고 서로의 주소는 넣지 않는다.**
  - 운영 프로젝트: Site URL `https://golmok-nyang.pages.dev/`, Redirect URLs `https://golmok-nyang.pages.dev/**`만.
  - 테스트 프로젝트: Site URL `https://test.golmok-nyang.pages.dev/`, Redirect URLs `https://test.golmok-nyang.pages.dev/**`만.
- 카카오톡 안 브라우저에서는 Google 로그인이 막힌다(구글 정책). 이 환경을 알아보면 Google 버튼 대신 "외부 브라우저로 열어 주세요" 안내.
- [미확인] Supabase 카카오 공급자가 이메일 동의를 기본 요청하는지. 개인 개발자 앱은 이메일 동의를 못 받을 수 있다. 재개 때 테스트 프로젝트에서 먼저 확인하고, 막히면 대시보드의 이메일 없는 사용자 허용 옵션 또는 `scopes` 지정으로 푼다. 안 되면 보고.
- 개인정보: auth.users에 공급자가 준 닉네임·(Google은) 이메일이 저장된다. 개인정보 안내(D-57)에 반영 필요(documenter).

## 5. 어댑터 전환과 시험
### 5-1. 선택 순서 (`initCaps`)
1. `window.claude`가 있으면 지금처럼 아티팩트 어댑터.
2. `SUPABASE_CONFIG`에서 `location.hostname`이 맞는 항목이 있고 url·key가 둘 다 있으면 Supabase 어댑터 (`Caps.mode='supabase'`).
3. 로컬 주소면 LocalMock(D-21, `Caps.mode='mock'`). 4. 그 밖은 지금의 정적 모드(`'static'`).
- 키가 비었거나 주소가 안 맞으면 **지금과 똑같다**(1차 배포 그대로). 되돌리기 = config 값 비우고 재배포.

### 5-2. 연결 실패
- supabase-js를 못 받거나 익명 로그인·첫 읽기가 실패하면 `Caps.db=null`(이 브라우저 체험 모드)로 떨어지고 알림 한 줄 "지금은 서버에 연결되지 않아 이 기기에만 저장돼요". 앱은 멈추지 않는다.
- 쓰기 중 네트워크 오류는 `code='network'`로 넘겨 화면이 다시 시도 안내.

### 5-3. 인터페이스 (화면 코드 변경 최소)
```js
// src/adapters/supabase.js — client를 인자로 받아 시험에서 가짜 client를 넣을 수 있게 한다
export function createSupabaseCaps(client, cfg) { return { user, db, room: null, lock: null }; }
// user: id(), isOwner(), can(), isAnonymous(), onChange(f)          ← M2-5b 범위(익명 세션)
//       can('post')=features.board_write && 회원, can('name')=features.names_anon || 회원 (서버 2-1과 같은 규칙)
//       [보류 D-82] signIn('kakao'|'google'), signOut(), leave() — 재개 때 추가
// caps.features: 시작 때 app_config.features 1회 읽기(실패 시 FEATURES_DEFAULT)
// db  : collection(path).orderBy().limit().onSnapshot(f) / .add(obj),  doc(path).get/set/update/delete
//       배포_계획 1-3의 경로만 표로 번역. posts의 likes·comments 맵은 어댑터가 옛 모양으로 합쳐 돌려준다.
//       posts update {likes:{[me]:on}} → post_likes insert/delete, {comments:{[cid]:c}} → post_comments insert
//       names2 update(up/down) → rpc name_vote, 신고 → rpc report, add(post+img) → insert → upload → rpc post_attach
//       서버 오류는 Error(code)로 던진다(3-6).
```
- LocalMock.user에 `isAnonymous·onChange`를 추가하고 `can()`을 `FEATURES_DEFAULT`로 판정(지금은 익명 이름 짓기·게시판 준비 중). 가짜 회원 전환(`signIn·signOut·leave`)·가입 시트 시험은 로그인 재개 때. 신고·필터는 모의에서 `core/text_filter.js`의 정규식만 적용.

### 5-4. 시험 방법 (실서버 없이 대부분)
| 층 | 방법 | 서버 |
|---|---|---|
| 필터 정규식 | `core/text_filter.js` 단위 시험 + 공통 벡터 `tests/filter_cases.json`(막을 것·통과할 것 각 30줄 이상, 금칙어 제외) | 없음 |
| 어댑터 번역 | `tests/fakes/supabase_fake.js`(from·select·insert·rpc·auth·storage 흉내)로 경로 번역·모양 합치기·오류 코드 변환·실패 시 체험 모드 | 없음 |
| 기존 회귀 | `npm test` 전부 통과 = 키 없을 때 동작 불변 | 없음(자체 서버) |
| DB 규칙 | `supabase/tests/check.sql`: 한 트랜잭션에서 가짜 auth.users·역할(`set local role authenticated`, `request.jwt.claims`)로 **features 기본값에서** 익명 글·댓글·업로드 거부(`feature_off`), 익명 이름 제안·투표·이름 신고 허용, 익명 게시판 신고 거부, 남의 글·이름 삭제 거부, 서버 열 덮어쓰기, 필터 벡터, 도배, 지역별 5개, 중복 신고, 3회 숨김, 복구 후 재신고. 이어서 같은 트랜잭션에서 features를 재개 값으로 바꿔 회원 글 허용·익명 이름 거부도 확인. PASS/FAIL 표 출력 후 `rollback` | 테스트 프로젝트 SQL Editor(사용자 실행) |
| 실제 동작 | 테스트 주소에서 두 브라우저(익명)로 게시판 읽기·좋아요, 이름 제안·투표가 서로 보임, 글쓰기 칸이 '준비 중' | 테스트 |
| [보류] 실제 로그인 | 재개 때 테스트 주소에서 카카오·Google 로그인·가입·로그아웃·탈퇴 | 테스트 |
[미확인] auth.users에 가짜 행을 넣을 때 필수 열. 안 되면 check.sql은 실제 시험 계정 uid 2개를 변수로 받는다(값은 파일에 쓰지 않음).

## 6. 사용자 할 일 (순서대로. 화면 이름은 바뀔 수 있음 [미확인])
A. Supabase (무료, 카드 등록 안 함)
1. [완료 D-81] 새 프로젝트 2개(테스트·운영, 이름에 실명·회사명 금지), 지역 Seoul. DB 비밀번호는 비밀번호 관리자에만.
2. [완료 D-81] Settings → API에서 Project URL과 공개 키(publishable 또는 anon)만 개발자에게 전달. `service_role`·`secret` 키는 복사도 전달도 하지 않는다.
3. [완료 D-81] Authentication → Sign In / Providers: Anonymous 켬, Email 끔. Kakao·Google은 보류(D-82).
4. [완료 D-81] Authentication → URL Configuration: 프로젝트마다 자기 주소만(4장). 운영은 `https://golmok-nyang.pages.dev/`·`/**`, 테스트는 `https://test.golmok-nyang.pages.dev/`·`/**`. 서로의 주소가 들어가 있으면 지운다.
5. SQL Editor에서 `supabase/sql/` 파일을 01→08 순서로 하나씩 붙여 넣고 Run(오류는 화면 그대로 알려 주기). 그다음 개발자가 따로 준 금칙어 파일 실행. 테스트 프로젝트 먼저.
6. 어드민 등록(로그인 보류 중엔 익명 uid가 어드민): 테스트 주소를 본인 브라우저로 한 번 연 직후 Authentication → Users에서 방금 생긴 익명 사용자(만든 시각으로 찾기)의 User UID 복사 → `insert into public.admins values ('<내 uid>');` 실행(uid는 저장소·채팅에 쓰지 않음). 그 브라우저의 사이트 데이터를 지우면 어드민이 풀리므로 다시 등록하고 옛 행을 지운다. 로그인 재개 뒤엔 회원 uid로 바꾼다.
7. `supabase/tests/check.sql` 실행 → 전부 PASS인지 확인. 테스트 프로젝트가 끝나면 운영 프로젝트에 5~7 반복(운영 주소로 6번).
B. [보류 D-82] 카카오 디벨로퍼스 — 로그인 재개 때 진행. 주소는 운영·테스트 두 개.
1. 애플리케이션 추가 → 플랫폼 Web에 사이트 도메인 `https://golmok-nyang.pages.dev`, `https://test.golmok-nyang.pages.dev` 등록.
2. 카카오 로그인 활성화 → Redirect URI에 `https://<프로젝트>.supabase.co/auth/v1/callback`(프로젝트마다).
3. 동의항목: 닉네임만 필수. 프로필 사진·이메일은 받지 않음(4장 [미확인] 참고).
4. 보안 메뉴에서 Client Secret 생성·사용 켬. **REST API 키 → Supabase Kakao의 Client ID, Client Secret → Secret 칸**에만 붙여 넣는다.
C. [보류 D-82] Google Cloud 콘솔 — 로그인 재개 때 진행. 끝나면 2-1의 features 한 줄 갱신.
1. 새 프로젝트 → OAuth 동의 화면: 외부, 앱 이름 "골목냥", 범위는 기본(openid·email·profile)만. 지원 이메일은 콘솔에만 입력.
2. 게시 상태를 "프로덕션"으로(테스트 상태는 등록한 시험 사용자만 로그인 가능). 기본 범위라 심사는 필요 없다고 알려져 있음 [미확인].
3. 사용자 인증 정보 → OAuth 클라이언트 ID(웹): 승인된 JavaScript 원본 = 사이트 주소들, 승인된 리디렉션 URI = Supabase 콜백 주소.
4. **클라이언트 ID·보안 비밀 → Supabase Google 공급자 칸**에만 붙여 넣는다. 저장소·채팅·.env에 쓰지 않는다(서버 쪽 비밀이라 Supabase만 가짐).
D. 실시간(M2-9): [2차_연결_실시간.md](2차_연결_실시간.md) 8-8 참고(A-5 뒤에 `08_realtime` 실행, Realtime 설정 확인).

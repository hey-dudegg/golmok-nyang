## 0. 전제와 범위
- 회원 전용(D-49·67): 게시판 글·댓글, 이름 제안·좋아요/싫어요·신고. **누구나**: 게시판 좋아요, 츄르, 홍보하기, 놀러가기, 싸움.
- "누구나"도 서버 기록(좋아요 등)에는 uid가 필요하므로 **Supabase 익명 로그인**으로 방문자에게 uid를 준다(배포_계획 1-4). 회원 = 소셜 로그인 + `members` 행이 있는 사람.
- 어드민 판별은 `admins` 표 + `is_admin()` 함수(관리자 키 없음, D-11). 화면 `isOwner()`는 버튼 표시용일 뿐 방어는 RLS.
- 게시판·이름 갱신은 Realtime을 쓰지 않는다: "열 때 읽기 + 내가 쓴 뒤 다시 읽기 + 보이는 동안 60초마다 읽기"로 `onSnapshot` 모양을 흉내(메시지 한도 보호). Realtime은 8장(사람 수·홍보)에만 쓴다(D-79).
- 이번 범위 밖: 로그 표(로그_설계), 의견(D-62 Pages Function), 이웃 데이터 이전(D-51).
- D-51 호환: 글·이름 표의 `uid`는 null 허용(null = 옛 데이터 이전분, 클라이언트는 넣을 수 없음), `legacy_author text` 열을 둔다. id는 uuid.
- 새 의존성: supabase-js ESM 번들 1개를 `prototype/vendor/`에 버전 고정으로 둔다(D-13·47, MIT). **의존성 추가라 팀장 확인 필요**(손으로 REST·Auth를 짜면 작업량이 2배 이상).
- 불확실한 것은 [미확인]으로 표시. 스테이징에서 먼저 확인한다.

## 1. P-07 결론: 공개 키 주입
**권장 A: `prototype/src/config.js`에 Project URL과 공개 키(publishable 또는 anon)를 커밋하고, 접속 주소로 운영/스테이징을 고른다.**
- 빌드 없음(D-13) 유지. 로컬 `python3 -m http.server`·`npm test`가 그대로 돈다.
- 공개 키는 어차피 모든 방문자 브라우저에 내려간다. 저장소에 있든 없든 노출 정도가 같고, 방어선은 RLS다(D-22 공개 저장소여도 추가 위험 없음).
- 관리자 키(service_role·`sb_secret_`)는 어디에도 쓰지 않는다(D-11). `/secure-check`에 두 문자열과 "config.js 밖의 `eyJ`·`sb_publishable_`" 검사를 더한다(devops).
- 부작용: GitHub 비밀 스캐너가 공개 키에 경고를 낼 수 있다(공개 키라 무시 가능, 사용자에게 미리 안내).

사용자 결정이 필요하면 두 안으로 묻는다.
| | A. config.js 커밋(권장) | C. Pages Function `/api/config`가 환경 변수를 JSON으로 돌려줌 |
|---|---|---|
| 빌드 | 없음 | 없음(D-62로 Functions는 이미 씀) |
| 저장소에 키 | 있음(공개 키) | 없음 |
| 방문자에게 키 | 보임 | 보임(같음) |
| 비용·속도 | 0, 추가 요청 없음 | 시작할 때 요청 1회 추가, Functions 무료 일 한도 소비 |
| 로컬 시험 | 그대로 | python 서버엔 Functions가 없어 모의로만, 실연결 로컬 시험은 wrangler 필요 |
옛 B안(빌드 때 치환)은 D-13에 어긋나 제외한다. 설정 모양(A 기준, 값은 빈칸이면 모의):
```js
export const SUPABASE_CONFIG = {           // 공개 값만. 비어 있으면 서버 연결 없이 지금과 같게 동작
  prod:    { hosts: ['<사이트>.pages.dev'],         url: '', key: '' },
  staging: { hosts: ['staging.<사이트>.pages.dev'], url: '', key: '' },
};
```

## 2. 표·RLS·저장소
원칙: 모든 표 RLS 켬, 정책 없으면 거부. 서버가 정하는 열(status·nick·created_at·img)은 트리거가 덮어쓴다. 함수는 `security definer` + `set search_path = ''` + 표 이름에 `public.` 접두.
SQL 파일(값 없음, 저장소 `supabase/sql/`): `01_base` `02_members` `03_board` `04_names` `05_moderation` `06_storage` `07_misc` `08_realtime`(8장) `99_rollback`. 금칙어 초기값은 저장소에 넣지 않는다(3-1).

### 2-1. 공통 함수
```sql
create table public.admins (uid uuid primary key references auth.users on delete cascade);  -- 정책 없음
create function public.is_admin() returns boolean ...  -- exists(admins where uid = auth.uid())
create function public.is_anon()  returns boolean ...  -- coalesce((auth.jwt()->>'is_anonymous')::boolean, true)
create function public.is_member() returns boolean ... -- not is_anon() and exists(members where uid = auth.uid())
create table public.app_config (key text primary key, value jsonb not null);  -- 읽기 모두, 쓰기 is_admin()
-- 초깃값: limits(3-3), report_hide {"post":3,"comment":3,"name":3}, terms_ver "2026-10"
```
[미확인] 익명 JWT 클레임 이름 `is_anonymous`. 없으면 true(익명 취급)로 기울게 해 안전 쪽으로 실패한다.

### 2-2. 회원 `members`
```sql
create table public.members (
  uid uuid primary key references auth.users on delete cascade,
  nick text not null check (char_length(nick) between 1 and 12),
  home text check (char_length(home) <= 40),
  age_ok boolean not null check (age_ok),            -- 만 14세 이상 확인(D-52). false는 넣을 수 없음
  terms_ver text not null, agreed_at timestamptz not null default now(),
  joined_at timestamptz not null default now());
-- select: uid = auth.uid() or is_admin()   (남에게 보이는 이름은 posts.nick 복사본만 → 회원 표는 비공개)
-- insert: uid = auth.uid() and not is_anon()         update: uid = auth.uid() (nick·home만, 열 권한으로 제한)
-- 트리거 members_guard: nick 필터(3장), terms_ver가 app_config 값과 다르면 거부
```
- `bonds`(uid pk, data jsonb, `pg_column_size(data) <= 16384`): 회원만 본인 읽기·쓰기. **익명 방문자의 교감 기록은 지금처럼 localStorage**(익명 uid는 브라우저를 지우면 사라지므로 DB에 쌓지 않음). 가입 직후 로컬 기록을 한 번 올린다.

### 2-3. 게시판 `posts`·`post_comments`·`post_likes`
```sql
create table public.posts (
  id uuid primary key default gen_random_uuid(),
  uid uuid references auth.users on delete cascade,   -- null = 이전 데이터(D-51)
  legacy_author text, nick text not null,
  body text not null check (char_length(body) between 1 and 500),
  img text,                                            -- 저장소 경로 '<uid>/<id>.webp|jpg', 서버만 채움(2-4)
  status text not null default 'ok' check (status in ('ok','hidden','removed')),
  hidden_at timestamptz, created_at timestamptz not null default now());
create table public.post_comments (
  id uuid primary key default gen_random_uuid(),
  post_id uuid not null references public.posts on delete cascade,
  uid uuid references auth.users on delete cascade, legacy_author text, nick text not null,
  body text not null check (char_length(body) between 1 and 200),
  status text not null default 'ok' check (status in ('ok','hidden','removed')),
  hidden_at timestamptz, created_at timestamptz not null default now());
create table public.post_likes (
  post_id uuid references public.posts on delete cascade,
  uid uuid references auth.users on delete cascade, primary key (post_id, uid));
```
| 표 | select | insert | update | delete |
|---|---|---|---|---|
| posts | `status='ok' or uid=auth.uid() or is_admin()` | `uid=auth.uid() and is_member()` | 없음(RPC만) | `uid=auth.uid() or is_admin()` |
| post_comments | 위와 같고, 부모 글이 보이는 경우만 | `uid=auth.uid() and is_member()` | 없음 | `uid=auth.uid() or is_admin()` |
| post_likes | 모두 | `uid=auth.uid()`(익명 포함, D-67) | 없음 | `uid=auth.uid()` |
- 트리거 `posts_before_insert`: `nick`=members.nick, `status`='ok', `img`=null, `created_at`=now(), `hidden_at`=null로 덮어씀 → `gn_text_check('post', body)` → `gn_rate_check('post')`. 댓글도 같다.
- 수정 기능은 없다(쓰기·지우기만). 목록은 `status='ok'` 최신 20개 + `post_likes(uid)`·`post_comments(...)` 함께 읽기(embedded select).

### 2-4. 캡쳐 저장소 (D-75)
"앱이 찍은 캡쳐인지"를 서버가 증명할 방법은 없다. 실현 가능한 수단을 겹쳐 쓴다.
1. 화면: 게시판에 파일 선택(`<input type=file>`)·붙여넣기·끌어놓기 받기가 없다. 그림은 `interact` 캡쳐 함수의 캔버스 결과만 쓴다.
2. 클라이언트 고정 규격: 긴 변 960px 이하로 줄여 WebP(못 만들면 JPEG) 품질 0.8, 120KB 넘으면 품질을 낮춰 재시도, 그래도 넘으면 그림 없이 올림.
3. 버킷 `captures`(공개 읽기): `file_size_limit` 131072바이트, `allowed_mime_types` `image/webp`, `image/jpeg`.
4. 경로·개수 정책(`storage.objects`):
```sql
-- insert: bucket_id='captures' and not is_anon()
--   and (storage.foldername(name))[1] = auth.uid()::text
--   and exists (select 1 from public.posts p where p.uid = auth.uid() and p.img is null
--               and p.created_at > now() - interval '10 minutes'
--               and storage.filename(name) in (p.id||'.webp', p.id||'.jpg'))   -- 글 1개에 그림 1장, 갓 쓴 글만
-- update: 없음(덮어쓰기 불가)   delete: 폴더 주인 또는 is_admin()   select: 공개 버킷이라 URL 읽기
```
5. 순서: `posts` insert(필터 통과) → 그림 올리기 → RPC `post_attach(post_id)`가 `storage.objects`에 그 경로가 있는지 확인하고 `img`를 채움.
6. 해상도는 서버에서 검사하지 않는다(파일 머리 해석은 DB 함수로 무리). 크기 상한 + 신고(3장)로 막는다.
7. 글 삭제 때 화면이 그림을 먼저 지운다. 남는 고아 파일은 어드민이 대시보드에서 지운다(관리자 키 없이 자동 정리는 하지 않음).
[미확인] 공개 버킷 전송량이 DB 전송량 5GB와 합산되는지. 목록 20개 × 120KB ≈ 2.4MB/회, `loading="lazy"`로 화면에 보이는 것만 받는다.

### 2-5. 이름 `names2`·`name_votes`
```sql
create table public.names2 (
  id uuid primary key default gen_random_uuid(),
  region text not null,                        -- 화면 경로 names2/{code}/list 의 code
  name text not null check (char_length(name) between 1 and 8),   -- NAME_RULE.MAXLEN과 맞춤
  uid uuid references auth.users on delete cascade, legacy_author text, nick text,
  up int not null default 0, down int not null default 0,
  status text not null default 'ok' check (status in ('ok','hidden','removed')),
  hidden_at timestamptz, created_at timestamptz not null default now());
create table public.name_votes (
  name_id uuid references public.names2 on delete cascade,
  uid uuid references auth.users on delete cascade,
  vote text not null check (vote in ('up','down')), primary key (name_id, uid));
```
- `names2`: select `status='ok' or uid=auth.uid() or is_admin()`, insert `uid=auth.uid() and is_member()`, update·delete 없음(본인 삭제는 RPC). 트리거: nick 복사·서버 열 덮어쓰기 → 필터 → (uid, region) 5개 제한(D-31) → 도배 검사.
- `name_votes`: 클라이언트 직접 쓰기 없음. RPC `name_vote(name_id, vote)`(회원만, 같은 표 다시 누르면 취소, 반대면 바꿈, up·down 다시 셈, `down > up`이면 status='removed', D-31).
- 신고는 3장의 공통 `reports`로(D-31 "신고 5개 삭제"와 D-74 "신고 3회 숨김"이 다름 → 팀장 확인 필요, 값은 `app_config.report_hide.name` 하나로 바꿀 수 있게 둠).

### 2-6. 기타 (배포_계획 1-4에서 이어받음)
- `admin_kv`(레시피): 읽기·쓰기 `is_admin()`. 화면 경로 `admin/recipes`.
- `promo_lock`·`promo_try`: 이번 범위 밖. 다만 D-67로 홍보는 누구나이므로 나중에 만들 때 "회원 전용" 조건을 빼고 uid당 쿨다운만 둔다(1-4 초안과 다름).

### 2-7. 탈퇴·정리 함수
- `member_leave()`: `delete from auth.users where id = auth.uid()` (security definer). cascade로 회원·교감·글·댓글·좋아요·이름·투표·신고가 지워진다. 그림 파일은 화면이 먼저 자기 폴더를 지운다.
- `daily_cleanup()`(D-09 Actions 하루 1회 호출, 배포_계획 1-5(e)): 가입 안 끝난 소셜 계정(members 행 없음) 7일 지나면 삭제, `status='removed'` 30일 지난 글·이름 삭제, 처리된 신고 30일 지나면 삭제.

## 3. 필터링·신고·어드민 복구
### 3-1. 금칙어 목록
- 위치: 표 `filter_words(word text primary key, added_at timestamptz default now())`. **RLS 켜고 정책 없음** → 방문자는 읽을 수 없고, 함수(`gn_text_check`, security definer)만 읽는다.
- 저장소 노출: 목록 자체가 보안 비밀은 아니지만, 공개되면 피해 가는 변형을 쉽게 찾고 공개 저장소에 욕설 목록이 남는다. **저장소에는 넣지 않는다.** 정규식(URL·연락처)은 일반적이라 저장소 SQL에 둔다.
- 초기값: developer가 `supabase/private/seed_words.sql`(.gitignore 대상, 추가 필요)로 만들어 사용자에게 건네고, 사용자가 SQL Editor에서 한 번 실행.
- 갱신: 사용자(어드민)가 Supabase Table Editor에서 줄 추가·삭제. 어드민 화면 편집은 만들지 않는다(필요해지면 RPC 2개로 추가).
- 단어는 정규화 뒤 형태(3-2)로 저장한다. 앱 쪽 `core/text_filter.js`는 정규식만 미리 검사하고(빠른 안내), 금칙어는 서버만 안다.

### 3-2. `gn_text_check(kind text, txt text)` — 거부 시 `raise exception '<코드>'`
정규화: `n1 = lower(normalize(txt, NFKC))`, 0폭 문자(`​-‍﻿`) 제거. `n2 = n1`에서 공백·`.-_,·*~!/|` 제거(단어 붙여 쓰기 대비).
| 코드 | 검사(Postgres 정규식, `~*`) | 대상 |
|---|---|---|
| `filter_word` | `exists(select 1 from filter_words w where n2 like '%'||w.word||'%')` | n2 |
| `filter_url` | `(https?://|www\.)` 또는 `[a-z0-9-]+\.(com|net|org|kr|co|io|me|ly|gg|xyz|site|shop|link|app|to)\M` 또는 `(닷컴|닷넷|점컴|open\.kakao)` | n1 |
| `filter_contact` | 전화: 구분자 뺀 n2에 `[0-9]{9,}` 또는 `01[016789][0-9]{7,8}` / 한글 숫자 `공일공` | n2 |
| `filter_contact` | 이메일: `[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}` 또는 `골뱅이` | n1 |
| `filter_contact` | 메신저 ID: `(카톡|카카오톡|ㅋㅌ|katalk|kakao|오픈채팅|오픈톡|텔레|텔레그램|telegram|라인|line|디엠|dm|인스타|insta)\s*(아이디|id)?\s*[:：]?\s*[a-z0-9._-]{4,}` 또는 `@[a-z0-9_.]{4,}` | n1 |
- 이름(kind='name')·닉네임(kind='nick')은 추가로 `^[가-힣a-z0-9 ]+$`(한글·영문·숫자·띄어쓰기만, core/name_rules와 맞춤)이 아니면 `filter_chars`.
- 오탐(정상 문장 차단)을 고칠 때는 SQL 함수를 새 파일로 교체(`create or replace`), 같은 시험 벡터(5-3)로 확인.

### 3-3. 도배 `gn_rate_check(kind text)` — 서버 시각 기준, 위반 시 `rate_limit`
`app_config.limits` 초깃값(어드민이 값만 바꿔 조정):
| kind | 최소 간격 | 10분당 | 1시간당 | 같은 내용 |
|---|---|---|---|---|
| post | 30초 | 3 | 6 | 24시간 안 같은 본문(정규화 n2 기준) 거부 `dup` |
| comment | 10초 | 10 | 30 | 1시간 안 같은 본문 거부 |
| name | 5초 | 10 | 20 | 같은 region에 같은 이름 있으면 거부 `dup` |
| nick 변경 | - | - | 3 | - |
- 셈은 해당 표에서 `uid = auth.uid() and created_at > now() - interval`로 바로 센다(별도 집계표 없음, 인덱스 `(uid, created_at)`).
- 지운 글도 세려면 삭제 대신 남는 흔적이 필요하나, 단순화를 위해 지운 글은 세지 않는다(쓰고 지우기 반복은 1시간당 한도로 막힘: 지워도 간격 검사는 마지막 글 기준이라 우회 가능 → 수용, 신고로 대응).

### 3-4. 신고 `reports`와 자동 숨김
```sql
create table public.reports (
  kind text check (kind in ('post','comment','name')), target uuid,
  uid uuid references auth.users on delete cascade,
  cleared boolean not null default false, created_at timestamptz not null default now(),
  primary key (kind, target, uid));                    -- 한 사람이 같은 대상 한 번만(중복 신고 방지)
-- RLS 켬. select: is_admin()만. insert·update·delete 정책 없음(RPC만)
```
`report(kind, target)` RPC:
1. `is_member()` 아니면 `need_member`. 자기 글·이름이면 조용히 무시(성공처럼 돌려줌).
2. `insert ... on conflict do nothing` (중복은 조용히 무시, 횟수는 알려 주지 않음 D-31).
3. `cleared = false` 신고 수 ≥ `app_config.report_hide[kind]`이면 대상 `status='hidden', hidden_at=now()`.
- 게시판 글·댓글 신고 권한: D-67 목록에 없으나, 익명 uid는 브라우저마다 새로 생겨 3회 숨김을 혼자 만들 수 있으므로 **회원 전용으로 설계**(팀장 확인 필요).

### 3-5. 어드민 확인·복구 (is_admin() 검사 RPC)
- `mod_list()`: hidden 상태의 글·댓글·이름과 신고 수, 숨긴 시각(최근 순 50개).
- `mod_restore(kind, target)`: status='ok', hidden_at=null, 그 대상의 신고 `cleared=true` → 다시 숨기려면 새 신고 3개가 필요.
- `mod_remove(kind, target)`: status='removed'(화면 어디에도 안 보임, 30일 뒤 정리). 글이면 화면이 그림 파일도 지운다.
- 화면: `ui/admin_panel`에 "숨김 검토" 칸 추가(목록·복구·삭제 버튼). 어드민이 아니면 RPC가 `need_admin`으로 거부.

### 3-6. 오류 코드 → 화면 문구
서버 메시지는 코드만 보낸다. 어댑터가 `Error.code`로 넘기고 `ui`가 한국어로 바꾼다:
`need_member` 로그인한 회원만 할 수 있어요 / `filter_word` 쓸 수 없는 말이 있어요 / `filter_url` 링크는 올릴 수 없어요 /
`filter_contact` 연락처·메신저 아이디는 올릴 수 없어요 / `filter_chars` 한글·영문·숫자만 쓸 수 있어요 / `rate_limit` 잠시 뒤에 다시 써 주세요 /
`dup` 같은 내용이 이미 있어요 / `need_admin`·기타 잠시 뒤 다시 시도해 주세요. 어떤 단어가 걸렸는지는 알려 주지 않는다.

## 4. 로그인 흐름
1. 첫 방문: 세션이 없으면 `signInAnonymously()`로 익명 uid(브라우저에 세션 저장, 다시 와도 같은 uid). 실패하면 5-2의 "연결 없음"으로.
2. 로그인 버튼(회원 전용 동작을 누를 때 또는 메뉴): 카카오 / Google 두 버튼. `signInWithOAuth({ provider, options: { redirectTo: location.origin + location.pathname } })`, `flowType: 'pkce'`.
3. 카카오·Google → Supabase 콜백 `https://<프로젝트>.supabase.co/auth/v1/callback` → 우리 사이트로 돌아옴(코드 교환은 supabase-js가 자동).
4. 돌아왔을 때 `members` 행이 없으면 가입 시트(`ui/signup`): 닉네임, 동네(선택), **"만 14세 이상입니다"(필수, D-52)**, **이용 안내·개인정보 안내 동의(필수, 링크, D-57)**. 동의 전에는 회원 전용 동작 불가(서버도 `is_member()`로 거부).
   - 시트를 닫으면 `signOut()` 후 다시 익명. 가입 안 끝난 계정은 7일 뒤 정리(2-7).
5. 가입 완료: `members` insert(트리거가 nick 필터·약관 버전 확인) → 로컬 교감 기록을 `bonds`로 한 번 올림.
6. 로그아웃: `signOut()` → 새 익명 세션. 익명 시절 좋아요는 옛 익명 uid에 남는다(수용).
7. 탈퇴: 확인 창 두 번 → 내 캡쳐 폴더 지우기 → `member_leave()` → `signOut()` → 안내 "모든 글·이름·기록을 지웠어요".
- 익명 계정을 소셜 계정으로 "연결"하는 기능(linkIdentity)은 쓰지 않는다(설정·시험이 늘어남). 로그인하면 새 uid다.
- 리디렉트 허용 주소(Supabase URL Configuration): Site URL `https://<사이트>.pages.dev/`, Redirect URLs `https://<사이트>.pages.dev/**`, `https://staging.<사이트>.pages.dev/**`.
- 카카오톡 안 브라우저에서는 Google 로그인이 막힌다(구글 정책). 이 환경을 알아보면 Google 버튼 대신 "외부 브라우저로 열어 주세요" 안내.
- [미확인] Supabase 카카오 공급자가 이메일 동의를 기본 요청하는지. 개인 개발자 앱은 이메일 동의를 못 받을 수 있다. 스테이징에서 먼저 확인하고, 막히면 대시보드의 이메일 없는 사용자 허용 옵션 또는 `scopes` 지정으로 푼다. 안 되면 보고.
- 개인정보: auth.users에 공급자가 준 닉네임·(Google은) 이메일이 저장된다. 개인정보 안내(D-57)에 반영 필요(documenter).

## 8. 실시간: 사람 수·홍보(M2-9)
D-79로 Supabase 모드에서도 `Caps.room`·`Caps.lock`을 채운다. 규칙은 D-15(10초 잠금 1명·안내 5초·1인 1분), D-20(1.2K 표기), D-67(누구나=익명 uid 포함).
### 8-1. 구성 요약
- 채널 하나 `gn:site`(**private**). Presence = 사람 수, 홍보 수신 = 같은 채널의 Broadcast. 지역별 채널은 만들지 않는다(100명 규모엔 하나로 충분, 연결 1개).
- 사람 수: 각 탭이 `track({ r: 'r:<지역코드>' })`. 키는 탭마다 임의 id(`room.id`). **uid·닉네임은 Presence에 넣지 않는다**(모든 접속자에게 보이므로).
- 홍보: 클라이언트는 Broadcast를 **보낼 수 없다**. `rpc('promo_claim')`이 서버 시각·행 잠금으로 판정하고, 이긴 경우에만 DB 안에서 `realtime.send`로 `gn:site`에 내보낸다.
- 게시판 등은 여전히 60초 읽기(0장). Postgres Changes는 쓰지 않는다.
### 8-2. 잠금 방식 비교 → DB 함수 권장
| | A. DB 함수 `promo_claim`(권장) | B. 클라이언트 Broadcast(+Presence로 선착순) |
|---|---|---|
| 경합 | `select … for update` 한 행, `now()` 기준이라 동시에 눌러도 1명 | 망 지연 동안 둘 다 이겼다고 볼 수 있음, 기기 시각 차이 영향 |
| 쿨다운·도배 | 서버가 uid로 셈(지워도 남는 기록) | localStorage라 지우면 우회 |
| 문구 위조 | 서버가 검사한 값만 나감 | 누구나 임의 문구·사진을 사이트 전체에 보낼 수 있음 |
| 비용 | RPC 1회 + 메시지 1×수신자 | 메시지 1×수신자(비슷) |
| 작업량 | SQL 함수 1개 + 정책 | 판정 규칙을 클라이언트마다 맞춰야 함 |
### 8-3. 홍보 문구(코드 확인 결과)
- `ui/together.js` `Promo.press`: 본문 "구경 오세요!"는 **고정 문구**. 단 데이터 `{code, name(고양이 이름), where(지역 이름), thumb(160px JPEG data URL 약 10KB), at}`는 보내는 쪽이 만든다. 받는 쪽은 code를 `REGIONS.unitOf`로 검사, name·where 20자 자르기, thumb는 `data:image/jpeg` 접두만 검사.
- 서버 판정 대상: `code`(지역 코드 형식, 길이 제한), `name`(1~20자 + `gn_text_check('name', …)`로 D-74 필터 재사용). 고양이 이름은 이미 필터된 이름이지만 위조 가능하므로 다시 검사한다.
- `where`는 보내지 않는다. 받는 쪽이 code로 자기 `REGIONS`에서 이름을 찾는다(위조 불가).
- `thumb`: 권장은 **Supabase 모드에서 빼기**(임의 그림을 사이트 전체에 5초 띄울 수 있고 신고 경로가 없음). 화면은 이미 thumb 없으면 그림 없이 그린다. 대안은 팀장 확인(보고 참조).
- `at`은 서버 시각(ms)으로 바꿔 넣는다.
### 8-4. SQL `supabase/sql/08_realtime.sql` (01~07 뒤, 05의 `gn_text_check`·01의 `is_admin`·`app_config` 필요)
```sql
create table public.promo_state (id int primary key check (id = 1), holder uuid, until timestamptz not null default 'epoch');
insert into public.promo_state values (1, null, 'epoch');                 -- RLS 켬, 정책 없음(함수만 씀)
create table public.promo_log (id bigint generated always as identity primary key,
  uid uuid not null references auth.users on delete cascade, ok boolean not null, created_at timestamptz not null default now());
create index on public.promo_log (uid, created_at); create index on public.promo_log (created_at);   -- RLS 켬, 정책 없음
create table public.promo_block (uid uuid primary key references auth.users on delete cascade, until timestamptz not null); -- RLS 켬, 정책 없음
-- app_config.limits.promo 초깃값: {"lock_s":10,"gap_s":60,"per10m":5,"per1h":15,"site1h":60,"abuse10m":30,"block_h":24}
create function public.promo_claim(p_code text, p_name text) returns jsonb  -- security definer, set search_path = ''
-- 1 auth.uid() 없음 → {ok:false,code:'auth'}            2 promo_block.until > now() → 'blocked'
-- 3 시도(ok 무관) 10분 > abuse10m → promo_block에 block_h 시간 insert → 'blocked'
-- 4 code 형식·name 길이·gn_text_check 실패 → 'bad_text'(예외는 함수 안에서 잡아 기록 후 반환)
-- 5 is_admin() 아니면: 마지막 ok가 gap_s 안·10분 per10m·1시간 per1h 넘음 → 'rate_limit'
-- 6 사이트 전체 1시간 ok ≥ site1h → 'busy'
-- 7 promo_state id=1 for update; until > now() → 'busy'
-- 8 until = now()+lock_s, holder = uid; realtime.send(jsonb{code,name,at}, 'promo', 'gn:site', true) → {ok:true}
-- 모든 갈래에서 promo_log에 (uid, ok) 1행. 1% 확률로 2일 지난 promo_log·지난 promo_block 삭제(별도 cron 없음)
create function public.promo_clear() returns void   -- is_admin()만: promo_state.until = 'epoch', 내 promo_log 삭제
-- 실행 권한: promo_claim·promo_clear는 authenticated에만 grant, anon·public revoke
-- realtime.messages 정책(private 채널 인가)
create policy gn_site_read on realtime.messages for select to authenticated using (realtime.topic() = 'gn:site');
create policy gn_site_presence on realtime.messages for insert to authenticated
  with check (realtime.topic() = 'gn:site' and extension = 'presence');   -- broadcast insert 정책 없음 = 클라이언트 송신 거부
```
- **거부를 `raise`가 아니라 jsonb로 돌려준다**: 예외면 트랜잭션이 되돌려져 `promo_log`가 남지 않아 도배 셈이 안 된다.
- 익명 사용자도 `authenticated` 역할이다(배포_계획 1-4). [미확인] `realtime.send`·`realtime.topic()`·`extension` 열 이름과 무료 요금제 사용 가능 여부 → 스테이징에서 먼저 확인.
- `99_rollback`에 위 정책 2개·함수 2개·표 3개 삭제를 앞쪽(역순)에 추가. 탈퇴(07)는 `on delete cascade`로 따라 지워진다.
### 8-5. 어댑터 인터페이스 (화면 변경 최소, LocalMock과 같은 모양)
```js
// createSupabaseCaps(client, cfg) → { user, db, room, lock }. 채널은 room이 만들고 lock은 rpc만 쓴다.
// room: { id, live, join(name), count(name='현재'|'*'), onCount(f), send(kind, data), on(f) }
//   live: 'SUBSCRIBED'일 때 true. CHANNEL_ERROR·TIMED_OUT·CLOSED면 false + onCount 알림(supabase-js 자동 재연결에 맡김)
//   count(n): presenceState()에서 키별 마지막 meta.r === n 인 수(나 포함). count('*') = 전체 키 수(사이트 전체)
//   send(): Supabase 모드에서는 아무것도 안 함(서버만 보냄). on(f): broadcast 'promo' 수신 → f('promo', payload)
// lock: { acquire(key, { holder, ttlMs, data }) → Promise<boolean>, peek() → null, clear(key) }
//   acquire('promo'): rpc promo_claim(data.code, data.name). ok → true, 'busy' → false, 그 밖은 Error(code) 던짐
//   (code: rate_limit·blocked·bad_text·auth·network). ttlMs는 무시(서버 값). clear → rpc promo_clear
```
- 화면 쪽 변경(`ui/together.js`): `acquire`에 `data`를 넘기고, 던진 오류를 문구로 바꾼다. LocalMock은 `data`를 무시하므로 지금 흐름 그대로.
- 보이는 동안만 접속: 탭이 60초 넘게 숨겨지면 `untrack`+채널 해제, 다시 보이면 재가입(동시 연결·메시지 절약, "지금 보는 사람" 뜻에도 맞음).
- 오류 문구(3-6에 추가): busy "지금은 다른 동네 홍보가 나가는 중이라 이번엔 묻혔어요"(지금 문구), rate_limit "홍보는 1분에 한 번만 할 수 있어요", blocked "홍보를 너무 자주 눌러서 잠시 쉬어요", bad_text "이 이름으로는 홍보할 수 없어요", network "연결이 끊겨 홍보를 보내지 못했어요".
### 8-6. 연결 실패 시
- 첫 구독이 10초 안에 `SUBSCRIBED`가 안 되거나 `live=false`인 동안: 사람 수 칸(`#viewers`) 숨김, 홍보 버튼 `disabled` + title "지금은 홍보를 보낼 수 없어요". 다시 `SUBSCRIBED`면 되살림.
- DB(5-2 체험 모드)로 떨어진 경우는 지금처럼 LocalMock(로컬) 또는 room·lock null(배포 주소). 배포 주소 정적 모드의 표시(사람 수 1)는 바꾸지 않는다.
- 어드민 가짜 사람 수(`Live.fake`)는 live와 무관하게 그대로 보인다.
### 8-7. 무료 한도 계산 (D-41: 30일 100명) — 한도 값은 모두 [미확인], 스테이징 대시보드에서 확인
| 항목 | 무료 한도(알려진 값) | 예상 사용 |
|---|---|---|
| 동시 연결 | 200 | 정점 20 가정(숨긴 탭 해제 포함) → 10% |
| 메시지/월 | 200만 | 아래 합 약 14만 → 7% |
| 초당 메시지 | 100 | 정점 Presence 변경 1~2회×20명 → 40 미만 |
| 메시지 크기 | 256KB | 홍보 1건 수백 바이트(thumb 빼면) |
- 가정: 방문 1,000회(100명×10회), 방문당 Presence 변경 6회(입장·지역 이동 4·퇴장), 수신자 정점 20명으로 크게 잡음.

- 최악(도배): `site1h` 60 → 월 43,200건×20 = 86만. 정상분을 더해도 100만 남짓으로 한도 안. 넘을 기미면 어드민이 `site1h`를 줄인다(코드 변경 없음).
- [미확인] 하트비트·join 응답이 메시지 수에 들어가는지. 들어가도 30초 간격×20명×월 정점 시간 수준이라 여유.

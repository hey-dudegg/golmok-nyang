# 2차 배포 실행 순서 (M2-2, 사용자용)

대상: 계정 주인(사용자). 근거: D-08·45·54·55·62·63·81, 배포_계획.md 0-4. 화면·버튼 이름은 Cloudflare가 바꿀 수 있어 **[미확인]** 표기(비슷한 이름을 찾아 진행). 키·비밀번호는 **대시보드 화면에만** 입력하고 채팅·저장소·파일에 붙이지 않는다.
공식 문서를 이번에 열람하지 못했다. 아래 동작은 알려진 Cloudflare Pages 동작에 근거한 것이며 첫 배포 때 눈으로 확인한다.

## 0. 시작 전 (코드 쪽, 팀장·developer가 먼저)
1. `prototype/_headers` CSP의 `connect-src`에 Supabase 두 프로젝트(https·wss)를 더한다. 안 하면 배포 후 연결이 브라우저에서 막힌다 (점검 보고 2번).
2. `/secure-check` 통과 후 커밋·푸시 승인(공개 저장소, 비밀값 없음 확인).
3. `test` 브랜치를 main에서 만들어 푸시한다(승인 뒤 팀장 또는 사용자).

## 1. Pages 프로젝트 만들기 (한 번만)
1. Cloudflare 대시보드 로그인, 2단계 인증 켜짐 확인. 결제 수단은 등록하지 않는다(D-01).
2. 왼쪽 메뉴 Workers & Pages [미확인] → 만들기(Create) → Pages 탭 → Connect to Git [미확인].
3. GitHub 연결 허용(저장소 하나만 선택 권장) → 이 저장소 선택.
4. 프로젝트 이름: `golmok-nyang` (이 이름이 주소 `golmok-nyang.pages.dev`가 됨. 이미 쓰이면 뒤에 글자가 붙으니 그때 알려 주기).
5. Production branch: `main`.
6. 빌드 설정: Framework preset `None`, Build command 비움, **Build output directory `prototype`**, Root directory(고급) 비움(저장소 루트). Root directory를 `prototype`으로 바꾸지 말 것: `functions/`가 저장소 루트에 있어 의견 중계가 빠진다.
7. 환경 변수는 이 화면에서 넣지 않고 3장에서 넣는다. Save and Deploy.
8. 첫 배포가 끝나면 `https://golmok-nyang.pages.dev`를 시크릿 창으로 열어 배포_계획.md C-11을 확인한다(로딩 완료, 콘솔 오류 없음, regions.json 200).

## 2. test 브랜치 미리보기 주소
1. 프로젝트 → Settings → Builds & deployments [미확인] → Branch control(미리보기 브랜치)이 "모든 비운영 브랜치(All non-production branches)"인지 확인.
2. `test` 브랜치를 푸시하면 미리보기 배포가 생기고 별칭 `https://test.golmok-nyang.pages.dev`가 붙는 것이 기본 동작이다 [미확인: 첫 배포 때 Deployments 화면의 Branch URL로 확인].
3. 미리보기마다 붙는 해시 주소(`<해시>.golmok-nyang.pages.dev`)는 `config.js` 호스트 목록에 없어 Supabase에 연결되지 않고 모의로 동작한다(정상). 시험은 항상 test 별칭 주소로 한다.
4. 미리보기 주소가 외부에 공개되는지(Cloudflare Access 보호 여부) [미확인]. 테스트 주소를 공유할 때는 noindex가 걸려 있으나 링크를 아는 사람은 열 수 있다는 점을 인지.

## 3. 환경 변수 (의견 보내기 중계, D-54·62)
1. Web3Forms 가입은 이미 했다면 건너뜀. 접근 키는 Web3Forms 화면에서만 복사.
2. 프로젝트 → Settings → Variables and Secrets (또는 Environment variables) [미확인].
3. **Production**과 **Preview** 두 환경에 각각 `WEB3FORMS_ACCESS_KEY` 를 입력한다. 형태는 암호화(Secret) 권장 [미확인: 화면 선택지]. 미리보기는 별도 설정이라 운영에만 넣으면 test 주소에서 의견 보내기가 `config` 오류(503)가 난다 [미확인: 두 환경 분리는 알려진 동작].
4. 변수를 추가·수정한 뒤에는 **새 배포가 있어야 반영**된다. Deployments에서 최신 배포를 재배포(Retry/Redeploy) [미확인] 하거나 빈 커밋을 푸시.
5. 확인: 각 주소에서 의견 보내기를 1회 보내 메일 도착 확인. 실패 시 브라우저 응답 코드(503=변수 없음, 403=origin, 429=횟수)를 알려 주기.

## 4. Web Analytics (D-55)
1. 프로젝트 → Metrics 또는 Web Analytics [미확인] → 활성화(Enable). 켜면 Cloudflare가 스크립트를 자동으로 넣는다.
2. 켠 뒤 시크릿 창에서 콘솔을 열어 CSP 위반 메시지가 없는지 확인하고 있으면 그대로 알려 주기(_headers는 `static.cloudflareinsights.com`·`cloudflareinsights.com`만 허용).

## 5. Supabase 쪽 (이미 완료: D-81, 테스트·운영 SQL 실행)
- 사이트가 뜬 뒤 어드민 등록(D-86)을 한다. 익명 세션이 기기별이므로 등록할 **기기·브라우저에서** 운영 주소를 열어 진행.
- Supabase 대시보드 Authentication 설정에서 익명 로그인(Anonymous sign-ins) 켜짐 확인 [미확인: 화면 이름].
- 소셜 로그인은 보류(D-82)라 카카오 리다이렉트 설정은 지금 하지 않는다.

## 6. 정리 작업 (D-87)
- DB 정리는 pg_cron(Supabase 안)이 한다. GitHub Actions는 하루 1회 요청만(D-09). 실제 워크플로 추가는 별도 작업.

## 7. 롤백
- Pages 프로젝트 → Deployments → 이전 배포 선택 → Rollback to this deployment [미확인]. 또는 문제 커밋을 되돌리는 커밋 푸시.
- 공개 중지: 프로젝트 삭제는 되돌릴 수 없으니 먼저 알려 주기.

## 8. 끝난 뒤 사용자가 알려 줄 것
최종 주소 두 개(운영·test 별칭), C-11 확인 결과, 두 주소의 의견 보내기 결과, 콘솔의 CSP 위반 문구(있다면).

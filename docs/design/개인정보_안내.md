## 1. 1차 짧은 고지
- 긴 것(첫 방문 알림줄): "골목냥은 기록을 이 기기(브라우저)에만 저장하고 서버로 보내지 않아요. [개인정보 안내]"
- 짧은 것(의견 보내기 팝업 맨 아래): "이 기기에만 저장돼요 · [개인정보 안내]"

의견 보내기 팝업에는 전송 상태에 따라 한 줄을 더한다(`PRIVACY_FEEDBACK`).
- 접근 키가 없을 때(모의): "지금은 시험 중이라 의견이 운영자에게 전달되지 않을 수 있어요." (D-54 반영)
- 접근 키가 있을 때(전송): "보낸 의견은 전송 서비스(Web3Forms)를 거쳐 운영자에게 전달돼요. 연락처는 적지 마세요." (D-54 반영)

## 2. 1차 안내 본문
팝업 제목: **개인정보 안내**. 맨 위에 "마지막 수정: YYYY-MM-DD"(코드 상수 `PRIVACY_VERSION`).

**① 무엇을 어디에 저장하나요**
- 골목냥은 이름, 연락처, 생년월일, 위치(GPS)를 묻지 않아요.
- 이웃 등록 정보, 고양이와 친해진 정도, 게시판 글, 이름 투표, 쓰던 의견 같은 기록은
  **지금 쓰는 이 기기의 브라우저(localStorage)에만** 저장돼요.
- 다른 브라우저나 시크릿 창, 다른 사람에게는 보이지 않아요. (게시판 글도 지금은 이 기기에서만 보여요.)

**② 밖으로 보내는 것이 있나요**
- 이 기기에 저장한 기록을 서버나 다른 회사로 보내지 않아요.
- 화면에 필요한 파일(글꼴, 3D 그림 도구, 지도 자료)도 모두 골목냥 사이트 안에서 받아와요. 글꼴 서버 같은 다른 회사 서버에 접속하지 않아요.
- 의견 보내기로 보낸 글만 전송 서비스(Web3Forms)를 거쳐 운영자에게 전달돼요. 그 밖의 글은 보내지 않아요. (D-54 반영)
- 광고, 추적 쿠키, 위치 수집을 쓰지 않아요.

**③ 사이트 접속 기록**
- 골목냥은 Cloudflare라는 호스팅 회사에 올려 두었어요. 페이지를 열면 Cloudflare가 보안과 운영을 위해
  접속한 인터넷 주소(IP), 브라우저 종류, 요청 시각을 기술적으로 처리해요. 운영자는 이것으로 누구인지 찾지 않아요.
- 방문 수를 세기 위해 쿠키 없는 방문 통계(Cloudflare Web Analytics)를 써요. 누구인지 알 수 없는 형태예요. (D-55 반영)

**④ 운영자에게 연락하기**
- 궁금한 점이나 삭제 요청은 화면 위쪽 **"의견 보내기"**로 보내 주세요. 연락처는 적지 않아도 돼요. (D-48)

**⑤ 저장한 기록 지우기**
- 브라우저 설정 → 사이트 데이터(쿠키 및 사이트 데이터) → 골목냥 주소를 찾아 삭제하면 모두 지워져요. 지운 기록은 되살릴 수 없어요.
- 화면 안 지우기 버튼은 두지 않는다(D-56 반영).

**⑥ 바뀌면 알려요**
- 안내가 바뀌면 "마지막 수정" 날짜를 바꾸고, 첫 화면 알림줄을 다시 한 번 보여 드려요.

## 4. 화면 설계와 파일
**4-1. 여는 곳**
| 곳 | 형태 | 시점 |
|---|---|---|
| 첫 방문 알림줄 | 화면 아래 가운데 작은 띠(긴 고지 + [개인정보 안내] + [알겠어요]) | 1차. `store`의 `privacy_seen` ≠ 현재 버전일 때만 |
| 의견 보내기 팝업 맨 아래 | 짧은 고지 한 줄 + 링크 | 1차 |
| 가입 시트(signup) | 3-6 요약 + 링크 + 만 14세 체크 | 2차 |
| `prototype/privacy.html` | 같은 본문의 정적 페이지 | 2차(로그인 설정에 안내 주소가 필요할 수 있음) [사용자 확인] |
- 알림줄은 아래 왼쪽 `#roster`, 아래 오른쪽 `#share`와 겹치지 않게 그 위(bottom 약 76px), 좁은 화면은 전체 폭.
  [알겠어요] 뒤로는 안 뜬다. 항상 떠 있는 바닥글은 두지 않는다(화면이 좁고 단순하게).

**4-2. 형태**: 1차는 **팝업(scrim)**. 별도 페이지는 3D 장면을 다시 불러야 하고, 팝업 틀이 이미 있다.
- `ui/dom.js`의 `openScrim(content, { center: true })`와 `h()` 재사용(닫기·Esc·바깥 누르기·포커스 포함).
- 의견 팝업의 시트 클래스를 재사용, 본문은 스크롤. 글은 모두 `h()`의 text로(innerHTML 금지, A-4).
- ④의 "의견 보내기"는 버튼: 안내를 닫고 `openFeedback(app)`을 연다. 의견 팝업에서 안내를 열어도 쓰던 글은 기존 `draft`에 남는다.

**4-3. 파일** (층: core ← adapters ← state ← render·sim ← ui ← app·main)
| 파일 | 층 | 내용 |
|---|---|---|
| `src/core/privacy_text.js` (새) | core | 문안 데이터만: `PRIVACY_VERSION`, `PRIVACY_NOTICE`({long, short, link, ok}), `PRIVACY_FEEDBACK`({live, mock}), `PRIVACY_SECTIONS`(①~⑥: {id, title, lines[]}). 2차 문안은 2차 때 추가 |
| `src/ui/privacy.js` (새) | ui | `openPrivacy(app, {opener})`→close, `showPrivacyBanner(app)`(본 버전이면 무시). core·adapters/store·ui/dom·ui/feedback import |
| `src/ui/feedback.js` (고침) | ui | 맨 아래 고지 줄 + 링크. privacy.js를 import하면 순환이 되므로 **`app.openPrivacy()` 호출**(main이 붙임) |
| `src/main.js` (고침) | main | `app.openPrivacy = (o) => openPrivacy(app, o)`, 시작 때 `showPrivacyBanner(app)` |
| `prototype/style.css` (고침) | - | 알림줄·본문 스타일 몇 줄 |
| `prototype/privacy.html` (2차, 새) | - | `privacy_text.js`만 import해 본문 출력. three 불러오지 않음 |
- `PRIVACY_FEEDBACK`의 키 `live`는 "전송 상태 문구"의 이름일 뿐 config 항목이 아니다(config의 `live` 항목은 D-54로 없음).

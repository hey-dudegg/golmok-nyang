## 13. 뒷걸음질 back_off (M19-6, 교감)
특징: ① 사용자를 마주 본 채 뒤로 물러난다 ② 몸을 낮추고 귀를 젖힌다 ③ 짧은 보폭으로 살살.
원인: 시퀀스·엔진. STEP.walk가 yawTarget을 이동 방향으로 돌려 등을 보이고 걸어간다. crab(yaw 고정)은 있으나 다리 위상이 앞으로만 돈다.

**E4 뒷걸음 옵션** (sim/agent.js 이동부, M19-2에 배정)
- moveTo opts `back: true` = crab처럼 yaw 고정 + `this.gait -= …`(다리 위상 역방향). opts `stride: 0.6` = 보폭 배수(기본 1).
- STEP.walk(x, z, speed, { back: true, stride: 0.6, keepPose: true })로 쓴다. keepPose로 걷기 자세(stand) 덮어쓰기를 막는다.

| 시각 | 자세 키 | plant | h | ov |
|---|---|---|---|---|
| 0.0~0.4 | faceYou 후 crouch + { eL 0.6, eR 0.6, tb −0.1, pupil 0.85 } | all | 기존 | 없음 |
| 0.4~끝 | 같은 자세 유지, 뒤로 0.5~0.7m(사용자 반대), 속도 0.45 | all | 기존 | lookAtYou = 1 내내 |
| 도착 | alert 2.5 { eL 0.4, eR 0.4 } (기존) | sit | 기존 | 없음 |

- 목표점은 기존 식(사용자 반대 방향 ×0.8)을 쓰되 거리 상한 0.7m. 뒤에 벽·오브젝트가 있으면 world.resolve가 멈춘다(timeout 기존).
- 완료 조건: 이동 중 |yaw − 사용자 방향| ≤ 0.15, 몸 이동 방향이 머리 반대, 걸음 위상이 역방향(앞발이 뒤로 딛음).

| 컷 | 시각 | 보여야 할 것 |
|---|---|---|
| V1 | 0.3 | 낮춘 몸, 귀 젖힘, 사용자 응시 |
| V2 | 1.2 | 얼굴은 카메라 쪽, 몸은 뒤로 물러난 위치. 앞발 하나 뒤로 딛는 중 |
| V3 | 도착+0.5 | 멈추고 경계하며 앉음 |

## 14. 교감 발라당 roll_over (M19-6, 교감)
특징: ① 사용자 쪽으로 배를 보이며 옆으로 굴러 눕는다 ② 등을 바닥에 대고 좌우로 비빈다 ③ 앞발 꼼지락, 사용자를 거꾸로 올려다봄.
원인: 자세값·시퀀스. 일상 belly를 그대로 쓴다. 배 방향이 사용자와 무관하고 응시 0.6뿐.

새 자세 `rollYou` (poses.js, 3장 belly 새 값 바탕): `{ ...belly, hr 2.0, cr 0.35, hdr −0.8, hdp −0.25, fle 2.1, fre 2.0, eye 0.7 }`
- 배가 카메라를 향하게: 눕기 전에 STEP.face로 yaw = 사용자 방향 ± π/2(hr 부호와 맞는 쪽). 고르는 쪽은 r.chance(0.5)로 하고 hr·cr·hdr 부호를 함께 뒤집는다.

| 시각 | 자세 키 | plant | h | ov |
|---|---|---|---|---|
| 0.0 | 걷기 nearYou(0.6) (기존) | all | 기존 | 없음 |
| 도착 | face(사용자 ± π/2) → loaf 0.8 (E1) | none | 기존 | 없음 |
| +0.8~+2.2 | rollYou로 굴러 눕기(단계 분할) | none | 기존 | lookAtYou 1 |
| +2.2~+6.7 | rollYou 유지 4.5초 | none | 기존 | 비비기(period 1.4): hr 0→+0.3(0.35)→−0.3(1.05)→0, cy 0.15 같은 위상. 꼼지락: fle·fre = 0.25·sin(t·7), 좌우 위상 π |
| 끝 | loaf 1.2 (기존) | none | 기존 | 없음 |

- 엔진: E1, E2. 새 자세 1개. 일상 belly(3장)와는 배 방향·응시·비비기 폭(0.3 대 0.22)·앞발 꼼지락으로 구분한다.
- 완료 조건: 유지 중 배 법선(가슴 y축 반대)이 카메라 쪽 수평 성분 > 0, 등 접지 조건은 3장과 같음.

| 컷 | 시각 | 보여야 할 것 |
|---|---|---|
| O1 | +1.5 | 사용자 쪽으로 굴러 눕는 중 |
| O2 | +2.6 | 배가 카메라 쪽, 머리 거꾸로 사용자 응시 |
| O3 | +2.55·+3.25 2장 | 좌우로 비빈 두 순간 비교 |

## 16. M21-3 큰 눕기→앉기 되내림 (R-25, 2026-11-23)
측정 정의(tests/lib/shoot_action.js 67·79줄): H = minPart[0] + hFinal(엉덩이 부위 최저 피부의 바닥 위 높이), 되내림 = max(누적 최대 − H).
원인(코드 근거)
1. plant 'none'이면 h는 높이를 정하지 않는다. cat_model.js 353줄 shift = −GROUND_SINK − lowest(): 몸 전체 최저점을 바닥에 맞춘다.
   그래서 H = 엉덩이 바닥 − 몸 전체 최저점이고, pose_plan 30·58줄의 h 보간은 결과에 영향이 없다.
2. 시작 side·sun은 엉덩이가 바닥에 닿아 H≈0, 끝 sit도 solveSit(325~337줄)가 엉덩이를 앞발 바닥에 맞춰 H≈0이다.
   시작과 끝이 둘 다 0이라 중간에 H가 조금만 떠도 그만큼 되내림이 된다(belly→stand는 끝 H가 가장 커서 단조).
3. planRise 접은 단계 at(tm)(side: d=1.42, tm=0.366, n=1)은 다리 10키를 TUCK(뒷다리 hls −1.55·hlk 2.7로 배 밑에 접음)으로 두고
   hr을 1.42→0.9로 돌리지만 hp는 0→−0.23만 움직인다. 반쯤(약 52도) 굴렀을 때 배 밑에 접힌 아래쪽 다리 뭉치가 엉덩이 바닥보다
   낮아져 최저점이 되고, 1의 규칙이 그 점을 바닥에 맞추므로 엉덩이가 뜬다(0.05m). 이어서 sit로 가며 엉덩이가 다시 깔려 내려간다.
   착수 전 확인(developer): 접고 구르는 단계 최저 부위 = knR(무릎). 원인 3 확인됨.
단조 조건: 단계 정지 자세 T_k의 H(T_k)가 k에 대해 줄지 않아야 하고, 끝 H가 최대여야 한다. sit 목표는 끝 H≈0이므로
   모든 k에서 H(T_k) ≤ ε(0.01m), 즉 "끝까지 엉덩이가 최저점". 그러려면 (a) 다리가 엉덩이 바닥 아래로 나오지 않고 (b) 엉덩이 쪽이 먼저 기울어 있어야 한다.

해결안 A(추천): planRise에 앉기 목표 분기 "엉덩이 축 일어나기". to.plant === 'sit'일 때만 쓴다.
- 다리값 L = 앞다리 5키(fls·fle·frs·fre·fsp)는 TUCK, 뒷다리 HIND_KEYS + hsp는 to 값(앉은 허벅지, 엉덩이 옆에 접힘).
- 단계 0(plant none, hold FOLD_HOLD): 굴리지 않는다. 몸·hp는 from 그대로, 다리만 L로 접는다.
- 단계 1..n(plant none): 지금 at(t)와 같되 TUCK 대신 L, hp = from.hp 고정, 나머지 몸·목·머리·꼬리만 mix(from, to, t), t ≤ tm.
  (처음 설계의 hp = to.hp는 꼬리 끝 t7이 −0.16m로 최저점이 되어 되내림 0.145로 악화 → 폐기, from.hp로 확정.)
- 그 뒤는 지금처럼 planSink(앞다리 펴기·남은 회전). planSink는 식빵→sit에서 합격한 경로이고, 뒷다리가 이미 to 값이라
  46줄(from.plant==='sit'일 때 뒷다리 고정)과 같은 효과가 난다.
```
// 인터페이스 예시 (구현 아님)
const sitT = to.plant === 'sit';
const L = sitT ? { ...pick(TUCK, FRONT_KEYS), ...pick(to, [...HIND_KEYS, 'hsp']) } : TUCK;
const pre = sitT ? [{ T: { ...from, ...L, plant: 'none' }, hold: FOLD_HOLD }] : [];
at(t): s = { ...to, ...L, plant: 'none' }; L·(sitT ? hp) 를 뺀 숫자 키만 mix(from, to, t); sitT 면 s.hp = from.hp
return pre.concat(접은 단계들, planSink(마지막 접은 단계, to, ...))
```
대안 B(A가 측정에서 실패하면): sit 목표는 접은 단계 없이 planSink로 바로 가고, 그 중간 단계 plant를 'min' 대신 'sit'로 둔다
  (solveSit가 엉덩이를 앞발 바닥 밑으로 못 내려가게 잡아 줌). 단점: M21-2 이전처럼 다리가 펴진 채 몸이 도는 모습이 다시 보일 수 있다.
영향 범위: planRise 안쪽만. stand 목표(belly→stand), planSink(식빵→sit), 눕기 쪽(planPose 21~34줄)은 그대로.
완료 조건
- 판정 되내림 = 최대되내림 − max(0, H시작 − H끝) ≤ 0.02m(팀장 결정). side 정지 H 0.031·sit H≈0.003이라 최대되내림 ≤0.01은 불가. (M21 측정: side 0.010·sun 0.011·belly→stand 0.011·식빵→sit 0.015, 모두 합격)
- side→sit, sun→sit 판정 되내림 ≤ 0.02(측정 최대되내림 side 0.026(수정 전 0.048), sun 0.018), minPart ≥ −GROUND_SINK. (M21 측정: side 0.010·sun 0.011·belly→stand 0.011·식빵→sit 0.015, 모두 합격)
- belly→stand·식빵→sit 기존 합격 유지, 회귀 19/19, 사진에서 다리가 바닥을 뚫거나 엉덩이가 공중에 뜨지 않음.

## 0. 한눈에
| 항목 | 내용 |
|---|---|
| 무엇 | 공원·주택가 골목의 길고양이 쉼터형 캣타워: 바닥 숨는 칸(집) + 칸 지붕 = 중단 + 기둥 위 상단 판 |

| 결정성 | 별도 난수 `props:tower:`+code, 기존 차·담·상자 배치는 한 칸도 안 바뀜(맨 마지막에 놓음) |

## 1. 장면·모양·크기·지점

### 1.1 장면 (현실성)
| 테마 | 확률 | 근거 |
|---|---|---|
| park(공원) | 70% | 공원 구석 길고양이 쉼터·급식소 옆 캣타워가 가장 흔한 실제 모습 |
| alley(골목) | 25%, **차가 없을 때만** | 주택가 담 밑 쉼터. 차와 같이 두면 뒷줄이 꽉 참(담과 같은 이유) |
| market(시장) | 0 | 가판·스툴이 뒷줄을 차지, 상인 구역이라 비현실적 |

### 1.2 모양 (코드 도형, 앞(+z)이 카메라 쪽)
- 칸(den): 바닥에 놓인 나무 상자 0.55 x 0.42 x 0.34(로컬 x -0.20 중심). 앞면에 입구(폭 0.22 x 높이 0.22, 둥근 위 모서리 대신 각진 틀). 안쪽 어두운 색.
- 중단(mid): 칸 지붕 = 판 0.60 x 0.46 x 0.03, 윗면 y 0.36. 가장자리에 낮은 턱 없음.
- 기둥: 원기둥 지름 0.10, 높이 0.72, 로컬 x +0.25, z -0.05. 삼줄 감은 질감(줄무늬 캔버스).
- 상단(top): 판 0.42 x 0.38 x 0.03, 윗면 y 0.72, 중심 x +0.25. 중단과 x로 엇갈려 hop 길이 확보.
- 받침: 기둥 아래 작은 판 0.30 x 0.30 x 0.03 (고양이 서는 면 아님).
- 외곽 풋프린트: l 0.95 x w 0.46 x h 0.75 (`hx` 0.475, `hz` 0.23).

### 1.3 지점
| id | mode | action | pos | y | poses | 기타 |
|---|---|---|---|---|---|---|
| den | in | towerDen | [-0.20, -0.04] | 0 | loaf, hideLow, peek | rest 'loaf', clear 0.30, shade 0.7, warm 0.6, tag hide, approach [-0.20, 0.40] |
| mid | on | towerLie | [-0.20, 0] | 0.36 | lie | inset 0.10, shade 0, warm 0.6, tag rest, shadowMax 0.22, approach [-0.20, 0.40] |
| top | on | towerLookout | [0.25, 0] | 0.72 | sit, lie | via ['mid'], inset 0.08, warm 0.5, tag perch, shadowMax 0.18, approach [-0.20, 0.40] |

세 지점의 접근점은 한 곳(칸 입구 앞 0.17m)이다. 경로가 한 줄이라 막힘 판정·시험이 단순하다.

```js
// 인터페이스 예시 (구현 아님)
PROP_KINDS.tower = { label: '캣타워', size: { l: 0.95, w: 0.46, h: 0.75 }, hx: 0.475, hz: 0.23, themes: ['park', 'alley'], slots: [ /* 1.3 표 */ ] };
```
`PROP_ACTION_KEYS`에 세 키 추가. `footOf('tower')`는 기존 식 그대로 `PROP_KINDS.tower`를 돌려준다(giftSpot이 자동으로 피함).

## 2. 배치 규칙 (layoutFor 확장)
| 규칙 | 내용 |
|---|---|
| 순서 | 차 -> 담 -> 상자 -> **캣타워**(맨 끝). 기존 세 종류 배치·난수가 그대로라 기준값 불변 |
| 난수 | `makeRng('props:tower:' + code)`, force는 기존과 같은 모양(`force.tower = {x,z}`면 그 자리, 차 고정 시험은 놓지 않음) |
| 개수 | 0~1. 공원 r() < 0.7, 골목 r() < 0.25 이고 cars.length 0 |
| 자리 | z -1.3~-0.7(뒷줄), x 는 화면 x -1.6~1.6 안. 공원은 담 중심과 반대쪽 반을 먼저 시도 |
| 겹침 | 기존 `nearestFree`(격자 0.05) + `OBJ_GAP` 0.15. 장애물 = 입력 obstacles + 차·담·상자 풋프린트 |
| 접근점 보호 | 담 wallLoaf 접근점·상자 in 접근점에 반경 `TOWER_KEEP` 0.2 원 장애물. 캣타워 자신의 접근점도 같은 반경 안에 다른 것이 없어야 함(`isFree` 점 검사), BOUNDS 안 |
| 선물 상자 | `giftSpot`은 props 풋프린트를 이미 피함. 추가로 **tower 접근점 원(0.2)** 만 장애물에 더한다(다른 kind는 그대로라 기존 선물 자리 불변) |
| 사용자 상자 놓기 | 기존 `nearestFree` 밀기에 tower 풋프린트가 들어가므로 변경 없음 |
| 실패 | 자리 없으면 건너뜀(0개). 세 행동은 avail 0 -> 기존과 동일 |

통로 0.5m 규칙(2.3)은 캣타워 접근점 쪽(+z)만 검사한다. 뒤·옆은 고양이가 지나갈 필요가 없다.

## 3. 행동

### 3.1 오르기·내리기 (4장 hop 재사용)
| 항목 | 설계 |
|---|---|
| mid 오르기 | 접근점 -> crouch 0.4s -> hop(0 -> 0.36) -> 착지 crouch 0.3s. 기존 `STEP.mount` 그대로 |
| top 오르기 | `via ['mid']`: mid 착지 -> 멈춤 0.3~0.6s(고개 위로) -> hop(0.36 -> 0.72, 수평 0.45) -> 착지. 단 사이마다 crouch-호-착지 |
| 사슬 구현 | `STEP.mount`가 `slot.via`를 보고 hop 단계를 줄 세운다(경로 = [ground, ...via, slot]). via 지점은 claim하지 않지만 **비어 있어야** 함 |
| 내리기 | 역순 top -> mid -> ground. mid가 다른 고양이로 차 있으면 top -> ground 한 번 hop(0.72 <= 담 0.80, 성체 한 번 도약 범위) |
| 빠른 내리기 | `dismountFast`: top도 한 번 hop(0.25s)으로 접근점 착지. 호 생략 없음(4A-1) |
| 칸 들어가기 | 접근점에서 낮은 걸음으로 입구 통과, `a.layer = 'in'`(tower 풋프린트만 무시). 나올 때 역순. y 변화 없음 |
| 높이 제한 | 담과 같은 식: `slot.y > 0.35 x scale`이면 새끼 avail 0 -> 새끼는 den만. via 단계도 같은 식으로 검사 |
| 점유 | top 고양이가 있어도 mid·den 사용 가능(cap 1씩). mid 점유 중이면 top avail 0(올라갈 길 없음) |

### 3.2 점수 (기존 척도, `a.p` 기존 키만, 결정적)
| 키 | 라벨 | 단계 | 점수(초안) | EMO_BIAS |
|---|---|---|---|---|
| towerLookout | 캣타워 꼭대기에서 망보는 중 | 두 단 오르기 -> `sit` 15~40초, 6~10초마다 `alert` 두리번 -> 내리기 | `avail*(0.20 + bold*0.5 + curious*0.4 + day*0.3)` | curious +0.6, wary +0.3, calm +0.2, scared -0.8 |
| towerLie | 캣타워에서 엎드린 중 | 오르기 -> `lie` 15~40초 -> 내리기 | `avail*(0.25 + day*0.4 + warm*0.4 + (1-energy)*0.3)` | calm +0.5, happy +0.3, scared -0.7 |
| towerDen | 캣타워 집에 숨은 중 | 들어가기 -> `loaf` 20~60초, 가끔 `peek` -> 나오기 | `avail*(0.15 + (1-bold)*0.6 + (kitten?0.5:0) + (1-day)*0.3)` | scared +0.9, wary +0.6, calm +0.2, playful -0.4 |
`curious`는 wallLoaf가 쓰는 값과 같은 출처를 쓴다(새 성격 값 없음). day·warm·kitten은 결정적(D-19).

### 3.3 반복 억제 (4A-2 + 캣타워 한 줄)
| 규칙 | 내용 |
|---|---|
| 기존 그대로 | 지점 쿨다운 90초, 사슬 반복 (행동,지점) 최근 3개 금지, 5분 2회 mount, 거부 연속 2회 상한 |
| **같은 오브젝트 묶음** | 최근 3개 행동 안에 tower 행동은 1개만(0점 처리). den -> mid -> top 처럼 지점만 바꿔 타워에 머무는 고리를 막음 |
| 시계 일정 | 세계 시계 일정도 같은 규칙을 결정적으로 적용(연속 tower 배정 금지) |
| 그 자리 반응 | top·mid의 쓰다듬기·츄르는 root 고정 미세 동작(4A-2). den은 under/in 규칙(극성 부정 보정 + peek, 끌어내지 않음) |
| 도망 | `flee`는 tag hide 지점으로 den을 자동 후보로 씀(기존 규칙, bold < 0.6). on 지점에서 도망은 빠른 내리기 후 달림 |
| 만남 | 시작 시 `leaveSlot(fast)`, top은 한 번 hop. 이후 쿨다운 |

## 4. 자세
| 쓰는 곳 | 자세 | 확인 |
|---|---|---|
| den | loaf(기본) · hideLow · peek | `prop_pose_h`로 `높이 x scale + 0.02 <= clear 0.30` 보장 |
| mid | lie | 판 0.60 x 0.46 안에 inset 0.10. 꼬리 늘어짐 허용(5.2) |
| top | sit(기본) · lie · alert(미세 두리번) | 판 0.42 x 0.38, sit 발자국이 inset 0.08 안 |
| 단 사이 | 공중 자세는 기존 `stand` + pounce 덧값 | 새 자세 없음 |

새 자세는 만들지 않는다. 구현 중 꼭 필요해지면(예: 상단 가장자리 앞발 늘어뜨림) **D-129 확인판 통과 조건**을 먼저 채운 뒤 팀장 승인: (1) 전환 확인판 페이지에 새 자세 + 들어가고 나오는 전환 등록, (2) 몸 회전이 크면 중간 자세 자동 분할, 회전 속도·각도 한계 시험 PASS, (3) pose_check 5체형 뚫림 0, (4) 사용자 확인판 확인.
sit -> lie, lie -> stand 전환은 D-129로 이미 분할된 전환을 그대로 쓴다.

## 8. 열린 질문과 추천안 (사용자 판단)

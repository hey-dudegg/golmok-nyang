## 2. 표·RLS·저장소
원칙: 모든 표 RLS 켬, 정책 없으면 거부. 서버가 정하는 열(status·nick·created_at·img)은 트리거가 덮어쓴다. 함수는 `security definer` + `set search_path = ''` + 표 이름에 `public.` 접두.
SQL 파일(값 없음, 저장소 `supabase/sql/`): `01_base` `02_members` `03_board` `04_names` `05_moderation` `06_storage` `07_misc` `08_realtime`(8장) `99_rollback`. 금칙어 초기값은 저장소에 넣지 않는다(3-1).

### 2-1. 공통 함수
```sql
create table public.admins (uid uuid primary key references auth.users on delete cascade);  -- 정책 없음
create function public.is_admin() returns boolean ...  -- exists(admins where uid = auth.uid())
create function public.is_anon()  returns boolean ...  -- coalesce((auth.jwt()->>'is_anonymous')::boolean, true)
create function public.is_member() returns boolean ... -- not is_anon() and exists(members where uid = auth.uid())
create table public.app_config (key text primary key, value jsonb not null);  -- 읽기 모두, 쓰기 is_admin()
-- 초깃값: limits(3-3), report_hide {"post":3,"comment":3,"name":3}, terms_ver "2026-10",
--         features {"login":false,"board_write":false,"names_anon":true}      -- D-82~84 스위치
create function public.gn_feature(f text) returns boolean ... -- coalesce((features->>f)::boolean, false). 값이 없으면 꺼짐
create function public.can_post() returns boolean ...  -- gn_feature('board_write') and is_member()
create function public.can_name() returns boolean ...  -- case when gn_feature('names_anon') then auth.uid() is not null
                                                       --      else is_member() end
```
[미확인] 익명 JWT 클레임 이름 `is_anonymous`. 없으면 true(익명 취급)로 기울게 해 안전 쪽으로 실패한다.

**기능 스위치 (D-82~84)**: 권한은 위 두 함수에만 모으고, 정책·트리거·RPC는 `can_post()`·`can_name()`만 부른다.
| 키 | 지금 | 켜면/끄면 | 쓰는 곳 |
|---|---|---|---|
| `login` | false | true면 화면에 로그인 버튼·가입 시트(4장). 서버 권한과는 무관(표시용) | 화면 |
| `board_write` | false | true면 회원이 글·댓글·캡쳐 업로드 가능. false면 트리거가 `feature_off`로 거부 | `can_post()` |
| `names_anon` | true | true면 익명 uid도 이름 제안·투표·신고. **false로 바꾸면 회원 전용(D-49)으로 복귀** | `can_name()` |
- 로그인 재개 = 사용자 할 일 B·C(6장) 뒤 `update app_config set value = '{"login":true,"board_write":true,"names_anon":false}' where key='features'` 한 줄(SQL Editor). 코드 배포 없음.
- 화면은 Supabase 모드에서 시작할 때 `app_config.features`를 한 번 읽어 `Caps.features`로 둔다(못 읽으면 `FEATURES_DEFAULT`). mock·static 모드는 `FEATURES_DEFAULT`. 화면 표시는 편의일 뿐 방어는 서버 함수다.
- `names_anon=false`로 돌려도 익명 시절 이름·투표는 그대로 남는다(삭제하지 않음). 그 uid는 이후 새 제안·투표만 못 한다.

### 2-2. 회원 `members`
```sql
create table public.members (
  uid uuid primary key references auth.users on delete cascade,
  nick text not null check (char_length(nick) between 1 and 12),
  home text check (char_length(home) <= 40),
  age_ok boolean not null check (age_ok),            -- 만 14세 이상 확인(D-52). false는 넣을 수 없음
  terms_ver text not null, agreed_at timestamptz not null default now(),
  joined_at timestamptz not null default now());
-- select: uid = auth.uid() or is_admin()   (남에게 보이는 이름은 posts.nick 복사본만 → 회원 표는 비공개)
-- insert: uid = auth.uid() and not is_anon()         update: uid = auth.uid() (nick·home만, 열 권한으로 제한)
-- 트리거 members_guard: nick 필터(3장), terms_ver가 app_config 값과 다르면 거부
```
- 로그인 보류(D-82) 동안 `members`·`bonds`는 만들어만 두고 비어 있다(익명은 insert 불가).
- `bonds`(uid pk, data jsonb, `pg_column_size(data) <= 16384`): 회원만 본인 읽기·쓰기. **익명 방문자의 교감 기록은 지금처럼 localStorage**(익명 uid는 브라우저를 지우면 사라지므로 DB에 쌓지 않음). 가입 직후 로컬 기록을 한 번 올린다.

### 2-3. 게시판 `posts`·`post_comments`·`post_likes`
```sql
create table public.posts (
  id uuid primary key default gen_random_uuid(),
  uid uuid references auth.users on delete cascade,   -- null = 이전 데이터(D-51)
  legacy_author text, nick text not null,
  body text not null check (char_length(body) between 1 and 500),
  img text,                                            -- 저장소 경로 '<uid>/<id>.webp|jpg', 서버만 채움(2-4)
  status text not null default 'ok' check (status in ('ok','hidden','removed')),
  hidden_at timestamptz, created_at timestamptz not null default now());
create table public.post_comments (
  id uuid primary key default gen_random_uuid(),
  post_id uuid not null references public.posts on delete cascade,
  uid uuid references auth.users on delete cascade, legacy_author text, nick text not null,
  body text not null check (char_length(body) between 1 and 200),
  status text not null default 'ok' check (status in ('ok','hidden','removed')),
  hidden_at timestamptz, created_at timestamptz not null default now());
create table public.post_likes (
  post_id uuid references public.posts on delete cascade,
  uid uuid references auth.users on delete cascade, primary key (post_id, uid));
```
| 표 | select | insert | update | delete |
|---|---|---|---|---|
| posts | `status='ok' or uid=auth.uid() or is_admin()` (누구나 읽기) | `uid=auth.uid() and can_post()` | 없음(RPC만) | `uid=auth.uid() or is_admin()` |
| post_comments | 위와 같고, 부모 글이 보이는 경우만 | `uid=auth.uid() and can_post()` | 없음 | `uid=auth.uid() or is_admin()` |
| post_likes | 모두 | `uid=auth.uid()`(익명 포함, D-67) | 없음 | `uid=auth.uid()` |
- 트리거 `posts_before_insert`: 맨 앞에서 `gn_feature('board_write')`가 false면 `raise exception 'feature_off'`(D-83, 정책 위반보다 먼저 분명한 코드) → `nick`=members.nick, `status`='ok', `img`=null, `created_at`=now(), `hidden_at`=null로 덮어씀 → `gn_text_check('post', body)` → `gn_rate_check('post')`. 댓글도 같다.
- 게시판 잠금(D-83)의 방어는 서버 두 겹: 트리거 `feature_off` + 정책 `can_post()`(회원도 아니라 이중으로 거부). 화면은 `Caps.features.board_write`가 false면 글쓰기 칸·댓글 입력 대신 "준비 중이에요" 문구와 비활성 버튼만 보이고, 캡쳐 첨부 버튼도 숨긴다. 목록·좋아요는 그대로.
- 수정 기능은 없다(쓰기·지우기만). 목록은 `status='ok'` 최신 20개 + `post_likes(uid)`·`post_comments(...)` 함께 읽기(embedded select).

### 2-4. 캡쳐 저장소 (D-75)
"앱이 찍은 캡쳐인지"를 서버가 증명할 방법은 없다. 실현 가능한 수단을 겹쳐 쓴다.
1. 화면: 게시판에 파일 선택(`<input type=file>`)·붙여넣기·끌어놓기 받기가 없다. 그림은 `interact` 캡쳐 함수의 캔버스 결과만 쓴다.
2. 클라이언트 고정 규격: 긴 변 960px 이하로 줄여 WebP(못 만들면 JPEG) 품질 0.8, 120KB 넘으면 품질을 낮춰 재시도, 그래도 넘으면 그림 없이 올림.
3. 버킷 `captures`(공개 읽기): `file_size_limit` 131072바이트, `allowed_mime_types` `image/webp`, `image/jpeg`.
4. 경로·개수 정책(`storage.objects`):
```sql
-- insert: bucket_id='captures' and public.can_post()          -- 게시판 잠금 중엔 업로드도 거부(D-83)
--   and (storage.foldername(name))[1] = auth.uid()::text
--   and exists (select 1 from public.posts p where p.uid = auth.uid() and p.img is null
--               and p.created_at > now() - interval '10 minutes'
--               and storage.filename(name) in (p.id||'.webp', p.id||'.jpg'))   -- 글 1개에 그림 1장, 갓 쓴 글만
-- update: 없음(덮어쓰기 불가)   delete: 폴더 주인 또는 is_admin()   select: 공개 버킷이라 URL 읽기
```
5. 순서: `posts` insert(필터 통과) → 그림 올리기 → RPC `post_attach(post_id)`가 `storage.objects`에 그 경로가 있는지 확인하고 `img`를 채움.
6. 해상도는 서버에서 검사하지 않는다(파일 머리 해석은 DB 함수로 무리). 크기 상한 + 신고(3장)로 막는다.
7. 글 삭제 때 화면이 그림을 먼저 지운다. 남는 고아 파일은 어드민이 대시보드에서 지운다(관리자 키 없이 자동 정리는 하지 않음).
- 지금(D-83): 버킷·정책·`post_attach`·클라이언트 캡쳐 규격(2번) 함수는 만들어 두되 화면에서 부르지 않는다. 시험은 가짜 client에서 `board_write=true`로 놓고 한다.
[미확인] 공개 버킷 전송량이 DB 전송량 5GB와 합산되는지. 목록 20개 × 120KB ≈ 2.4MB/회, `loading="lazy"`로 화면에 보이는 것만 받는다.

### 2-5. 이름 `names2`·`name_votes`
```sql
create table public.names2 (
  id uuid primary key default gen_random_uuid(),
  region text not null,                        -- 화면 경로 names2/{code}/list 의 code
  name text not null check (char_length(name) between 1 and 8),   -- NAME_RULE.MAXLEN과 맞춤
  uid uuid references auth.users on delete cascade, legacy_author text, nick text,
  up int not null default 0, down int not null default 0,
  status text not null default 'ok' check (status in ('ok','hidden','removed')),
  hidden_at timestamptz, created_at timestamptz not null default now());
create table public.name_votes (
  name_id uuid references public.names2 on delete cascade,
  uid uuid references auth.users on delete cascade,
  vote text not null check (vote in ('up','down')), primary key (name_id, uid));
```
- `names2`: select `status='ok' or uid=auth.uid() or is_admin()`, insert `uid=auth.uid() and can_name()`, update·delete 없음(본인 삭제는 RPC, 익명도 자기 uid 것만). 트리거: nick 복사(회원이면 members.nick, 익명이면 null → 화면은 작성자 표시 생략) → 서버 열 덮어쓰기 → 필터 → (uid, region) 5개 제한(D-31) → 도배 검사.
- `name_votes`: 클라이언트 직접 쓰기 없음. RPC `name_vote(name_id, vote)`(`can_name()` 아니면 `need_member`, 같은 표 다시 누르면 취소, 반대면 바꿈, up·down 다시 셈, `down > up`이면 status='removed', D-31).
- 신고는 3장의 공통 `reports`로(이름 신고도 `can_name()`, 3-4). 숨김 횟수는 `app_config.report_hide.name`(D-74 3회).
- 익명 허용의 남용 방지(D-84): 세션(uid)당 지역별 이름 5개(D-31), 서버 필터(D-74), 신고 3회 숨김, 도배 한도(3-3 name), 익명 로그인 IP당 한도(실시간 문서 8-8 3번). 브라우저를 지우면 새 uid라 5개 제한은 다시 생긴다(수용).

### 2-5-1. 이름 짓기 안내 문구 (D-84)
- 문구(제안): "지금은 로그인 없이 할 수 있어요. 나중엔 로그인이 필요한 기능이에요."
- 조건: `Caps.features.names_anon && !Caps.features.login && Caps.user.isAnonymous()`. 로그인을 켜면 저절로 안 보인다.
- 위치·시점: ① 이름 짓기 화면(이름 제안·목록 시트)을 **처음 열 때 1회** 작은 팝업(확인 버튼 하나), 본 기록은 localStorage `gn_names_notice` = 1. ② 그 뒤에도 이름 입력칸 바로 아래에 한 줄 안내문(작은 글씨)을 늘 둔다 — 팝업을 놓쳐도 "임시로 열려 있다"는 뜻이 남게.
- mock 모드에서도 같은 조건으로 보여 로컬에서 시험한다. 문구는 `ui` 한 곳의 상수로 둔다.

### 2-6. 기타 (배포_계획 1-4에서 이어받음)
- `admin_kv`(레시피): 읽기·쓰기 `is_admin()`. 화면 경로 `admin/recipes`.
- `promo_lock`·`promo_try`: 이번 범위 밖. 다만 D-67로 홍보는 누구나이므로 나중에 만들 때 "회원 전용" 조건을 빼고 uid당 쿨다운만 둔다(1-4 초안과 다름).

### 2-7. 탈퇴·정리 함수
- `member_leave()`: `delete from auth.users where id = auth.uid()` (security definer). cascade로 회원·교감·글·댓글·좋아요·이름·투표·신고가 지워진다. 그림 파일은 화면이 먼저 자기 폴더를 지운다.
- `daily_cleanup()`(D-09 Actions 하루 1회 호출, 배포_계획 1-5(e)): 가입 안 끝난 소셜 계정(members 행 없음, `is_anonymous=false`) 7일 지나면 삭제, `status='removed'` 30일 지난 글·이름 삭제, 처리된 신고 30일 지나면 삭제.
- 익명 계정은 지우지 않는다: 익명 uid를 지우면 cascade로 그 사람이 지은 이름·투표가 사라진다(D-84로 익명 이름이 생김). 쌓이는 수는 무료 한도(월 활성 사용자) 안이라 지금은 둔다.

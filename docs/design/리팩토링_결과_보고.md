# 리팩토링 결과 보고 (D-33~35, 단계 0~3)

> 작성: documenter, 2026-10-24. 기준 결정: D-52까지 반영. 관련: D-13, D-33, D-34, D-35.
> [미확인] 표시는 이번 작성에서 확인하지 못한 내용이다.

## 1. 한 줄 결론

단계 0~3을 마쳤다. 웹 페이지 파일이 1.62MB(1,623,061바이트)에서 6KB(5,991바이트)로 줄었고, 기능은 나눠진 모듈 안으로 옮겼다. 원격 저장소에 올라가 있고(4198e1b), 사용자 최종 확인만 남았다.

## 2. 왜 했나

| 문제 | 설명 |
|---|---|
| 한 파일에 전부 있었다 | 스타일, 지역 경계 데이터, 코드가 `index.html` 한 파일에 섞여 있었다 |
| 읽기 부담이 컸다 | 경계 데이터가 전체의 81%(약 1,297KB)였다. 코드를 찾으려면 큰 파일을 열어야 했다 |
| 안전하게 고치기 어려웠다 | 한 곳을 고치면 어디에 영향이 가는지 알기 어려웠다 |

목표는 "동작은 그대로, 파일만 나누기"다 (D-33). 빌드 도구 없이 ES 모듈로 나눈다 (D-13 유지).

## 3. 단계별 결과

| 단계 | 무엇을 옮겼나 | 커밋 | `index.html` 크기 |
|---|---|---|---|
| 0 | 시험 도구를 `tests/`로 옮기고 기준값 저장 | 0e4effd (0·1 함께) | 변화 없음 (코드 수정 없음) |
| 1 | 스타일 → `prototype/style.css`, 지역 경계 → `prototype/data/regions.json` | 0e4effd | 1.62MB → 0.30MB (298KB) |
| 2 | 순수 계산 모듈 11개 → `src/core/` | 9ac9ca0 | 298KB → 237KB |

- 모듈 수: 단계 3 커밋(4198e1b) 시점 `prototype/src/` `.js` 46개(C-16의 47개는 집계 차이). 이후 R-16·R-17 모듈이 더해져 지금은 59개다.
- 25KB에 가까운 파일(2026-10-24 실측): render/cat_model.js 23.7KB, main.js 21.8KB, ui/admin_panel.js 21.0KB. 나머지는 20KB 미만.

## 4. 현재 구조

```
prototype/
  index.html          뼈대와 로더 (모듈을 못 받으면 안내)
  style.css           스타일
  data/regions.json   지역 경계 (한 줄, 약 1.3MB. 열지 않는다)
  src/
    main.js           시작점
    config.js         배포 설정 자리
    core/             순수 계산 (화면·three 없음)
    adapters/         바깥 세상 (저장, 자료 읽기)
    state/            회원·게시판·레시피 등 상태
    render/           three.js 장면과 고양이 모습
    sim/              고양이 행동·만남
    ui/               화면 (패널, 카드, 시트, 어드민)
    app/              앱 조각 (놀러가기, 교감)
```

층 규칙 (위 층은 아래 층을 부를 수 있고, 아래 층은 위 층을 부르지 않는다):

```
  main.js · app/         조립 (맨 위)
        │
       ui/               화면
        │
  sim/ · render/ · state/  행동·그림·상태 (render는 core만 부른다)
        │
    adapters/            바깥 세상 (저장·자료 읽기)
        │
      core/              순수 계산 (맨 아래)
```

- 위반은 `npm run test:imports`가 잡는다.
- 파일 하나는 400줄, 25KB를 넘으면 나눈다 (`src/README.md`).
- 화면 함수는 앱 객체를 인자로 받는다. 전역 `app`은 `main.js`만 쓴다.
- 시험용 노출(`window.__*`)은 `main.js` 끝 한 곳에서만 한다.

## 5. 품질 확인

시험은 `npm test`에 묶여 있다. 목록은 13개다 (`tests/run_all.js`, shots 제외).

- 실행 결과: 2026-10-24 tester 실행에서 13/13 PASS(unit 191건 통과). 같은 날 전체 실행 1회는 reg·loadfail이 시간 초과로 실패했다가 단독 재실행에서 통과했다(M1-1에서 보완 중).
- unit 191건은 node --test 실행 결과(# pass 191)다. 파일 안 시험 선언은 59개이고 반복문으로 사례가 늘어난다.
- 기준값 비교는 픽셀 비교가 아니다. 그림은 사람이 눈으로 본다.
- 시험을 돌리는 방법: 로컬 서버(`python3 -m http.server 8000`)가 필요하다. `file://`로 열면 안 된다 (D-35).

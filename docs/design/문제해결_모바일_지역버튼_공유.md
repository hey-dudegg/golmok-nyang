## 1. 문제 1 — 모바일 시/군/구 버튼이 세로로 길게 늘어남

### 재현 (확인)
- 로컬 서버(포트 8015)에서 puppeteer로 `#26`(부산) 열기 → "지역 바꾸기" → 시/도 버튼에 focus해 목록 전환, 칩 높이 측정.

| 화면 폭 | 목록 높이(style.height) | 부산 16곳 칩 높이 | 대구 9곳 칩 높이 | 경기 47곳 칩 높이 |
|---|---|---|---|---|
| 360 | 387px | 93px | 191px | 23px |
| 390 | 359px | 116px | 177px | 23px |
| 412 | 331px | 107px | 163px | 23px |
| 1100(PC) | 96px (max-height로 잘림, style 303px) | 29px | 46px | 23px |

- 390x800 스크린샷: 부산 16곳이 3줄인데 줄마다 약 116px 높이의 세로 알약 모양. 정상 칩 높이는 23px.
- 참고: 부산은 16곳, 대구가 9곳이다. 사용자가 본 "9곳"은 대구 화면으로 보인다.

### 원인 (확인)
두 가지가 겹친다.
1. `prototype/src/ui/picker.js:74-79` `reserve()`
   시트 높이 흔들림을 막으려고 16개 시/도 중 가장 긴 목록(경기 47곳)의 높이를 재서
   `soonList.style.height = mh + 'px'`로 고정한다. 모바일에서는 이 값이 330~390px.
2. `prototype/style.css:166` `.soonlist { display:flex; flex-wrap:wrap; ... }`
   여러 줄 flex 컨테이너는 `align-content` 기본값(normal = stretch)이라 남는 세로 공간을
   각 줄에 나눠 주고, 칩(`align-self` 기본 stretch)도 그 줄 높이만큼 늘어난다.
   칩이 적은 지역(대구 9곳, 부산 16곳)일수록 줄 수가 적어 칩 하나가 더 길어진다.
- PC에서 덜 보이는 이유: `style.css:166`의 `max-height:96px`가 높이를 96px로 묶어 늘어나는 폭이 작다
  (그래도 대구 46px, 부산 29px로 약간 늘어나 있다).
- 모바일에서 심한 이유: `style.css:207` `@media (max-width:720px) .soonlist { max-height:none; overflow:visible; }`
  가 상한을 풀어서 `reserve()`가 잡은 큰 높이가 그대로 적용된다.
- 비활성 문구·min-height·줄바꿈 금지는 원인이 아니다 (칩 문구는 짧은 구 이름, min-height 없음).

### 해결안 비교
| 안 | 내용 | 효과 | 부작용 | 작업량 |
|---|---|---|---|---|
| A (권장) | `style.css:166` `.soonlist`에 `align-content:flex-start; align-items:flex-start;` 추가 | 높이는 그대로 예약되고 칩은 23px로 위에 붙는다. PC·모바일 모두 고쳐짐 | 칩 아래 빈 공간이 남음(모바일 최대 약 300px 공백) | CSS 1줄 |
| B | A + 모바일에서는 `reserve()` 생략(`matchMedia('(max-width:720px)')`면 높이 고정 안 함) | 모바일 빈 공간도 사라짐. 모바일은 마우스 hover 되먹임이 없어 예약이 필요 없음 | 모바일에서 시/도를 누르면 바로 이동하므로 목록 전환 자체가 드묾. 회전·폭 변경 시 분기 확인 필요 | CSS 1줄 + JS 2~3줄 |
| C | `height` 대신 `min-height`로 예약 | 늘어남은 그대로 남는다(min-height도 stretch 대상) | 효과 없음 | - |

- 권장: A를 먼저 적용하고, 모바일 공백이 거슬리면 B까지. 3D·셰이더·행동 엔진과 무관하므로 기준값(tests/baseline)·pose 시험 영향 없음.
  picker 화면을 찍는 시험이 있으면 스크린샷 비교만 다시 본다.

## 2. 문제 2 — 사람 수는 1, 이름·랭킹은 공유되는 것처럼 보임

### 사람 수 (확인)
- 배포 사이트에는 `window.claude`가 없고, `LocalMock.usable()`은 localhost에서만 참이다
  (`src/adapters/local_mock.js:8`, D-21). 그래서 `src/adapters/caps.js:8-10`에서 room·lock·db·user가 모두 null.
- `src/ui/together.js:20` `real() { return Caps.room ? Caps.room.count(...) : 1; }` → room이 없으면 항상 1.
  휴대폰·PC가 서로를 셀 통로가 없다. 의도된 1차 배포 동작이다.

### 이름·랭킹 (확인: 기기 사이 공유 경로 없음)
- `src/state/names.js:22-31` `watch()`: `Caps.db`가 null이면 `loadLocal()` → `store.get('names2:'+지역)`,
  즉 그 브라우저의 localStorage만 읽는다. 저장도 `saveLocal()`(names.js:43)로 localStorage에만 쓴다.
- names.js:32-35의 `storage` 이벤트는 같은 브라우저의 다른 탭끼리만 전달된다. 다른 기기로 가는 길이 아니다.
- `src/adapters/store.js:5-8`: 키 앞에 `golmok:`을 붙인 localStorage 읽기·쓰기뿐, 네트워크 전송 없음.
- 같아 보이는 이유: 고양이 기본 이름이 결정적으로 만들어진다.
  `src/core/genome.js:115-124` `dongPopulation()`이 `makeRng('mascot:'+지역코드)`로 성별·나이·털·이름을 뽑으므로
  어느 기기든 같은 지역이면 같은 고양이·같은 기본 이름(D-04, D-19). `src/main.js:102-104`는 투표 1위가 없으면 이 기본 이름을 쓴다.
  랭킹도 새 기기에서는 둘 다 "아직 지어 준 이름이 없어요"로 같게 보인다. 모의 투표나 미리 넣은 후보 이름은 없다.
- 판정: 한 기기에서 지은 이름이 다른 기기에 나타나는 경로는 **현재 코드에 없다**.
  같은 이름이 보였다면 (1) 기본 이름이었거나 (2) 양쪽에서 같은 이름을 각각 지었거나 (3) 같은 기기의 다른 탭이었던 경우다.
- 원격 사이트는 따로 요청하지 않았다(코드로 판정 가능).

### 해결 방향 (설계만)
- 기기 간 공유(사람 수·이름·랭킹)는 공용 저장소·실시간 채널이 필요하다. 계획된 Supabase(Presence·DB) 어댑터를
  `Caps.room`·`Caps.db` 자리에 끼우면 화면 코드는 그대로 동작한다(together.js:12, names.js:24 주석의 설계대로).
- 그 전까지 오해를 줄이려면: 이름 탭 안내문(names_panel.js:28)에 "지금은 이 기기에만 저장돼요" 한 줄 추가를 검토.

### 사용자 설명 (비개발자용, 5줄)
1. 지금 사이트는 기기끼리 서로 연결되어 있지 않아서, "보는 눈"은 내 화면 하나만 세어 늘 1로 나와요.
2. 고양이 이름은 지역마다 정해진 규칙으로 만들어져서, 어느 기기에서 봐도 처음 이름은 똑같아요.
3. 그래서 공유되는 것처럼 보이지만, 새로 지은 이름과 투표는 그 기기(브라우저)에만 저장돼요.
4. 휴대폰에서 지은 이름은 PC에 나타나지 않아요. 이건 고장이 아니라 아직 공용 저장소를 붙이지 않은 상태예요.
5. 공용 저장소(무료 범위)를 연결하는 다음 단계에서 사람 수와 이름이 기기 사이에 함께 보이게 돼요.

## 0. 2026-10-24 갱신: 현재 코드 기준 점검과 2단계 배포 (마지막 반영 D-36)

> 이 장은 prototype/ 현재 코드를 직접 확인해 덧붙였습니다. 1~10장(Supabase 쪽 설계)은 코드에 아직 어댑터가 없어 그대로 유효합니다. 실제 배포·계정 설정·커밋은 하지 않았습니다.

### 0-2. 배포 대상·구조 (D-08, D-13)

- **정적 호스팅 루트 = `prototype/`** (Pages 설정: Framework 없음, Build command 비움, Output directory `prototype`). 현재 파일 64개·약 1.9MB. 가장 큰 것은 `data/regions.json` 1.3MB(한 줄 JSON), `data/landmarks.json` 22KB. Pages 한도(파일당 25MiB, 사이트 20,000개)에 한참 못 미침 [확인: 1-1 근거].
- 출력 폴더가 `prototype/`이므로 `docs/`, `.private/`, `tests/`, `.env*`, `node_modules/`는 **배포되지 않습니다**. 이 구조를 바꾸지 않는 한 `.private` 유출 경로는 없음.
- 경로: `index.html`·로더는 상대경로(`./src/main.js`, `./data/regions.json`)만 사용, 절대경로(`/…`) 없음(grep 확인). 하위 경로·루트 어디에 올려도 동작. 공유 링크(`?r=코드`)는 `location.href` 기반이라 도메인 무관. 라우팅이 없어 `_redirects`·404 처리 불필요.
- **외부 의존 2종(둘 다 해결됨):**
  1. three.js 0.160.0: 해결됨. `prototype/vendor/`에 자체 호스팅, import map이 사이트 안 경로를 가리킴(버전 고정 유지) (D-47 반영).
  2. 글꼴: 해결됨. `prototype/vendor/fonts/`에 자체 호스팅, CSS에 외부 주소 없음 → CSP 외부 허용·방문자 IP 전달 없음 (D-53 반영).
  - 그 외 외부 주소: 공유 버튼의 X·Threads 글쓰기 링크는 클릭 시 이동만(스크립트 로드 아님). 5장 CSP 초안의 `connect-src`는 Web3Forms가 접근 키를 넣을 때(1차~), supabase는 2차에 필요 (D-54 반영).
- **import map과 인라인 스크립트:** `index.html`에 인라인 `<script type="importmap">`과 인라인 `<script type="module">`(로더)가 있어 엄격한 CSP(`script-src 'self'`)는 인라인을 막습니다. 1차에서는 CSP를 **Report-Only로만** 두거나 해시를 허용하고, 강제는 로더를 외부 파일로 뺀 뒤(developer) 합니다(S-8).
- **모듈 로딩 실패 안내:** 로더가 `import('./src/main.js')` 실패(404·망 오류)를 잡아 안내 화면을 띄우고, `regions_data.js`가 경계 자료 실패를 안내합니다(`load_fail` 시험 통과). vendor의 three.js를 못 받아도 빈 화면이 아니라 안내가 뜹니다 (D-47 반영). `file://` 직접 열기는 불가이며 안내문이 로컬 서버 실행법을 알려 줍니다(배포 환경에는 무관).
- **캐시와 `_headers`(`prototype/_headers`, 현재 파일 없음 → 새로 만들 것):**
  - 파일 이름에 해시가 없는 ES 모듈 구성이라, 배포 직후 옛·새 모듈이 섞여 로드되면 import 불일치가 날 수 있습니다. 권장: `/*`에 `Cache-Control: no-cache`(매번 ETag로 확인, 변경 없으면 304)로 시작. Pages 기본 캐시 동작은 [미확인]: 가입 후 응답 헤더를 직접 확인.
  - `data/regions.json`(1.3MB)은 거의 안 바뀌므로 필요하면 `/data/*`만 `max-age=3600` 정도로 완화(바꿀 때 최대 1시간 지연 감수). 전송 압축은 Cloudflare 기본 [추측].
  - 보안 헤더(`X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `X-Robots-Tag: noindex`)는 5장 초안 그대로 1차부터 적용 가능(규칙 100개·줄 2,000자 한도 안).
  - 1차 `_headers` 예시(값 없음):

    ```
    /*
      Cache-Control: no-cache
      X-Content-Type-Options: nosniff
      Referrer-Policy: strict-origin-when-cross-origin
      Permissions-Policy: camera=(), microphone=(), geolocation=()
      X-Robots-Tag: noindex
    ```
  - 모듈 스크립트는 MIME이 틀리면 실패하므로 첫 배포 후 `.js`·`.json` 응답의 Content-Type을 확인합니다 [추측: 일반적으로 정상].
- 자체 호스팅(three.js, 글꼴)은 사용자 확인을 받아 완료했습니다(`prototype/vendor/`, 라이선스 파일 포함) (D-47·53 반영).

### 0-4. 단계별 절차 (1차)

**사용자가 직접 할 일(D-14: 계정·설정은 사용자 명의, 에이전트는 실행하지 않음):**
1. GitHub·Cloudflare 계정에 2단계 인증 켜기. Cloudflare 가입 시 **결제 수단 미등록**(8장 체크리스트 A-1~2).
2. 팀장에게 커밋·푸시 승인(C-10). 저장소는 이미 공개(D-22).
3. Cloudflare Pages에서 "Connect to Git" → 저장소 선택 → Production branch `main`, Framework 없음, Build command 비움, Output directory `prototype` → 저장·배포.
4. 나온 주소(`*.pages.dev`)를 에이전트에게 알려 주기(공개 정보).
5. C-11을 눈으로 확인하고 문제 화면을 알려 주기.
6. 링크를 공유할 범위 결정(P-02). 환경 변수는 1차에 **없음**.

**에이전트가 할 수 있는 일(저장소 파일만, 승인 후):**
- `prototype/_headers` 작성(0-2 예시), 배포 후 응답 헤더 점검 안내, 롤백 안내.
- `.github/workflows/`에 시험 워크플로(syntax·imports·unit 3종만. 브라우저 시험은 Chrome·서버가 필요해 제외). 공개 저장소 Actions 무료 여부는 [미확인]. D-09 하루 1회 요청은 2차에 추가.
- 개인정보 고지 한 줄. 자체 호스팅은 완료 (D-47·53 반영).

**롤백:**
- Cloudflare Pages 배포 목록에서 이전 배포로 되돌리기 [미확인: 메뉴 이름, 가입 후 확인]. 또는 문제 커밋을 되돌리는 새 커밋을 푸시하면 자동 재배포(이력 보존).
- 공개 중지: Pages 프로젝트 삭제 또는 링크 공유 중단. 코드 롤백해도 방문자 기기의 localStorage(체험 모드 기록)는 남음.
- 2차 롤백: 어댑터는 실전 설정 값(URL·키)을 비우면 모의로 복귀, 의견 전송은 `accessKey`를 비운 뒤 재배포(1분) (D-54 반영).

### 0-6. 모의 어댑터(D-21) → Supabase 어댑터(D-10) 전환 시점과 P-07

- **전환 시점:** 1차 정적 공개에서 화면·로딩이 안정되고 0-7의 2차용 P가 정해진 뒤, 2차(M4-1~)에서 어댑터-0을 시작합니다. 한 번에 갈아끼우지 않고 `config.js`의 실전 설정 값 유무로 **모의 ↔ 실전을 선택**하게 합니다(값이 비면 모의, 스테이징에 먼저 값 입력. 의견 전송의 `accessKey` 방식과 같음, D-54 반영). 모의 어댑터와 tests는 유지(회귀 시험이 모의에 의존). `LocalMock.usable()`은 계속 로컬 호스트 전용.
- **P-07 선택지(2장 상세):** A `config.js`에 공개 값(URL·anon 키) 커밋 / B 배포 때 환경 변수 치환(빌드 명령이 생김). **추천: A.** 이유: 빌드 없음(D-13) 유지, 키는 어차피 방문자에게 보이는 공개 값이고 방어선은 RLS, 호스트 이름으로 스테이징·운영 선택 가능. 부작용: 공개 저장소에 키 문자열이 보여 GitHub 비밀 스캐너 경고가 올 수 있음(공개 키라 실제 위험 없음, 미리 안내). 보완: `/secure-check`에 `service_role`·`sb_secret` 값 패턴 검사 추가, 값이 들어가는 파일은 `src/config.js` 한 곳으로 한정. 1차에는 키가 필요 없어 **P-07은 2차 착수 전까지 미뤄도 됩니다.**

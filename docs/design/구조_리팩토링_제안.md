# 소스 구조 리팩토링 제안 (architect, 2026-10-18)

> 작성 범위: 조사와 제안만. 코드는 고치지 않았고, 다른 docs도 건드리지 않았다.
> 반영한 마지막 결정: D-32. 관련: D-08, D-10, D-13, D-21, D-29, P-07, M1 초안.

## 한 줄 결론과 권장안

**지금의 단일 HTML은 "프로토타입 단계"에는 괜찮았지만, 기능을 더 얹기에는 이미 적절하지 않다.**
빌드 도구(Vite 등)는 필요 없고, **"빌드 없는 정적 ES 모듈 분리"(D-13 그대로)를 M0-4 전에 하는 것을 권장**한다.

| 순서 | 할 일 | 위험 | 효과 |
|---|---|---|---|
| 0 | 시험 스크립트를 저장소 `tests/`로 옮기고 "분리 전 기준값" 저장 | 매우 낮음 | 이후 모든 단계의 안전망 |
| 1 | CSS를 `style.css`로, 경계 JSON을 `data/regions.json`으로 | 낮음 | 파일 1.59MB -> 약 0.27MB. 에이전트 읽기 부담 -83% |
| 2 | 순수 로직(수학·유전자·행동표·교감 규칙)을 `src/`로 | 낮음 | 단위 시험 가능 |
| 3 | 나머지(장면·시계·UI·어드민)를 `src/`로, 전역 `app`을 `ctx`로 | 중간 | 파일당 5~25KB, 순환 제거 |
| 4 | (선택) 아티팩트용 단일 파일 합치기 스크립트 | 낮음 | 아티팩트로 되돌릴 길 유지 |

예상 작업량: 에이전트 약 4~6회 작업(추측), 토큰 약 1~2백만(추측). 상세는 7장.

## 1. 현황 (스크립트로 측정)

측정 대상: `prototype/index.html` 1,594,203바이트 / 4,113줄. 측정 스크립트는 scratchpad에만 있다.

| 구성 | 시작 줄 | 크기 | 줄 수 | 비고 |
|---|---|---|---|---|
| `<style>` 2개 | 1, 6 | 27KB | 296 | 한 곳에 몰려 있음 |
| HTML 본문 | - | 3KB | 39 | 거의 비어 있음(JS가 DOM을 만듦) |
| 경계 JSON `#regions-data` | 329 | **1,297KB (전체의 81%)** | **1줄**(127만 자) | 시/도 16·시군구 256·행정동 3,558, 점 15만 개 |
| import map | 330 | 0.2KB | 1 | three.js 0.160 (jsDelivr 고정) |
| `<script type="module">` | 331 | 266KB | 3,781 | 코드 전부. 16개 구역 |

사용자 설명의 "인라인 module script 3개"와 다르게, 실제 인라인 `<script>`는 JSON·import map·module 3개이고 **모듈 코드는 1개**다. 압축하면(gzip) 전체 557KB, 코드만 88KB, JSON 460KB다.

### 의존 관계 (정규식 기반 추정. 주석·문자열 속 단어도 잡히므로 대략치)

- 맨 아래: 00_util은 아무것도 안 쓰고, 거의 모든 구역이 쓴다. 30_genome, 35_regions도 util만 쓴다. 여기까지는 깨끗하다.
- 중간: 20_catmodel -> 10_shaders, 40_poses -> 20_catmodel, 50_scene -> shaders·genome, 62_clock -> util·genome·poses·scene·behavior·visit.
- 위: 70_ui가 65_caps에서 11개, 80_admin이 65_caps에서 13개, 90_main이 거의 전부(65_caps에서 21개)를 쓴다.
- **숨은 결합 1: 전역 `app`.** `app.xxx` 접근이 106곳(`app.dong` 22, `app.selected` 8, `app.mascot` 7 ...)이고, 거의 모든 구역이 90_main의 `app`을 함수 안에서 불러 쓴다. 지금은 한 스코프라 문제가 안 보이지만, 파일을 나누면 곧바로 **순환 import**가 된다.
- **숨은 결합 2: 65_caps <-> 70_ui.** caps가 `renderCard`(UI)를 부르고 UI는 Caps·GATE를 쓴다. 분리 시 진짜 순환이 되는 유일한 구역 간 쌍이다(나머지 쌍은 `app` 때문).
- 모듈 최상위 가변 상태: `SIDO_MAP`(let) 1개뿐. 나머지는 const 객체(Admin, GATE, Caps, Board, Names, Clock, Trips, LocalMock 등)의 내부 상태다.
- `window.__*` 노출은 시험용 7개: `__app`, `__advance`, `__still`, `__pose`(자세 확인), 그리고 `?admin`일 때만 `__trips`, `__TRIP`, `__inter`. 시험 스크립트가 이것에 의존하므로 **분리 후에도 유지**해야 한다.
- 브라우저 저장: localStorage 키는 `golmok:` 접두사. 모듈이 나뉘어도 영향 없음.
- 외부 접속: three.js(CDN)와 `window.claude`(없으면 LocalMock)뿐. `fetch`는 이미지 저장용 1곳.

## 3. 세 가지 선택지 비교

"추측"은 근거 확인을 못 한 판단이다.

| 기준 | A 단일 HTML 유지 | B 정적 ES 모듈 분리 (권장) | C 번들러(Vite 등) |
|---|---|---|---|
| 첫 로딩 | 557KB(gzip) 한 번에. 파싱 부담은 작음(추측: JSON 파싱 수십 ms) | 파일 수십 개지만 HTTP/2·3에서 병렬. import 깊이만큼 순차 요청 생김 -> `modulepreload`로 완화(추측) | 가장 빠르게 최적화 가능. 우리 규모에선 차이 미미(추측) |
| 재방문·캐시 | 코드 한 줄만 고쳐도 1.5MB 재전송 | 바뀐 파일만 재전송. JSON은 거의 안 바뀌므로 304 | 해시 파일명으로 최상 |
| 데이터 지연 로딩 | 불가(HTML에 박힘) | `fetch('data/regions.json')`, 시/도별 조각도 가능 | 가능 |
| 에이전트 읽기 비용 | 코드만 **약 8만 토큰**(추측: 24만 자, 한글 1만 자 기준 환산), 한 번 읽기도 부담. JSON 줄은 읽기 금지 | 파일당 3~33KB(약 1~1만 토큰). 필요한 파일만 읽음 | 모듈과 같음 + 설정 파일 추가 |
| 에이전트 수정 | 큰 파일 `Edit`는 고유 문자열 찾기·재읽기 반복. 두 에이전트 동시 수정 불가 | 파일이 달라 충돌 적음. 리뷰 diff가 작음 | B와 같음 |
| 단위 시험 | 불가에 가까움(전부 브라우저+puppeteer). 지금 시험도 `scratchpad`에만 있어 **저장소에 없음** | 순수 모듈은 `node`로 직접 import해 시험 가능(three·DOM에 안 닿는 파일) | B와 같음 |
| 배포 | 파일 1개 | 폴더째 업로드(Pages가 그대로 서빙) | 빌드 단계·Node 버전·의존성 관리 추가. D-13과 충돌, 비전문가 부담 |
| 오프라인·공유 | "파일 하나 더블클릭"이 장점. 단, 지금도 three.js를 CDN에서 받으므로 완전 오프라인은 아님 | 로컬 서버 필요(`python -m http.server`). 이미 현재 안내와 같음(`file://`에서는 ES 모듈·fetch 제한) | 로컬 서버 또는 빌드 필요 |
| 보안·CSP | 인라인 스크립트 때문에 엄격한 CSP가 어려움(`unsafe-inline` 또는 해시 필요) | 코드가 외부 파일이라 `script-src 'self'` + CDN 한 곳으로 CSP 작성이 쉬움. import map은 인라인이라 해시 1개 필요(추측, 적용 시 확인) | 가능 |
| 아티팩트 복귀 | 그대로 가능 | 합치기 스크립트 필요(4단계). 합칠 수 있도록 규칙 필요 | 번들러가 단일 파일 출력 가능하나 도구 추가 |
| 순환 의존 | 숨어 있음(한 스코프) | 파일 경계에서 드러남 -> 고칠 기회. 대신 정리 작업 필요 | B와 같음 |
| 비용 | 0 | 0 | 0원이지만 의존성 확인 필요(CLAUDE.md 규칙상 사전 확인) |

판단:
- **A는 한계 도달.** 변경이 끊임없이 일어나는 단계(M0-4, 명소, 의견함)인데 파일이 계속 커지고, 시험·수정이 느려진다는 실제 증상이 있다.
- **C는 지금 과함.** 이점(해시 캐시, 트리 셰이킹, 압축)이 현 규모에서 작고, 비전문가가 관리할 도구가 늘며, D-13과 충돌한다. 나중에 코드가 훨씬 커지거나 TypeScript가 필요해지면 B의 폴더 구조 그대로 C로 올릴 수 있다(분리해 두면 이전이 쉬움).
- **B가 D-13의 연장**이라 새 결정이 거의 필요 없다. 구체 파일 구성만 정하면 된다.

### 의존 방향 (한 방향만 허용)

```
main -> ui, sim, render, state, adapters, core
ui   -> state, adapters, render(읽기만), core
sim  -> core, render(자세만), state(읽기만)
render -> core
state -> adapters, core
adapters -> core(+config)
core -> (없음)
```

규칙:
1. **화살표 반대 방향 import 금지.** 위 층에서 아래 층만 부른다. 아래 층이 위 층을 불러야 하면 **콜백 또는 이벤트**로 바꾼다(예: caps가 `renderCard`를 직접 부르던 것은 "변경됨" 이벤트를 내보내고 UI가 받게 한다).
2. **전역 `app` 폐지.** `app.dong`, `app.selected`, `app.mascot` 같은 현재 상태는 `state/ctx.js`의 한 객체(`ctx.dong` 등)로 옮긴다. 로직 함수는 가능하면 인자로 받는다. 106곳을 한 번에 바꾸지 말고 `ctx.js`가 `app`을 가리키게 해 두고(`ctx.app = app`) 순서대로 줄여 간다.
3. 가변 전역 상태는 한 모듈이 소유하고 다른 모듈은 함수로만 접근. `SIDO_MAP` 같은 캐시는 해당 모듈 내부로.
4. `window.__*` 시험용 노출은 `main.js` 한곳에서만 한다(시험 스크립트 호환).
5. 같은 파일명 기능 번호(00_, 10_) 대신 의미 있는 이름만 쓴다.
6. 파일 하나 400줄·25KB 넘으면 나눈다는 가이드를 둔다.

## 5. 이행 단계와 검증 (위험 낮은 순)

공통 규칙: 한 단계 = 한 묶음 작업. 단계마다 시험 통과 + 사용자 시연 후 다음으로. 단계 중에는 `index.html` 동결.

### 단계 0. 안전망 만들기 (코드 수정 없음)
- 지금 scratchpad에 있는 `reg.js`(어드민 버튼 전수 클릭·자세 바닥 높이), `pose_check.js`, `m02c.js`, `b2_polarity.js`를 `tests/`로 복사한다. 주소·크롬 경로 등 환경 값은 인자로 받게 정리(공개 저장소: 개인 경로·계정 정보 금지).
- **기준값 저장**: ① 페이지 오류 0건, ② 같은 시각·같은 지역에서 `window.__app`으로 뽑은 고양이 상태 해시(고양이 id, 성격, 욕구·감정, 오늘 일정)의 JSON, ③ 대표 화면 스크린샷 몇 장(서울·제주 / 평상시·어드민 열림).
- 정적 검사: 모듈 코드를 뽑아 `node --check`(문법) + 사용하지 않는 이름·선언 안 된 이름 검사(예: 가벼운 스크립트로 `eslint no-undef` 상당. 새 의존성은 확인받고 쓸 것).
- 완료 조건: 현재 파일로 시험 전부 통과하고 기준값 파일이 만들어짐.

### 단계 1. CSS와 경계 JSON 분리 (효과 최대, 위험 낮음)
- `<style>` -> `style.css` (복사, 내용 무변경).
- `#regions-data` -> `data/regions.json`. `REGIONS`는 지금 모듈 로드 중 동기로 만들어지므로, **최상위 await로 `fetch` 후 만들기**(모듈 스크립트는 최상위 await 지원)가 가장 단순하다. 로딩 화면은 이미 있으므로 UX 영향 작음.
- 대안: `export default {...}` 형태의 `regions.js`로 두면 비동기도 필요 없고 `import`만으로 끝나지만 JSON 편집·지연 로딩에는 불리. 권장은 JSON + fetch.
- 선택 추가 효과(별도 결정): 지금 활성은 시/도 16곳뿐인데 지도(`buildSidoMap`)가 행정동 폴리곤 15만 점을 합친다. 시/도 단순화 경계를 미리 만들어 `data/sido_outline.json`로 두면 첫 화면 데이터가 크게 줄 수 있다(추측: 수십 KB). 행정동은 비활성이므로 필요할 때 지연 로딩. 동작 변화(경계 모양이 단순화됨)가 생기므로 별도 승인 사항.
- 검증: 단계 0 시험 전부 + 기준값 해시 동일 + 스크린샷 비교. 로컬 서버로 열어 콘솔 오류 0.
- 롤백: git 한 커밋 되돌리기(사용자 승인 후 커밋).

### 단계 2. 순수 로직 먼저 떼기 (core/)
- util, genome, regions, behavior_tables, touch_rules(65_caps에서), name_rules를 `src/core/`로. 한 줄 import/export만 추가하고 로직은 그대로.
- `regions.js`는 JSON을 인자로 받는 함수 `buildRegions(raw)`로 해서 DOM 의존 제거.
- 이 단계에서 처음으로 **node 단위 시험**이 생긴다: 결정적 계산(`makeGenome`, `themeFor`, 일정, 교감 규칙 확률표)의 입력->출력 스냅샷을 비교해 "분리 전후 동일"을 직접 증명한다. 기존 `b2_polarity.js`가 확인하던 내용도 여기서 더 빠르게 돈다.
- 검증/롤백: 단계 1과 같음.

### 단계 3. 나머지 분리 + `app` 정리
1. `render/`(shaders, cat_model, poses, scene)
2. `adapters/`(caps, local_mock) - D-10 정리. caps 안의 gate/admin/member 로직은 `state/`로
3. `sim/`(agent, trips)
4. `ui/` 패널들, `main.js`
- 순서 이유: 아래 층(의존이 적은 쪽)부터 떼야 위 층이 `import`로 바뀔 때 깨지지 않는다. 각 하위 단계마다 시험을 돌린다.
- `app` 정리는 모듈화가 끝난 뒤에 별도 하위 단계로(분리와 의미 변경을 섞지 않기).
- 순환 점검: `import` 그래프를 뽑는 작은 스크립트로 순환 0 확인(완료 조건).
- 검증: 기준값 해시·스크린샷·시험 전부 동일. 어드민 버튼 전수(reg.js) 오류 0.

### 단계 4. (선택) 단일 파일 합치기 `tools/bundle.mjs`
- 빌드가 아닌 "이어 붙이기": CSS·JSON을 인라인하고 모듈을 의존 순서대로 한 `<script type="module">`로 연결, `import/export` 줄만 제거.
- 이를 위해 코딩 규칙이 필요하다: 한 줄 `import`/`export`, default export 금지, 이름 충돌 금지, 모듈 간 순환 금지. 단계 3의 규칙과 같아서 추가 부담은 작다.
- 용도: 아티팩트 재게시, 메일 첨부 같은 "파일 하나" 공유, 단계별 회귀 시험의 보조 기준(합친 결과가 분리 전과 동일하게 동작하는지).
- 한계: 아티팩트가 CDN(jsDelivr)을 허용하는지는 확인하지 못함 -> **미확인**. 원래 아티팩트가 three.js CDN으로 동작했다는 기록만 있다.

### 롤백
- 각 단계를 별도 커밋(사용자 승인 후)으로 두고 문제 시 해당 커밋만 되돌린다. 분리 시작 전 태그를 하나 달아 두면 한 번에 복귀 가능.
- 단계 3 도중에는 옛 `prototype/index.html`을 지우지 말고 `prototype_old/`(추적 안 함 또는 태그)로 둔다. 새 구조는 새 폴더/같은 폴더에서 비교 가능하게.

## 10. 가정과 미확인

- 의존 관계는 정규식 추정이다. 실제 분리 때 정확한 import 그래프를 다시 뽑아야 한다.
- 토큰·시간 추정은 실측이 아니라 글자 수 기반 환산이다.
- Cloudflare Pages의 캐시 헤더 기본값, 아티팩트의 CDN 허용 범위, import map에 대한 CSP 해시 적용은 확인하지 못했다.
- 시험 스크립트(reg.js 등)는 세션 임시 폴더에 있었고 저장소에는 없다. 최신본인지 확인이 필요하다.
- 조사 시점에 index.html은 다른 developer가 수정 중이어서 줄 번호가 바뀔 수 있다.

|---|---|

## 1. 현황 분석 (코드에서 확인한 사실)

## 2. 오브젝트 데이터 모델

위치: `src/core/props.js`(순수, three 없음). 모양 그리기는 `src/render/props.js`(5절). 층 규칙(core <- adapters <- state <- render/sim) 안에서 render가 core 표를 읽는다.

### 2.1 종류표 `PROP_KINDS` (확장은 표에 한 줄 추가)

```js
// 인터페이스 예시 (구현 아님). 단위 m, 지점 좌표는 오브젝트 로컬(x: 길이 방향, z: 폭 방향, 앞(+z)이 카메라 쪽)
export const PROP_KINDS = {
  car: { label: '자동차', size: { l: 2.2, w: 0.95, h: 0.62 }, footprint: 'box', passUnder: true,
    themes: ['alley', 'market'], slots: [ /* 2.2 */ ] },
  // 이후: crate(상자), lowwall(낮은 담), pipe(구멍), bench, barrel ...
};
```

| kind | 도형(코드) | 크기(l x w x h) | 지점 | 단계 | 테마 |
|---|---|---|---|---|---|
| car (소형차, 양식화) | 몸통 상자 2단(하체·캐빈) + 앞유리(어두운 상자) + 바퀴 4(원기둥) + 헤드램프 | 2.2 x 0.95 x 0.62, 차체 바닥 높이 0.20, 본네트 윗면 0.42 | hood(위), under(아래), 지붕은 막음(비워 둠) | O1 | 골목·시장 |
| lowwall (낮은 담) | 상자 + 갓돌 상자 + 표면 질감(기존 wallTex 재사용 가능) | 1.8 x 0.22 x 0.80 | top(위) x2, behind(뒤 그늘) | O2 | 골목·시장·공원 |
| crate (종이/플라스틱 상자) | 윗면 열린 상자(4면 + 바닥) | 0.55 x 0.45 x 0.28 | in(안), top(뚜껑 위 변형) | O2 | 전체 |
| pipe (콘크리트 관/구멍) | 열린 관(원기둥 속을 뒤집은 면) 또는 문턱 있는 개구부 상자 | 0.7 x 0.45 x 0.40 | in(안, 눈만), front(입구 앞) | O3 | 골목·공원 |

차는 실물 크기(4m)를 넣으면 5m 무대를 다 먹으므로 **양식화한 작은 차**로 한다(고양이 키 0.2m와 비율 유지: 하체 틈 0.20 > 웅크린 고양이 높이 + 여유, 본네트 0.42는 고양이가 한 번 도약해 오를 높이). 비례는 사용자 확인 대상(P-O4).

### 2.2 지점 `slot` 정의

| 필드 | 뜻 | 예 (car.hood) |
|---|---|---|
| id | 종류 안 고유 이름 | `'hood'` |
| mode | `on`(위) / `under`(아래) / `in`(안) / `beside`(옆) | `'on'` |
| pos | [lx, lz] 로컬 위치(오브젝트 중심 기준) | [0.72, 0.0] (앞쪽 끝) |
| y | 서는 면 높이(m). 아래/안은 바닥 위 얹은 높이 | 0.42 |
| yaw | 고양이가 보는 방향(로컬 각, 기본 `'cam'`=카메라 쪽) | `'cam'` 또는 -π/2 |
| poses | 허용 자세 | `['loaf','lie','sit']` |
| cap | 수용 수 | 1 |
| inset | 가장자리에서 띄울 여유(몸 크기 x scale) | 0.12 |
| approach | 접근점 [lx, lz]와 올라가는 방향 | [0.72, 0.62] (카메라 쪽 옆) |
| clear | 허용 높이(under/in): 자세 높이 x scale 이 이 값 이하여야 선택 가능 | under: 0.20 |
| shade | 햇빛 가림(0 햇빛 ~ 1 그늘) | hood 0 / under 0.7 |
| hideK | 가림 의도(under/in): 몸이 가려지는 비율 목표 | under 0.6 (등·머리 일부만 보임) |
| warm | 따뜻함(겨울·낮 점수) | hood 0.8 / under 0.2 |
| tag | 행동 연결용 꼬리표 | `'rest'`, `'hide'`, `'perch'`, `'peek'` |

지점은 "자리"만 정의한다. 어떤 자세·몇 초는 행동(3장)이 정한다.

### 2.3 배치 규칙 `layoutFor` (순수 함수, 결정적)

`layoutFor({ theme, code, obstacles }) -> [{ id, kind, x, z, rot, seed }]` (`makeRng('props:' + code)`).

| 규칙 | 내용 |
|---|---|
| 개수(테마별) | alley: 차 0~1(60%) + 상자 1~2 + 낮은 담 0~1 + 구멍 0~1 / market: 차 0~1(40%) + 상자 2~3 / park: 낮은 담 1 + 구멍 0~1 (차 없음) |
| 가로줄 | 차·낮은 담은 뒷담 가까이 z -1.4~-0.9 에 나란히(길이 방향 x축). 카메라 기본 화면 x -1.6~1.6 안에 최소 1개가 들어오게 중심 x를 배치. |
| 간섭 | 기존 `S.obstacles`(화분·의자·상자·전봇대)와 사각형 겹침 검사, 최대 20번 재시도, 실패하면 그 오브젝트는 건너뛴다(없는 장면은 현재와 같다). |
| 통로 | 오브젝트 사이·무대 가장자리와의 틈 >= 0.5m (고양이가 접근점에 설 수 있게). 접근점은 `BOUNDS` 안이어야 한다. |
| 명소 | 사용하지 않는다(D-26). `layoutFor`에 명소 인자를 받지 않는다. |
| 실패 안전 | 빈 배열이면 새 행동은 점수 0 -> 현재 동작과 동일 |

런타임 결과는 `world.props = PropWorld`(src/sim/props.js): `slots()`, `claim(id, agent)`, `release`, `nearest(tag, from)`, `occupied(slotId)`. `world.blocked/resolve`도 여기 오브젝트 풋프린트를 합친다.

## 3. 행동 연결 (D-03·D-07 확률표 유지)

새 행동은 `ACTIONS`에 키 추가. 점수 함수는 기존과 같은 모양(`score(a, ctx)`), `Clock.weights`의 `EMO_BIAS`에 감정 편향 한 줄씩 추가. 지점이 없으면 점수 0.

| 키 | 라벨 | 단계 | 점수(초안, 기존 척도 0~2 안팎) | 감정 편향(EMO_BIAS, 0.5 기준) |
|---|---|---|---|---|
| hoodLoaf (O1) | 차 본네트에서 엎드린 중 | 접근 -> 도약 올라가기 -> `lie` 자세 유지 10~30초 -> 내려오기 | `avail * (0.30 + day*0.55 + warmth*0.4 + bold*0.35 + (1-E)*0.3)` | calm +0.6, happy +0.3, wary -0.6, scared -0.9 |
| underHide (O1) | 차 밑에 숨은 중 | 접근 -> 낮게 걷기 들어가기 -> `hideLow`/`peek` 유지 12~40초 -> 천천히 나옴 | `avail * (0.12 + (1-bold)*0.9 + shy*0.5 + heat*0.5)`; 보통 낮은 값이라 겁쟁이/한여름 낮 아니면 드묾 | scared +1.0, wary +0.8, calm -0.2, playful -0.4 |
| wallLoaf (O2) | 담 위에 엎드린 중 | 올라가기 -> `lie` 15~40초 (가끔 `alert` 두리번) | `avail * (0.25 + bold*0.5 + curious*0.5 + day*0.3)` | curious +0.6, calm +0.4, scared -0.7 |
| crateSit (O2) | 상자 안에 들어간 중 | 들어가기 -> `sit`/`loaf` (귀·머리만 보임) | `avail * (0.30 + (kitten?0.6:0) + (1-bold)*0.3 + playful*0.2)` (고양이의 "상자 사랑" = 새끼·소심한 쪽 가중) | calm +0.4, playful +0.3 |
| holePeek (O3) | 구멍에서 빼꼼 | 들어가기 -> `peek`(눈·귀) 유지, 가끔 사라졌다 나옴 | `avail * (0.10 + curious*0.5 + (1-bold)*0.5)` | curious +0.8, scared +0.5, wary +0.4 |

- `avail` = 해당 종류의 빈 지점이 있고(런타임은 점유 반영, 시계는 존재만 반영) 허용 자세 높이가 `clear` 이내면 1, 아니면 0.
- `day`/`warmth`: `a.world.day`와 지점 `warm`. `heat`: 낮 x 여름(`seasonOf`) x under 그늘. 모두 시각·계절의 함수라 결정적(D-19 유지).
- 반복 방지(마지막 행동 x0.35, 시계 x0.3/0.6)와 상위 N 추첨은 엔진 그대로.
- 퍼소널리티 키는 기존 `a.p`의 bold / social / playful / grumpy / energy만 쓴다(새 성격 값 없음, 유전자 변경 없음).
- 끝나면 내려와 접근점에서 `stand` -> 다음 행동. 일정 항목이 중간에 끝나도(10초 이상 비운 뒤 복귀 포함) `enterClock`의 빨리 감기가 동일하게 마지막 지점 상태를 계산한다.

### 교감 반응 쪽 연결 (REACTIONS)

| 상황 | 변경 |
|---|---|
| `flee`(도망) | 지금은 `farFrom(you)` 임의 지점. 숨는 지점(tag `hide`)이 근처에 있고 bold < 0.6 이면 그리로 달려가 `underHide`/`holePeek`의 들어가기 단계로 연결. 없으면 현재 그대로. |
| 숨은 상태(under/in)에서 쓰다듬기 | 극성을 부정 쪽으로 보정(D-30 짝짓기 유지: 같은 극성의 행동·속마음만). 기본은 `peek`로 빼꼼 + "숨어 있어요" 안내, 끌어내지 않는다. |
| 츄르 | 숨은 상태여도 가능. 접근점까지 천천히 나와서 먹고, 다시 돌아가지 않고 일정으로 복귀. |
| 높은 곳(on) | 쓰다듬기는 일반과 같되 손 위치는 root.y 기준으로 이미 올라간다(머리 정점 월드 좌표를 쓰므로 자동). |

## 4. 이동·접근

| 항목 | 설계 |
|---|---|
| 접근 | `STEP.walk(approach)` 후 `STEP.mount(slot)`. 접근점은 항상 오브젝트 카메라 쪽 옆 (+z)이라 올라가는 모습이 보임. |
| 올라가기(on) | 웅크리기 0.4s(`crouch`) -> 도약 호 0.5~0.7s(`STEP.hop`: from.y -> slot.y, 정점 = 높이 차 + 0.08) -> 착지 `crouch` 0.3s -> 자세. 속도·거리는 `scale` 배수(새끼는 높이 한계: slot.y > 0.35 x scale 이상이면 새끼는 `avail=0`, 즉 새끼는 본네트 불가·낮은 담은 가능). |
| 내려오기 | 올라가기의 역(호 + 착지). 급할 때(만남 시작·도망)는 `dismountFast`(0.25s). |
| 들어가기(under/in) | 접근점에서 `crouch`(낮은 걸음) 후 지점으로 직선(얕은 이동). 이 동안 `a.layer = 'under'`로 바꿔 해당 오브젝트 풋프린트 충돌을 무시하고, 나올 때 layer를 되돌린다. |
| 충돌 | 풋프린트는 사각형(회전 포함) 장애물. `layer`가 `under/in`인 고양이는 그 오브젝트만 통과. `resolve` 수정 한 곳. 다른 고양이 겹침 방지(기존)는 y 차가 0.2 이상이면 무시. |
| 점유 | `claim(slotId, agent)`은 `STEP.mount`의 start에서, `release`는 dismount 끝 / goDong 초기화 / 에이전트 제거 / 만남 시작 시. cap 초과면 같은 kind의 다른 지점 -> 없으면 접근점에서 지상 `loaf`로 대체(행동이 막히지 않음). |
| 시계와 점유 | 시계 일정(`entry`)은 점유를 모른다(결정성). 시작 시 `lazy()` 안에서 지점을 다시 고른다: 일정이 정한 지점 -> 점유 시 같은 kind 다른 지점 -> 없으면 대체. 마스코트 1마리 + 손님 몇 마리라 충돌은 드물다. |
| 시간대 | 낮(`world.day`)이면 on 지점 가중, 밤이면 under/in(`nap` 변형 가능). 새벽·밤의 졸림 곡선(`circadian`)은 기존 `nap/loaf`에 이미 반영 -> 새 행동은 점수를 겹쳐 올리지 않는다. |
| 날씨 | 현재 `weatherFor`는 clear/haze/mist(비 없음)뿐. 날씨 분기는 넣지 않고 **계절·낮밤만** 쓴다. 비 날씨는 새 요소라 P-O5로 올림. |
| 어긋남 방지 | 도약 호 중에는 `jump`(기존 pounce)와 `hop`이 동시에 안 돌게 한쪽만(`a.hop` 별도 필드). 빨리 감기(sim)에서는 호 대신 즉시 이동(시간 합산만). |

## 5. 자세와 렌더링

### 5.1 새 자세 (POSES, `plant`/높이는 B1 방식 그대로)

| 자세 | 용도 | 비고 |
|---|---|---|
| lie | 엎드리기(스핑크스): 앞발 앞으로, 턱 들거나 내림, 뒷다리 접음 | loaf와 구분(loaf는 앞발 접음). `plant:'none'`, h는 loaf 계수 재사용 후 pose_check로 확정 |
| hideLow | 낮게 납작(귀 눕힘, 배 바닥, 동공 큼) | under 용. 키가 가장 낮은 자세. `clear` 검증 기준 |
| peek | 머리만 내밀기(목 위로, 귀 쫑긋, 눈 크게) | in/under 용. 몸은 hideLow 로 가려진 채 |
| dangle | 담 위에서 앞발 한쪽 늘어뜨림 | O2 선택(없어도 됨) |
| (전환) | hop 구간의 공중 자세 | 새 자세 없이 `stand` + 덧값 `pounce`식(`tb`, `fls` 등) 재사용 |

### 5.2 높이 보정 (B1과의 관계)

| 문제 | 설계 |
|---|---|
| 면 위 바닥 뚫림 | `CatView.update`는 "가장 낮은 정점 = root 기준 0"으로 보정(B1). 그러므로 root.y = 면 높이만 올리면 발이 면에 닿는다. 별도 높이 보정 없음. |
| 가장자리 | 지점의 `inset`(몸 크기 x scale)만큼 안쪽에 두어 몸이 면 밖으로 삐져나오지 않게. 꼬리가 늘어지는 `lie`는 꼬리가 면 아래로 떨어져도 되나(허공 통과) 바닥 아래로 뚫리지 않게 `GROUND_SINK` 안전망이 이미 있다. |
| 그림자 | 발밑 원형 그림자는 root 자식이라 면 위에 놓인다(y=0.004). 면 가장자리 밖으로 번지면 어색하므로 on 지점에서는 `shadow` 스케일을 지점 크기에 맞춰 상한(`slot.shadowMax`). 환경 쪽은 오브젝트에 `castShadow=true`라 지면에 차 그림자가 생긴다. |
| 차 밑 햇빛 | 고양이 셰이더는 그림자 맵을 못 받는다. `CatView` 재질에 `shade`(0~1) uniform 추가, 조명 식에서 sunCol 항에 `(1-shade*0.75)`를 곱한다. 에이전트가 지점 `shade`로 부드럽게 보간(들어갈 때 어두워짐). 셰이더 파일 변경은 이 한 줄뿐. |
| 키 한계 | 설계 시험 `prop_pose_h`: 자세 x 체형(pose_check의 5체형)의 최대 높이(m)를 구해 `clear`와 비교 -> `under`/`in` 지점에 쓸 자세는 `높이 x scale + 0.02 <= clear`를 시험으로 보장. |

### 5.3 가림 (별도 기술 없이 깊이로)

| 연출 | 방법 |
|---|---|
| 차 밑에서 몸 일부만 | 차체 바닥 높이 0.20에 바퀴 4개. 앞(+z) 바퀴 사이로 고양이가 보이고 바퀴·하체 판이 윗부분과 옆을 자연스럽게 가린다. `hideLow`(높이 약 0.12)로 등선 정도 보임. 고양이 y는 0, 몸을 풋프린트 안쪽(lz = -0.1)에 둠. |
| 구멍에서 눈만 | 관/개구부 앞턱(문턱 상자 높이 0.14)을 고양이 앞에 두고, 고양이는 턱 뒤 0.15m 안쪽에서 `peek`. 눈·귀만 턱 위로 나옴. 안쪽 면은 어두운 색 재질(조명 영향 낮춤). |
| 상자 안 | 상자 벽 높이 0.26, 고양이 `sit`(높이 ~0.2~0.25): 귀와 머리 윗부분만. 바닥 얹기 `slot.y`로 보이는 양 조절. |
| 털 껍질 | 고양이 털은 껍질(shell) 방식: 현재 투명도 혼합을 쓰지 않는 것으로 확인(`depthWrite` 변경 없음) -> 깊이 정렬 문제 없음. 차 창문은 불투명 어두운 색으로(투명 재질 금지: 정렬 문제 회피). |
| 선택(pick) | `main.pick`은 가슴 정점의 화면 투영 거리로 고른다. 가림과 무관하게 누를 수 있다(차 밑 고양이는 차 위로 눌러도 선택됨). 필요하면 가림 비율이 높을 때 반경을 줄임(11장 질문 아님, 구현 때 확인). |
| 카메라 | `select(a, focus)`의 카메라 목표 높이에 `a.y`를 더한다(올라간 고양이를 따라감). 차 밑 고양이는 `selUp`을 낮춰 낮은 시점으로. |

### 5.4 오브젝트 그리기 (D-01·D-13: 코드 도형만)

- 위치: `src/render/props.js`(조립) + 도형 도우미는 필요하면 `backdrop_shapes.js`의 `roof` 등을 **재사용하지 않는다**: 그 파일은 z -9~-40의 먼 실루엣(병합된 BufferGeometry, 선 윤곽·낮은 폴리)용이라 가까이에서 부적합하다. 대신 `scene.js build()`에 이미 쓰는 `box()/cyl()/std()`(MeshStandardMaterial) 패턴과 `scene_themes.js`의 `canvasTex/speckle`(질감 캔버스)을 그대로 쓴다. 공통 도구는 `scene_themes.js`에서 import(층 규칙 내).
- 함수: `buildProps(S, E, layout, std, box, cyl)` -> 오브젝트마다 `THREE.Group`(원점=중심, 회전 `rot`). 그룹 하나에 메시 5~12개. 병합 불필요(총 오브젝트 3~6개).
- 색: 차는 `makeRng` 시드로 5색 중 하나(회색·흰·빨강·남색·연두), 질감은 얼룩/먼지만(작은 캔버스 256x128).
- 정리: `clearEnv()`가 `env`를 통째로 traverse해 dispose하므로 오브젝트 그룹을 `E`에 넣으면 누수 없음(기존 backdrop 누수 시험이 같은 방식).

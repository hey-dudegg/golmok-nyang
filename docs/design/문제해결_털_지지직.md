## 1. 증상
- 고양이를 가까이 확대하면 털 가장자리, 흰 털, 몸통 윤곽이 모래알 같은 점으로 흩어진다(DJ/error.png).
- 카메라나 고양이가 조금만 움직여도 점 무늬가 프레임마다 바뀌어 깜빡인다. 사용자: "눈이 너무 아프다". 치명으로 분류.

## 2. 재현
- 방법: puppeteer(tests/lib/common.js, swiftshader), 자체 정적 서버(빈 포트), `?still=40&hour=14&shells=16|28&pr=1.75|1`.
  마스코트에 카메라를 0.6m 안쪽으로 붙이고 스크린샷. 임시 스크립트는 tests/out(깃 무시)에 두었다가 지웠다.
- 1280x800(pr 1, 셸 28): 재현됨. 꼬리·엉덩이 윤곽·털끝이 사용자 스크린샷과 같은 점묘로 보인다.
- 390x800(pr 1.75, 셸 16): 첫 회차에서 같은 점묘 확인. 다음 회차는 카메라가 고양이를 벗어나 화면 비교는 무효.
- 렌더러 상태: antialias=true, gl SAMPLES=4 (MSAA는 켜져 있음).
- 한 프레임 차(고양이 숨쉬기·작은 움직임 포함, 화면 가운데 60% 영역):
  - 1280: 밝기 차 평균 9.1, 40 넘게 바뀐 화소 6.1%
  - 390: 평균 5.2, 1.3%
  - 정지 물체(바닥·벽)는 거의 0이고 바뀐 화소는 털 영역에 모인다.
  - 한계: 움직임 자체의 차이가 섞여 있다. 수동 render로 움직임을 뺀 비교는 헤드리스 캡처가 이전 프레임을 잡아
    무효였다. 해결안별 깜빡임 수치는 아직 없다(구현 후 같은 방법으로 다시 잰다).

## 3. 원인
### 확인 (코드)
1. **털 투명도를 화면 좌표 디더 + discard로 표현한다.** prototype/src/render/shaders.js:148-149
   ```glsl
   float ign = fract(52.9829189 * fract(dot(gl_FragCoord.xy + vec2(hgt*97.0, hgt*31.0), ...)));
   if (alpha < max(ign, 0.02)) discard;
   ```
   alpha가 0~1 사이인 화소는 살거나 죽는 것만 가능해서 반투명 대신 1화소 점 무늬가 된다(정지 화면의 모래알).
2. **디더 무늬가 화면(gl_FragCoord)에 고정돼 있다.** 털은 세계에서 움직이는데 무늬는 화면에 붙어 있어,
   털이 1화소 미만만 움직여도 살아남는 점 집합이 통째로 바뀐다 = 지지직. 이런 디더는 TAA(여러 프레임 평균)가
   있어야 매끄러워지는데 이 렌더러에는 TAA가 없다.
3. **MSAA가 이 점을 못 지운다.** discard는 화소의 모든 샘플을 버리고 디더 단위가 1화소라 4x MSAA가 섞을 것이 없다.
   alphaToCoverage(알파를 샘플 마스크로 바꾸는 기능)는 쓰지 않는다(shaders.js:183 makeFurMaterial, 설정 없음).
4. **중간 알파 영역이 넓다.** shaders.js:138 털끝 페이드 `1 - 0.55*smoothstep(0.35,1,t)`, 가닥 가장자리 fwidth 페이드,
   솜털 층(a2)이 겹쳐 셸 위쪽 대부분이 alpha 0.3~0.7 → 디더가 가장 거칠게 보이는 구간이다.
### 추정 (확인 안 함)
5. 확대할수록 셸 사이 간격이 화면에서 벌어져(셸 16·28, main.js:52; 자동 조절 main.js:312-321) 윤곽이 점선처럼 보인다.
   셸 수를 줄이는 자동 품질 조절이 모바일에서 이를 키운다.
6. PC pr 1에서는 디더 1화소가 크게 보이고, 모바일 pr 1.75(main.js:68)에서는 작지만 화면을 가까이 봐 눈에 띈다.
7. 셸 투명 정렬은 원인이 아니다: 털 재질은 불투명(transparent 없음, 알파 1 출력)이라 정렬을 안 탄다.

## 4. 해결안 비교
| | A. alphaToCoverage | B. 디더 제거 + 알파 정리 + 거리 LOD | C. 디더를 털 좌표에 고정 |
|---|---|---|---|
| 방법 | discard 대신 `gl_FragColor.a = alpha`, `mat.alphaToCoverage = true`. MSAA 4x가 화소 안에서 섞는다 | 임계를 고정(alpha<0.5)하고 털끝 페이드를 "반지름 줄이기"로 바꿔 알파를 0/1에 가깝게. 화면에서 가닥이 1화소보다 작아지면(fwidth 큼) 가닥 무늬 대신 평균 덮임으로 바꾸고 바깥 셸을 일찍 자른다 | ign을 gl_FragCoord 대신 `hash(floor(vRest*density*k), 셸)`로 |
| 지지직 | 거의 사라짐(화면 고정 무늬 없음) | 사라짐(무작위 없음) | 사라짐(무늬가 털에 붙어 움직임) |
| 정지 모래알 | 부드러움(샘플 4개 평균) | 없음. 대신 가닥 가장자리 계단이 조금 남음 | 그대로 남음 |
| 멀리서 | 좋음 | LOD 덕에 좋음 | 반짝임(모아레) 생김 |
| MSAA 없는 기기 | 효과 없음 → B식 고정 임계로 폴백 필요 | 영향 없음 | 영향 없음 |
| 모바일 성능 | 거의 0(이미 MSAA 켜짐, discard 줄어 오히려 이득 가능) | 0~이득(바깥 셸 컷으로 채움 감소) | 0 |
| 작업량 | 작음(셰이더 2줄 + 재질 1줄 + 폴백 분기) | 중간(셰이더 알파 식 재조정, 눈으로 튜닝) | 아주 작음 |
| 털 느낌 변화 | 털끝이 조금 더 부드럽고 옅어짐 | 털끝이 조금 단단해짐(튜닝 필요) | 없음 |

참고: 셸 수를 늘리는 안은 윤곽 점선(추정 5)만 줄이고 지지직은 못 고치며 모바일 비용이 커서 보조로만 쓴다
(가까이 볼 때만 셸 +8 같은 거리 기반 조절).

## 5. 권장안과 결정 필요 사항
- **권장: A + B의 일부.**
  1) alphaToCoverage를 기본으로(shaders.js:149 discard 제거, 알파 출력, makeFurMaterial에 alphaToCoverage).
  2) MSAA가 없을 때(gl SAMPLES < 2) 고정 임계 0.5 discard로 폴백(무작위 디더는 어디서도 쓰지 않는다).
  3) 털끝 페이드 계수 0.55를 낮추고, fwidth가 클 때 바깥 셸 알파를 줄이는 LOD를 넣는다.
  4) 구현 뒤 같은 재현 스크립트로 1280·390에서 한 프레임 차와 확대 스크린샷을 다시 재 합격 확인.
- 합격 기준 제안: 확대 정지 화면에 1화소 점묘가 없을 것, 카메라 0.5도 회전 시 털 영역 깜빡임이 바닥과 같은 수준.
- 팀장 결정 필요: (a) 권장안 채택 여부, (b) 털끝이 약간 부드럽게 바뀌는 것(외형 변화) 허용 여부 — 사용자 확인 권장.
- 실기기(아이폰 사파리, 안드로이드 크롬) 확인은 swiftshader로 대신할 수 없다. 배포 전 사용자 눈 확인 필요.

## 7. 움직임 지지직 (D-66 적용 뒤 후속, 2026-10-29, troubleshooter)
### 7.1 증상·재현
- 사용자 폰: 정지 시 지지직은 줄었으나 걷기·행동 중에는 털이 다소 지지직. 폰 실기 확인은 못 했다.
- 재현: swiftshader 390x800 pr1.75 shells16, 카메라를 0.5화소씩 4번 돌려 털 영역 인접 프레임 변화율(%) 측정.
  한계: 진짜 움직임(가장자리 이동)이 섞여 바닥값을 모른다. 변형끼리 상대 비교만 유효. swiftshader MSAA 4x는 폰 GPU의 A2C 방식과 다르다.
### 7.2 원인
확인(코드):
1. 가닥 크기가 화소 몇 개 수준이다. density 330(shaders.js:98·205) → 가닥 칸 약 3mm, 폰에서 2.2m 거리 약 3화소(계산).
   LOD(shaders.js:148)는 fwidth(d) 0.35~0.85(칸 6~2.4화소)에서만 켜지므로 3~6화소 구간은 가닥 무늬가 그대로 살아 있다.
2. 가닥 가장자리 폭 `fw=max(fwidth(d),0.02)`(138·145줄)는 약 1화소 폭의 날카로운 경계다. 몸이 움직이면 가닥이
   프레임마다 다른 화소 위상에 걸쳐 4샘플 중 켜지는 수가 바뀐다(커버리지 0~4의 5단계). TAA 없이는 이 위상 변화가 곧 반짝임이다.
3. 털끝은 `rad=0.95*(1-t)^0.75`(136줄)로 급히 가늘어져 셸 위쪽은 폭 1화소 미만 → 알파가 0.5 경계를 넘나든다.
4. 골격·셸 갱신 순서는 문제 없음: update()가 자세→행렬→bones 유니폼 후 같은 프레임에 그린다(cat_model.js:336-356, main.js:272→301).
   vRest는 정점 속성이라 무늬는 피부에 붙어 움직인다(셸 간 떨림 없음). 정점당 뼈 하나(shaders.js:76)라 관절 이음선만 단단히 꺾인다.
5. 바닥 보정 hOff가 매 프레임 damp로 미세하게 움직여(cat_model.js:350) 정지 자세에서도 화면 위상이 조금씩 바뀐다(추정 아님, 코드 확인. 영향 크기는 미측정).
확인(측정): 바꿔 본 변화율(near 0.7m / mid 2.2m, 현재 16.7 / 15.2):
| 변형 | near | mid |
|---|---|---|
| LOD 더 일찍(0.15~0.5) | 21.4 | 17.7 |
| 가장자리 폭 2배(min 0.05) | 0.6 | 9.4 |
| 가장자리 폭 3배(min 0.1) | 2.2 | 10.9 |
| 폭 2배 + LOD 일찍 | 2.6 | 13.4 |
| 폭 2배, LOD 끔 | 1.8 | 11.6 |
| A2C 끄고 임계 0.5 (MSAA 없는 폰 경로) | 10.0 | 15.8 |
- 읽는 법: near는 폭 키우기 하나로 거의 해결. LOD를 앞당기면 오히려 나빠짐(평균 덮임이 A2C 단계 무늬를 키움).
  mid는 어느 것도 확 줄지 않음 = 가닥(3화소)과 샘플(4개)의 크기가 비슷한 구간.
추정(미확인): 폰 GPU의 A2C는 화면 좌표 고정 디더 무늬로 샘플 마스크를 고르는 구현이 많아 2번이 더 심할 수 있다.
MSAA가 없는 폰이면 고정 임계 0.5 경로(shaders.js:158)라 위 마지막 줄(10~16%)과 같다. 폰 SAMPLES 값은 확인 못 함.

  - swiftshader도 MSAA 4(samples=4)라 PC에서 재현됨. 앞서 "재현 안 됨"은 PC가 MSAA 없다고 본 오해였다.
  - 방법: 390x800 pr2, 정면 얼굴 0.7m. tests/fur_m114.js (임시 변형 비교 스크립트, 이번에 추가).
  - 같은 구도 A/B: (a) ccb 그대로 a2c / (b) LOD 끄기 / (c) 털끝 페이드 구형 복원 / (d) a2c 대신 디더 discard + 알파 1.0.
    a·b·c는 얼굴 중앙이 계단형 블록으로 털 없이 밋밋·어둡고 몸 털은 밝게 그려짐. d만 얼굴·몸 균일. 즉 LOD·털끝 페이드는 원인이 아니고 a2c 출력이 원인.
  - 기전(추정): a2c는 알파를 샘플 마스크(0/25/50/75/100%)로 양자화한다. 셸마다 알파가 비슷하면 같은 샘플만 덮여 누적이 안 되고,
    머리는 털이 짧아(headFur 0.55, cat_model.js:133) 셸이 겹쳐 밑바탕이 드러난다. 계단 모양은 그림자 맵 경계와 겹친 것으로 보이나 미확인.
- 해결 시도(실패): 디더 문턱을 털 좌표 고정 해시로 교체(hash31(floor(vRest*density*k)+hgt)). k=6: near 2.07->4.28%, mid 6.08->8.39%.
  k=1: near 2.52->3.91%, mid 7.02->9.40%. 오히려 증가(화면 고정이 불안정을 줄인다는 가정이 틀림: 화소 격자가 움직일 때 같은 문제). 폐기.
- 코드 상태: shaders.js·scene.js·fur_flicker.js는 커밋 2205a5d(롤백)로 되돌렸다. 시도 셰이더는 보관 안 함(저장소 밖).
- 남은 후보: (1) 롤백 유지하고 지지직은 수용(외형 우선), (2) 디더(discard) 유지 + MSAA 켠 상태에서 털 알파만 부드럽게(셸 수 증가는 성능),
  (3) 가닥 격자 밀도 하향(B). 어느 쪽도 외형 변화가 있어 사용자 판단 필요.

## 9. M1-14 후보 비교 (고정 구도, 코드 변경 없음)
- 구도 고정(앱 코드 무변경): 시험이 `?still=20`으로 루프를 멈춘 뒤 mascot.ext=true, setPose('sit'), update 80회로 자세를 안정시키고 머리 기준으로 카메라를 둔다.
  MSAA 끔은 시험이 getContext의 antialias를 false로 바꿔 만든다. 구도 쌍 비교는 한 실행 안의 변형끼리만 유효(실행마다 고양이 유전자·위치가 다름).
- 후보: a=a2c+셸별 디더 오프셋(a0은 오프셋 0), b=고정 임계 0.5(a2c 없음), c=롤백+density 0.7.
- 외형(MSAA 켬, 390x800 pr2, 정면 0.7m): 롤백·b는 얼굴·몸 톤 균일. a0·a는 얼굴 중앙에 옅은 블록·낟알 무늬와 전체 밝아짐(톤 불일치, 불합격).
  c는 가닥이 굵어지고 밝아져 톤이 달라짐(불합격). a0 재현은 약하게만 됨(원인 조건 장면: 낮, 그림자 진 얼굴).
- 지지직 변화율(%, near=정면 0.7m / mid=옆 2m):
  - MSAA 끔 pr2: 롤백 2.31/4.05, b 2.23/3.75, c 1.75/3.36, a 1.69/3.27 (a2c 끔이라 a는 의미 약함)
  - MSAA 켬 pr1: 롤백 3.02/3.30, b 2.91/3.16 (pr2는 시간 초과)
- 판정: 외형 합격(롤백·b) 중 지지직이 확실히 낮은 안 없음(b는 -4%). 외형 불합격(c)만 -17~24%. 따라서 수정하지 않고 롤백 유지(= 수용).
- 도구: tests/fur_m114.js(shots|flicker, 변형 문자열 치환), tests/lib/montage.js(그림 이어 붙이기). fur_flicker.js는 옛 셰이더 전용이라 삭제(어디서도 참조 안 함).
- 남은 방향(미검증): 셸 수·두께 조정, 시간 평활(이전 프레임 혼합, 큰 변경), 사용자 폰 실측 후 재판단.

## 0. 요약

- 고정비: 팀장은 매 턴 CLAUDE.md 약 3.3k 토큰을 싣고, 서브에이전트는 위임 1회마다 CLAUDE.md + 정의 + INDEX로 약 5.9k를 쓴 뒤에야 일을 시작한다.
- 변동비 중 큰 것은 (1) 추가만 하는 기록 파일을 Edit하려고 통째로 읽기(LOG 4.9k, 커질수록 늘어남)
  (2) 설계 문서 통째 읽기(문서당 1.7k~18.9k) (3) `npm test` 전체 출력(약 8~10k로 추정)이다.
- 상위 3개 방안: O4 기록 파일 끝만 읽기(기록 턴당 약 5~6k), O5 시험 출력 요약(실행당 약 8k),
  O1+O2 CLAUDE.md 정리와 위임 시 INDEX 생략(턴당 약 1.1k, 위임당 약 3k).

## 1. 측정 방법

- 크기: `wc -c`·`wc -l`, git 기록은 `git show <커밋>:<파일> | wc -c`. 측정일 2026-10-24, 작업 트리 기준(수정 중 파일 포함).
  작업 트리 파일은 CRLF(core.autocrlf=true)라 wc 바이트에 줄 수만큼 더해진다. git 기록 값은 LF 기준.
- 토큰 추정(에이전트 정의의 규칙): 비ASCII 글자(한글 등) 1자 = 1토큰, ASCII 4바이트 = 1토큰. 파이썬 스크립트로 계산(8장).
  실제 토크나이저와 ±30% 차이가 날 수 있으므로 비교·순위용으로만 쓴다.
- 이미지: Anthropic 문서의 근사식 `토큰 ≈ 가로 x 세로 / 750`.
- 시험 출력: 실행하지 않고 스크립트의 `console.log` 위치와 반복 횟수로 추정(2.8).
- Claude Code 자체 시스템 프롬프트·도구 스키마는 측정할 수 없어 제외했다.
- 서브에이전트도 CLAUDE.md를 받는다: 이 작업(token-optimizer) 세션 시작 시 CLAUDE.md 전문이 함께 들어왔다.

### 2.8 시험 출력 `npm test` (실행하지 않고 추정)

`tests/run_all.js`는 13개 시험의 표준출력을 **모두 그대로** 찍은 뒤 끝에 통과표(15줄)를 찍는다.

| 시험 | 출력 근거 | 추정 크기 |
|---|---|---|
| syntax | 파일마다 `ok   <이름>` 1줄 (src 59 + 로더·import map·JSON) | 약 63줄, 2.8KB |
| imports | 통과해도 모듈마다 import 간선 1줄을 항상 출력(116행) | 약 62줄, 6.5KB |
| unit | `node --test` 59개, 파이프 출력은 TAP(시험당 약 5줄) | 약 300줄, 9KB |
| feedback | `t()` 확인 49개 각 1줄 | 약 50줄, 2KB |
| backdrop | 16곳 x 후보 2~3 각 1줄 + 메모리 JSON | 약 45줄, 3.5KB |
| 나머지 8개 | 머리줄·RESULT·요약 몇 줄 | 약 4KB |
| 통과표 | 13행 + 머리 | 1KB |
| 합계 | | **약 29KB, 8~10k 토큰** |

Bash 도구 출력 한도(3만 자)에 가깝다. 넘으면 잘려 통과표를 놓칠 수 있다. 통과 판정에 필요한 것은 통과표 15줄(약 400토큰)뿐이다.

## 5. 토큰 수칙 (모든 에이전트 공통, 11줄)

1. 읽기 전에 `wc -c`·`wc -l`로 크기부터 본다. 8KB 넘는 파일은 grep으로 위치를 찾고 offset/limit으로 그 부분만 연다(D-125). 위임문의 함수명·줄 범위 우선.
2. 같은 파일을 다시 통째로 읽지 않는다. 바뀐 부분은 `git diff <파일>`로 본다.
3. 위임문에 결정 변경분이 있으면 INDEX·DECISIONS를 다시 열지 않는다. 없을 때만 INDEX의 D 표를 본다.
4. 설계 문서는 위임문이 지정한 장만 읽는다. 지정이 없으면 목차부터 본다.
5. 추가만 하는 파일(LOG·CHANGELOG)은 끝 몇 줄만 읽고 붙인다. history·archive는 grep만.
6. regions.json·tests/out·node_modules는 열지 않는다. 이미지는 꼭 필요한 1~2장만, 작은 크기 먼저. 촬영 전 자세·구도 고정, 비교는 같은 장면 수치로. 도구 30회면 중간 보고(D-125).
7. 시험은 통과표만 출력해 본다(`| tail -n 16`). 실패한 시험만 이름을 지정해 다시 돌린다.
8. 명령 출력은 `head`·`tail`·`grep`으로 줄여서 받는다. 목록은 `head -20`, 많으면 `wc -l`로 개수만. 성공 로그를 붙여 넣지 않는다.
9. 보고는 정해진 10줄 형식만. 코드·로그 인용은 근거가 되는 몇 줄만. 토큰 내역에 재읽기 횟수·읽은 총 KB(D-125).
10. 계획에 없는 탐색(전체 Glob, 폴더 통째 읽기)은 하지 않고 필요한 파일을 위임문에 묻는다.
11. 시험 실패, 기준값 변경, 개인정보·보안, 공개 직전, Supabase 정책·이전, 위임문이 모호할 때는 아끼지 않는다. 9장 표대로 끝까지 읽는다.

# 명소 1단계(시/도 16곳) 후보표 (R-17, 2026-10-19)

- 근거 결정: D-26(사용자는 이름만), D-27(지역당 후보 2~3곳을 주차 번호로 순환), D-28(절차적 3D 실루엣 + 2D 원경), D-29(1단계 시/도 16곳). 설계 원문은 `의견함_명소배경_설계.md` 2부.
- 이 문서는 **사용자 확인용 입력 자료**입니다. 코드는 건드리지 않았습니다. 사진·이미지는 쓰지 않고 이름·유형·형태 설명만 적었습니다.
- 지역 코드는 `prototype/data/regions.json`의 시/도 첫 두 자리와 `SIDO_SHORT`(regions.js) 기준입니다. 이 프로젝트는 **전남광주통합특별시(코드 12)** 를 한 지역으로 다루므로 광주·전남이 한 칸입니다.

## 사용법 (사용자)
1. 아래 시/도별 표에서 마음에 들면 "승인", 바꾸고 싶으면 **해당 칸의 이름만** 고쳐 말해 주세요. (예: "대구 3번을 서문시장 대신 앞산전망대로")
2. 유형·설명은 Claude가 이름에 맞춰 고칩니다. 사용자가 신경 쓸 것은 이름뿐입니다.
3. 표의 번호(1/2/3)는 순환 순서입니다. 주차 번호 % 3 으로 돌려 보여 줄 예정이며(D-27), 순서가 마음에 안 들면 알려 주세요.

## 유형 어휘
- 설계 13장 `kind`: tower, palace, hanok, fortress, bridge, harbor, lighthouse, mountain, island, falls, field, market, skyline, temple, park (이하 영문 키만 씀).
- **이 표에서 새로 제안하는 유형 4개**(설계 목록에 없음): `lake`(호수·호반), `beach`(해변·해안 바위), `hillvillage`(언덕 위 계단식 마을), `forest`(숲·대숲·갈대밭). `field`로 합쳐도 되지만 형태가 달라 분리를 권합니다.
- 신뢰도: **높음** = 널리 알려진 대표 명소이고 위치·명칭이 하나로 정해짐. **보통** = 유명하나 대표성이 다른 후보와 경합하거나 일부만 확인. **낮음** = 명칭·위치가 모호하거나 확인하지 못함.
- 근거 출처는 WebSearch 결과 URL입니다. 공식 관광 사이트 직접 확인이 아니라 **언론·여행 기사 등 간접 자료**가 대부분이며, 검색 결과에 없던 항목은 "미확인"으로 표시했습니다(Claude의 일반 지식에 의존).

## 가정·미확인
- 검색은 시/도당 1회 이내로 했고 공식 관광 사이트(한국관광공사, 각 시/도)의 직접 확인은 못 했습니다. 인용 URL은 간접 기사이며 일부는 내용이 검색 요약에만 의존합니다. 전북의 URL은 검색 결과 목록에서 기사 번호를 특정하지 못해 재확인이 필요합니다.

## 부록 A. `data/landmarks.json` 스키마 초안 (설계 17장 확장, 서울 예시)
```json
{
  "version": 1,
  "kinds": ["tower","palace","hanok","fortress","bridge","harbor","lighthouse","mountain","island","falls","field","market","skyline","temple","park",
            "lake","beach","hillvillage","forest"],
  "terrain": { "11": "city", "26": "coast", "12": "mixed", "50": "island" },
  "places": {
    "11": [
      { "id": "seoul-namsan", "name": "남산 (N서울타워)", "kind": "tower",
        "line": "도심 위 언덕 꼭대기에 솟은 가는 탑",
        "parts": ["ridge", "tower", "skyline"],
        "rotation": 0, "source": "claude", "confidence": "high", "status": "draft" },
      { "id": "seoul-gyeongbok", "name": "경복궁", "kind": "palace",
        "line": "북악산 능선 앞의 겹처마 지붕", "rotation": 1,
        "source": "claude", "confidence": "high", "status": "draft" },
      { "id": "seoul-bukchon", "name": "북촌한옥마을", "kind": "hanok",
        "line": "언덕을 따라 이어진 기와지붕", "rotation": 2,
        "source": "claude", "confidence": "high", "status": "draft" }
    ]
  }
}
```
- 추가 필드 제안: `parts`(생략 시 `kind`의 기본 부품 조합 사용), `rotation`(순환 순서 0..n-1, 주차 번호 % 개수와 대응). 사용자가 승인하면 `source`를 `user`, `status`를 `ok`로 바꿈.
- 사용자가 이름만 고치면 `name`만 바뀌고 `kind`·`line`은 Claude가 재작성하므로 `status`를 다시 `draft`로 돌려 확인을 받는 흐름을 권장.
- 키는 시/도 코드 2자리. 코드 12(전남광주)는 지역 JSON의 현재 시/도 코드를 따름.
- `source`에 `claude` 값은 설계 문서의 정의와 같음. 공개 저장소이므로 이름과 한 줄 설명 외의 개인정보는 없음.

## 2. 출처 표기 (Open-Meteo)

현재: `privacy.js:22` 개인정보 팝업 맨 아래 작은 줄 "날씨 자료: Open-Meteo.com (기상청 모델)", 링크 `https://open-meteo.com/`(새 창, noopener noreferrer). 패널 `title`에도 "기상청 모델 · Open-Meteo".

판단: **최소 요건은 충족하나 자리가 약하다.**
- Open-Meteo 무료 이용은 CC BY 4.0 출처 표기와 비상업 조건이다(내 지식 기준). 표기는 링크를 포함해 눈에 띄는 곳에 있어야 하는데, 개인정보 팝업 맨 끝은 날씨와 무관한 자리라 "눈에 띄게"에는 부족하다.
- 기상청 모델 자료 출처(기관명) 표기 요구 여부는 [미확인]. 팀장: Open-Meteo 이용 약관(Terms)·attribution 안내와 KMA 모델 설명 페이지를 웹에서 확인해 주세요. 확인 전에는 아래 문구로 두 곳을 모두 적어 안전하게 간다.
- 서버가 `src:'kma'`로 표시하는 것과 문구 "기상청 모델"은 일치한다. 기상청이 직접 제공한다는 오인을 막기 위해 "기상청 모델"은 "모델명"임을 드러내는 편이 낫다.

**확정 추천 1안**
- 문구: `날씨 자료: Open-Meteo.com (CC BY 4.0) · 기상청 예보 모델 기반`  (링크는 Open-Meteo.com 글자에, 필요하면 CC BY 4.0에 `https://creativecommons.org/licenses/by/4.0/`)
- 자리: ① **정보·도움말 화면(또는 푸터형 "정보" 줄) 안의 "자료 출처" 한 줄**(주 자리, 날씨가 보이는 화면에서 두 번 이내로 닿음) ② 개인정보 팝업 끝 줄(현행 유지, 같은 문구로 통일). 패널 `title`은 지금처럼 "기상청 모델 · Open-Meteo" 유지.
- 정보·도움말 자리가 아직 없으면 개인정보 팝업 줄만으로는 "조건부"이므로, 최소한 첫 화면 하단 작은 글자 링크 1개를 둔다(developer, 1차).
- 비상업 조건(D-96): 광고·후원·유료 기능 추가 시 재확인(날씨_설계 6장 마지막 줄 유지).

## 3. D-122 전수표: 사용자가 직접 기록하는 글의 금칙어(`gn_text_check`) 적용

기준은 서버(DB 트리거·RPC)가 거치는지다. 화면(`core/text_filter.js`)만의 검사는 우회되므로 "아니오"로 본다.

**빠진 곳 조치 제안**
- T5 닉네임(중. 로그인 재개 D-82 전에 필수. 지금은 익명이 members에 insert 불가라 비활성이라 현재 노출 없음): 담당 **developer**(2차 SQL, 05 또는 새 11 파일). `members_guard`를 `create or replace`로 교체해 INSERT·UPDATE(nick이 바뀔 때) 모두에서 `perform public.gn_text_check('nick', new.nick)`을 호출하고, `kind='nick'` 도배(변경 1시간 3회)는 설계 3-3과 같이 로그인 재개 때 함께. 시험은 `supabase/tests/check_05_filter.sql`에 nick 벡터(금칙어·URL·연락처·특수문자) 4건 추가.
- T5 보강: 이미 저장된 닉네임·이름은 새 금칙어 추가 시 소급되지 않음. 어드민 `mod_list` 외에, 새 단어를 넣을 때 기존 행 점검 쿼리(select 전용)를 운영 메모에 둔다(security 문안 가능).
- T4 순서 의존: `08_realtime.sql:71`은 05가 없으면 검사를 건너뜀. 실행 순서 05→08을 사용자 체크리스트에 고정하고, 확인 SQL에 "홍보 이름에 금칙어를 넣으면 `bad_text`" 항목을 둔다(developer). 요약하면 **05를 반드시 08 앞에 실행**.
- T7 상자: 10_box.sql 작성 때 developer가 (a) `gn_text_check('name', ...)`을 예외 삼킴 없이 호출하고 코드를 그대로 반환, (b) `box_place` 이름 1~10자, (c) `gn_rate_check` 연결, (d) 시험 벡터에 금칙어 거부 1건을 넣는다. 구현 완료 후 security가 재확인.
- 앞으로 사용자가 쓰는 글이 새로 생기면(예: 낚싯대·자동차 이름 D-120) 같은 함수 호출을 설계 완료 조건에 넣는다. 팀장이 위임문에 "D-122: 글 입력은 gn_text_check 서버 호출"을 고정 문장으로 붙이길 권한다.

## 4. 팀장 확인·사용자 판단

팀장 확인 필요
1. 웹 확인 요청 [미확인]: Open-Meteo 이용 약관의 표기 문구·위치 요구, 기상청(KMA) 모델 자료의 출처 표기 요구, 무료 호출 한도 수치.
2. 정보·도움말 자리가 현재 있는지(2장 자리 ① 결정). 없으면 개인정보 팝업 줄 + 하단 링크로 간다.
3. 개인정보 안내에 "날씨 캐시(localStorage, 30분)" 한 줄 추가 여부(W13).
4. T5 닉네임 필터는 M2 SQL 보완 작업으로 등록 필요(로그인 재개 전 필수 선행, P 후보).

사용자 판단 필요: **없음** (모두 코드·문안 조치이며 계정 설정 변경 없음). 단 T5 실행 시점이 로그인 재개와 연동되므로 팀장이 일정에만 반영.
